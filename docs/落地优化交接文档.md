- 落地收敛：`recover_duration` 0.8 s → 0.004 s，消除了锁髋漂移和交还髋时的二次瞬态（#34）。着地 → 收敛从 1.81 s 缩短到 **0.50 s**（零速度），1.5 m/s 时为 **0.46 s**；不停机。
- 离地检测没有问题：着地后 12 ms 进入 RECOVER，监督层 0.1 s 内回到 ground。

## 2. 剩余问题：着地俯仰误差

| 指标 | 零速度 | 1.5 m/s |
|---|---|---|
| 着地瞬间 θ | −12.6° | −12.6° |
| 落地后 \|θ\|max | 12.8° | 12.8° |
| 速度偏差峰 | 0.12 m/s | 0.11 m/s |

剩下的 0.5 s 基本都在把这 12.6° 的后仰纠回来。要继续缩短，只能让机身在着地时更接近 θ = 0。

原因分析（已核实部分）：
- viewer 记录（`artifacts/viewer-default2/stand.json.gz`，t = 4.10～4.26）显示，飞行后段轮子力矩一直卡在 **±5 N·m 限幅**。也就是说，靠轮子反作用力矩做空中姿态控制，**控制能力已经饱和**。
- 所以单纯调大 `flight_pitch_kp/kd`（20/6）预计**没有效果**。这一点是推断，没有专门扫参验证。

## 3. 可选方向与工作量评估

| 编号 | 方向 | 内容 | 工作量 | 风险 |
|---|---|---|---|---|
| D1 | 飞行 PD 扫参 | 扫 `flight_pitch_kp/kd`，先确认是否饱和 | 小（约半天） | 很可能无效，只用来排除这个方向 |
| D2 | 推力段出口姿态 | 调 `preload_pitch`、推力幅度 / 截止条件 `q≥2.0`，让离地时的 θ̇ 在飞行中正好把 θ 带到 0 | 中（1～2 天，MuJoCo 网格搜索） | 会影响跳跃高度（当前 385 mm，要求 ≥ 200 mm）；零速度 / 有速度两种情况要分别验证 |
| D3 | 髋参与空中姿态（L-P） | 飞行段用髋摆动改变转动惯量分布或反作用，与轮子一起组成空中俯仰控制器 | 大（3～5 天）：要改结构，需要角动量模型，并重新设计着地姿态 `land_hip` | 着地时 q ≠ 0 会破坏 C25 结论（q ≈ π/2 时无法着地平衡），需要重新评估 |
| D4 | 着地缓冲 | LANDING 阶段让髋变柔（阻抗），吸收冲击，平滑地交给 WBC | 中到大（2～3 天） | 与 WBC 接管逻辑（C18-A）耦合 |
| D5 | 着地前 MPC 预锚定 | 着地前把 MPC 参考切换到"带初始俯仰误差的恢复轨迹"，避免 RECOVERY 从零开始 | 中（1～2 天） | 需要改监督层的 RECOVERY → GROUND 接管 |

建议顺序：先做 D1（半天，排除方向），再做 D2（性价比最高），D3 / D4 视 D2 的结果决定。

## 4. 同一模块的其他未完成项（第 14 次排查 L0～L3）

- **被推离地**：离地检测只在主动跳跃时接管。非跳跃状态下被推离地时，WBC 仍然输出零力矩，没有飞行 / 着地控制律。需要：
  1. 修复 #30：`run()` 的停机判据改为 `limits.contains(torque, tolerance=1e-6)`，目前仍是 `_ZERO_TOLERANCE = 1e-9`；
  2. 非跳跃状态也接入 `GroundContactEstimator`，AIRBORNE / SINGLE_SUPPORT 时复用跳跃的 FLIGHT / LANDING 控制律；
  3. 落地缓冲（与 D4 可以合并）。

  工作量：中到大（2～4 天）。
- **跳跃中俯仰峰值 36～39°**，距离 45° 保护线余量小。做 D2 时应一起观察。
- **跳跃期间不响应速度指令**；PREPARE 的进入条件是速度 < 0.3 m/s、俯仰 < 5°，所以 viewer 里高速行驶时按空格不会起跳。行驶中起跳只在脚本中验证过（`jump_times`）。

## 7. 追加：D1 / D2 测试结果与更正（第 21 次排查）

- **更正第 2 节**：剩下的 0.5 s 主要花在髋角恢复（0.50 s）和速度恢复（0.34 s）上，俯仰只需 0.21 s。所以第 3 节以"着地俯仰误差"为目标的 D3 / D5 方向优先级应该下调。
- D1（飞行 PD）：饱和属实。加大增益能降低着地俯仰，但总收敛变慢（0.50 → 0.64 s），不采用。
- D2（预倾角）：−30° 最优；−20 / −25° 收敛更慢，−35° 停机。
- 新方向 D6：调地面平衡控制的髋 / 速度恢复带宽，与推扰恢复共用同一套机制。它影响所有工况，需要重新跑零输入、推扰、加减速和跳跃的全套回归。工作量中等（1～2 天，可以复用 `tests/tuning/grid_sweep.py`）。**是否要做，由用户决定。**
