十四、代码修改测试判定原则

1. 代码能运行不等于算法任务生效。
2. WBC返回feasible不等于跳跃力学可行。
3. data.ctrl写入成功不等于质心按目标运动。
4. WBC预测接触力存在不等于轮子真实接地。
5. 几何轮隙为正不等于已经完成有效蹬伸。
6. 状态机没有崩溃不等于状态流正确。
7. 只有接口、任务、动力学、输出、接触和状态机证据完整后，才能判断跳跃功能是否成功。

# 问题排查agent复查：WP3异常根因（2026-10-09）

一、关于“机体被固定”的结论

该猜想被源码和数据否定。`robot.xml` 的base包含 `base_free`；`output.py`通过 `mujoco.mj_step`推进物理，控制循环没有持续写入根部位置。WP3结果中根部z从 `0.220239 m`降到 `0.164718 m`，质心z从 `0.263881 m`降到 `0.243734 m`，根部竖直速度达到 `-2.139 m/s`。机体确实下降，只是腿长从 `0.2800 m`塌到 `0.13245 m`，所以视觉上相对腿部像机体不动。

二、已确认根因

COMPRESS目标为 `-config.com_acceleration() = -11.8004 m/s²`，小于 `-g`。按 `F_normal_total=m(g+a_com_z)`，该目标要求负法向力；轮地接触无法提供拉力，实际法向力因此归零，轮毂在仍处于COMPRESS时先离地。WBC随后继续输出腿部力矩，腿长继续下降并越过压缩终点。

证据：t=1.225 s仍为COMPRESS时gap为 `1.485/1.478 mm`；最大gap `0.06909 m`；实际法向力从约 `71 N`降为 `0`；最小腿长 `0.13245 m`。因此首先是压缩参考物理不可行，不是MuJoCo根部固定或API把力传错。

三、下一步安排

WP3阶段目标判定为失败，暂停进入释放优化。下一阶段只修复COMPRESS参考和压缩制动：使用满足 `-g < a_com_z < 0` 的已批准profile，增加COMPRESS_BRAKE，确保压缩终点前下降速度被制动；然后验证“压缩双轮接触 -> 释放 -> 离地即停”。飞行和落地暂不测试。
