## 最新状态：2026-09-22 WBC 力矩问题定位与 QP 重写待启动

**用户要求（当前目标）**：受扰动后姿态峰值不超过 5 deg，位移立刻收敛（“踹不动”）。
用户明确表示：基于 LQR 建模控制的五连杆轮腿能做到；若本构型做不到就直说。

### 已定位：WBC 确实没发挥力矩（有实测证据）

- 零空间法下 `max |torque| = 0.380 N*m`，轮限值 5.0，**仅 7.6%**。
- `forward_velocity` 的 `scaling` 全程为 0（零空间耗尽）；`roll` / `height` 也恒为 0。
- 力矩不是决策变量，而是从零空间法反解出来的副产品，链条里没有任何一项在“要求出力矩”。

### 已建立的 QP 雏形（`Algorithm/wbc/task_qp.py`）

- 决策变量 `[qacc, f, tau]`，任务全为软目标，硬约束为动力学等式 / 力矩限 / 法向非负 / 摩擦锥。
- **证明可行**：力矩升到 2.24~2.60 N*m（高约 6 倍），动力学残差 3.4e-07。
- **但姿态失控**：`maxpitch ≈ 0.78 rad` 撞 45° 保护线；位置也回不到原点。
- **权重无效**：`pitch` 权重 3→100（33 倍）对姿态综无影响，且力矩未打满，
  说明问题在“任务定义与决策变量的对映”，不在权重。

### 用户决定（2026-09-22）

1. 不再与零空间法做对比（不做单步对拍）。
2. **直接重写 QP 求解**——该重写尚未开始。
3. 期望状态作为“尽量达到的目标”，而不是硬约束去干扰其他状态。

### 当前不要动的东西

- MPC 侧已部署 `pitch=400, pitch_rate=60, velocity=4000`，不再调。
- `Algorithm/wbc/weighted.py`（WLS 对照）与 `forward_velocity` 目标源改动仍在工作区，未清理。

### 待办

- 重写 QP 求解（用户指定为下一步）。
- 重写后验证：力矩占用率、姿态峰值（目标 ≤ 5 deg）、收敛时间、是否回原点。
- 未跑全量测试（298 项）；改了 MPC 默认权重后可能有期望值需同步。

## 历史状态：2026-09-22 MPC 参数迭代与键盘实测反馈

零速度抗扰与速度跟踪均有一组经过验证的参数；键盘控制已接入。以下问题为实测反馈与尚未修复项。

用户实测反馈（viewer + 键盘，55 s，位移 4.285 m、偏航 -2.70 rad）：

- 位移收敛偏慢（零速度抗扰回归约 4.4 s）。定位：MPC 实际只输出 0.05 N 量级的力，属权重/预测行为，与 MuJoCo 补偿开关无关。
- 有速度指令时加减速太慢：直接由 `MotionLimits.commanded_acceleration = 0.80` 决定（用户指定值，原为 2.00）。
- 速度上限偏慢：由 `MotionLimits.max_speed = 1.20` 限幅（项目默认值，无实测依据）；键盘步长 2.5 被限到 1.2。
- 带指令运行时的姿态峰值 `0.2938 rad`，已用掉 `pitch_limit = 0.30` 的 98% 裕度，再激进一点就会触发 `attitude_guard`。

未修复缺陷（本阶段未动）：

- viewer 自带的重置会把 `data.time` 清零，而 `run()` 假设时钟不退，会抛 `ValueError: Supervisor clock must be finite and strictly increasing`。旧 LQR 路径有 `reset_runtime_state()`，MPC/WBC 路径没有对应处理。
- 带速度/偏航指令时的姿态裕度偏小，尚未定位到具体通道。
- `max_speed`、`commanded_acceleration`、`max_acceleration` 三个限值均无实测标定依据。
- WBC 的 PD 反馈仍偏弱（`preview_lead = 0.02` 下误差只有 1e-4~1e-3 量级），系统实际以 MPC 前馈为主。

WBC 层对照结论（已实测，见修改日志）：

- 零空间法与加权最小二乘（WLS）、以及“直接跟踪指令速度”三种组合，实际减速度、姿态、回归时间**完全相同**。WBC 的任务分配、目标来源、优先级都不是减速慢的原因。
- 真正原因是 `pitch` 与 `forward_velocity` 争同一自由度：减速必须靠俯仰，而 `pitch` 任务要求保持竖直；只要 MPC 不规划“为减速而俯仰”，下层就不会减速。
- 因此唯一被数据支持的旋钮仍是 MPC 的 `pitch` / `pitch_rate` 权重。
- 未决：`Algorithm/wbc/weighted.py` 是否保留；`forward_velocity` 目标源改动是否保留。

下一步优先级（分析结论，尚无实测）：

- 继续迭代 MPC 参数收益接近上限：`velocity` 4000 → 8000 仅 6.5% 改善且姿态变差；加大 `pitch` 反而让位置收敛变差。再要收益需放宽约束或改 MPC 结构。
- WBC 只调增益收益同样很小（kp 40 → 320 实测变化 < 5%），因为 PD 误差只有 1e-4~1e-3 量级。
- WBC 的 `preview_lead` 是唯一有实质空间的一维：加大前瞻才能让 PD 反馈真正生效，但有过冲/振荡风险。
- 建议顺序：先动 `preview_lead` 激活反馈层，再回头重调 MPC 参数。

### 历史设计结论的必要修订

1. “接触行乘连续权重就连续释放”：非零行缩放不改变硬等式的零空间；到零仍有秩跳变。
   接触释放需要明确的模式/松弛/接触力策略，不能直接采用历史 A1 选项一的数学理由。
2. “固定材料点向心项等于滚动约束偏置”：沿移动几何切点重算雅可比的导数与固定材料点不同。
   本地核验平地 1 m/s 匀速纯滚动，移动切点约束偏置为零，固定材料点竖向项为 6.25 m/s²。
3. “MuJoCo 无 mj_jacDot、mj_fullM 返回 CSR”：本地 MuJoCo 3.13.0 提供 mj_jacDot；mj_fullM 填充稠密矩阵。
   仍需区分固定材料点雅可比导数与移动接触几何，并兼容版本签名。
4. “P Jc.T=0 意味着零空间法不能控制接触力”：只能证明当前将 Jc.T f 塞进被消去偏置的通路无效；
   不能推出所有零空间力控制都不可能。力跟踪需独立映射与可行性设计。
5. “单轮离地必然立刻侧翻”“接触力断言证明 MuJoCo 必然发散”：这些是过强结论。
   短时恢复能力须根据接触几何、状态和动力学测试；不能把解析双边模型的断言当作真实仿真证据。
6. 真实 XML 髋轴分别为 -y/+y，直接将两个原始 ctrl 相加当成机身俯仰力矩需要重新核验符号；
   fullinertia 的 Iyy=0.053191，不能混同 MuJoCo 主惯量排序与机身坐标轴分量。
7. 历史 `|tau_wheel| <= mu*fz*R` 只能作为近似限值，完整关系还涉及轮转动惯量和侧向摩擦共享。
   真实摩擦可行性需在接触坐标系校验，不能宣称一个箱约束已精确等价于摩擦锥。

详见 [修改日志.md](修改日志.md) 的 2026-09-20 阶段记录。

## 结论先行

算法层面没有"未知的坑"了——MPC 的约束/QP/兜底、WBC 的消力/零空间/SNS 都有实测数字
兜着。真正挡住上仿真的是三件事：

1. **接触模型不一致**（A1）：WBC 用的是双边等式接触，MuJoCo 是单边 + 摩擦锥。这不是
   参数差异，是**建模范式差异**，不改就会在最常见的"轮子轻微腾空"工况下直接发散。
2. **适配层不存在**（A2）：`M / h / S / Jc / J̇c q̇` 目前只有测试里的解析模型提供。
3. **实时性不达标**（B1）：WBC 在只有 7 自由度的玩具模型上已经 2.64 ms/拍（≈370 Hz），
   真机是 10 自由度、还要从 MuJoCo 取矩阵，只会更慢。方案 §2.2 预测的"纯 Python 跑不到
   1 kHz"**【实测】**成立。

## A 类：会直接导致仿真失败（上仿真前必须解决）

### A1 接触模型不一致：双边等式约束 vs MuJoCo 单边 + 摩擦锥

**现象**：WBC 核心把接触写成**硬等式** `Jc q̈ + J̇c q̇ = 0`（`projection.py`），也就是
"接触点既不能分离、切向也不能滑"。而 MuJoCo 里轮地是 `condim="3"` 的**点接触 + 摩擦锥**
（`URDF_Model_plane.xml:41`）——法向只能推不能拉、切向可以滑。

**证据**：
- 【实测】联调时必须在每一拍断言"两个轮子的法向力为正"，否则仿真会在几拍内失效
  （`tests/test_joint.py::test_torques_and_contact_forces_stay_physical`）。这个断言
  本身就说明双边模型在 MuJoCo 上会被违反。
- 【文档】§8 陷阱 8："圆柱-平面单点接触……接触点沿轮缘移动，`Jc` 必须每拍重算"；
  §4.4 要求"接触集变化时对 `Jc` 的行做**连续加权**（权重 = 归一化法向力），而不是硬增删行"。

**影响**：真机上只要出现轻微的轮子卸载（横滚、升降腿、粗糙地形），WBC 仍然认为接触存在
并继续求解约束力，而 MuJoCo 那边轮子已经离地 → 力矩与实际接触力脱节 → 发散。方案 §1.6
说得很重："单支撑 = 横滚完全不可控 = 必然侧翻"，所以这个问题一定会遇到。

**建议动作**（三选一，需要决策，见 C3）：
1. 保留双边（当前实现），但补上**接触状态机 + 连续加权**：`Jc` 的行按归一化法向力加权，
   法向力趋零时该行权重趋零。这是方案 §4.4 的原意，改动最小。
2. 改成"法向单边 + 切向滚动约束"的混合形式：法向只做单边检查（不施加等式），切向保留
   滚动约束。
3. 换 QP-WBC（把 `f` 留在决策变量里），代价是方案明确要避免的。

### A2 MuJoCo 适配器不存在

**现象**：WBC 核心的输入是 `M, h, S, Jc, J̇c q̇`，目前全部由 `tests/planar_robot.py`
解析给出。真机侧一个都还没有。

**证据**：【分析】`Algorithm/mpc/model.py:from_mujoco` 只取了 `A/B`（给 MPC 用），
没有任何地方提供 WBC 需要的矩阵。

**需要落的五件事**：

| 量 | MuJoCo 来源 | 注意点 |
|---|---|---|
| `M` | `mj_fullM` | 返回稀疏 CSR，需转稠密；每拍重建的开销要实测 |
| `h` | `qfrc_bias` | 含科氏 + 重力，不含约束力，正合 `M q̈ + h = Sᵀτ + Jcᵀf` |
| `S` | 执行器 → 关节映射 | 4 个 `<motor gear="1">`，即单位选择矩阵 |
| `Jc` | `mj_jac` ×2 接触点 | 只给点雅可比；**滚动约束那一项要自己补**（见 A1/C3）。接触点沿轮缘移动，每拍重算 |
| `J̇c q̇` | `mj_objectAcceleration`（`qacc=0`） | 方案 §4.2 推荐；1 m/s 时向心项相当于 0.64 g，绝不能省 |

**影响**：没这个，WBC 一行都跑不起来。这也是"上仿真"最短路径上的第一块砖。

### A3 摩擦锥没有接进 SNS

**现象**：`ActuatorLimits` 只有固定的硬件上下限（`j1/j3` ±10、`j2/j4` ±5）。
方案 §5.2 要求把摩擦锥**解析化**成实时变化的力矩上界：

```
|τ_wheel,i| ≤ min( 5.0 ,  μ · f̂_z,i · 0.16 )
```

**证据**：【分析】`grep friction|mu|normal_force Algorithm/wbc/*.py` 无任何命中。

**影响**：
- 打滑时 WBC 不知道自己已经在锥边界上，会继续加大切向力。
- 方案 §3.2 的结论是"平地上绑住性能的是电机力矩，不是摩擦锥"，所以平地问题不大；但
  **抬腿 / 剧烈横滚 / 粗糙地形**时单轮法向力会掉到标称的 67% 以下，锥先触发。

**依赖**：需要 `f̂_z` 估计（见 B2）。方案 §5.2 建议留 20% 保守余量（`μ_eff = 0.8`）。

### A4 接触集切换 / 单轮离地没有实现

**现象**：没有接触状态判定、没有 `RECOVER` 行为、没有接触行的连续加权。
`contact` 字段在 `ChassisState` 里存在，但 MPC 侧只是把腾空轮的力上限置零，
WBC 侧完全没有接触集的概念。

**证据**：【文档】§4.4 与 §2.4 的 `RECOVER` 状态；【分析】`projection.py` 没有任何
按权重组装 `Jc` 的入口。

**影响**：粗糙地形（`main.py --terrain rough`）上必然遇到，而且方案 §1.6 说这是**失效**
而不是"性能下降"。

### A5 MPC 的降阶模型与 WBC 的实际工作条件不一致

**现象**：`ReducedModel.from_mujoco` 的线性化是在**髋关节自由**（`j1/j3` 力矩为 0）的
条件下测的（`model.py` 自己记了这条：`measure_contact_linearization` 的 caveat）。
而 WBC 会把髋握住并主动控制它——等效质量、不稳定极点、`B` 的俯仰行都会变。

**证据**：
- 【实测】**联调时位置指令的刹车段把闭环打散，试了 5 档增益全部发散**；速度指令则很干净
  （稳态误差 < 0.002 m/s）。位置指令的差别在于规划器要求俯仰在 0.25 s 内摆 ±0.2 rad，
  而降阶模型里根本没有腿的动态。
- 【文档】`model.py` 的 docstring 与 §2 的 M0/M2 阶段都写了要"带髋约束重新实测一次"。

**影响**：这是**已经实测出来的**问题，不是推测。上仿真后速度环大概能用，但任何激进的
加速/制动动作都会暴露。

**建议动作**：M2 阶段前用"髋被 PD 握住"的条件下重测一次线性化（改 `Algorithm/lqr.py`
的 `derivative()`，给 `j1/j3` 加保持力矩），然后重跑 MPC 的单元测试（夹具里记录了旧值）。
注意这会改变所有增益的标称值。

## B 类：能跑但会不稳定或性能不达标

### B1 实时性不达标（WBC）

**现象与实测**（平面双腿玩具模型，`nv=7, na=4, nc=4`，CPython 3.13 + numpy 2.5）：

| 环节 | 单拍耗时 |
|---|---|
| `M` + `Jc` 组装 | 0.126 ms |
| `ContactElimination`（QR + 伪逆） | 0.310 ms |
| 层级求解一次 | 0.430 ms |
| **SNS 一次 `resolve`** | **2.113 ms** |
| **整拍 `wbc.solve`** | **2.640 ms ≈ 370 Hz** |

**根因**：SNS 每拍要把层级**重复解 5~8 次**（全局缩放要 2 次、每级预算 2 次、钳位回路
每轮 1 次），占了整拍的 80%。

**影响**：
- 方案 §2.2 要求慢环 250 Hz、快环 1 kHz。当前连 250 Hz 都够呛，而且真机 `nv=10`、
  还要每拍从 MuJoCo 取矩阵，只会更慢。
- 方案的应对是"快慢双环"（快环 1 kHz 只做俯仰阻尼 + 饱和，纯标量运算）。**快慢环没有实现**。

**建议动作**（按性价比）：
1. 先降 SNS 的重复求解次数：全局缩放的两次求解可以复用（`τ(s)` 对 `s` 是精确仿射的，
   系数可以跨拍缓存）；每级预算的两点测量也可以只在预算真的可能绑定的时候做。
2. 再实测 MuJoCo 侧取矩阵的开销，确认是否要缓存 `M/Jc` 的结构。
3. 必要时把热点 numba/Cython 化（方案 §2.2 说"不要在 M2 之前做"）。

### B2 状态估计器缺一半

**现象**：现有 `Algorithm/estimator.py` 的 `BodyStateKalman` 只给 `pitch` /
`pitch_rate` / `forward_velocity`。

**证据**：【分析】`grep "^class |def " Algorithm/estimator.py` 只有这三个出口。

**MPC 与 WBC 需要但当前没有的量**（方案 §2.3 的表）：

| 量 | 现状 |
|---|---|
| 姿态 φ θ ψ | 只有 pitch；无四元数 EKF、无横滚/偏航 |
| 机身速度 | 纯轮速里程计，**漏了轮心相对机身的运动项 `∓0.06·cos q·q̇`** ——方案点名这条会被 MPC 当成真实速度误差去追 |
| 机身高度 z | 无 |
| 接触状态 | 无 |
| 法向力 `f̂_z` | 无（摩擦锥 A3 依赖它） |

### B3 §2.4 的启动/失效状态机没有

【文档】`INIT / PARK / RAISE / BALANCE / RECOVER / FAULT` 六个状态一个都没有。方案明确
说"MPC 需要有效的接触状态才能工作，不能冷启动"，并且 `RAISE` 阶段必须在俯仰任务闭环
之后才动髋（否则 §1.5 的 20 N·m 俯仰扰动会直接推倒机器人）。

### B4 `s` 回馈通道没有

【文档】§5.4 要求把 WBC 每级的任务缩放因子回馈给 MPC（收紧对应方向的约束上界、在代价里
加正则）。现在缩放因子只躺在 `SNSResult.scaling` 里，没人读。不接会出现文档点名的正反馈：
"MPC 规划 → WBC 做不到 → MPC 看到误差加大要求更狠 → 更做不到"。

### B5 MPC 的求解时间在饱和工况会顶到周期

**证据**：【实测】H=25 时 `cond(P) ≈ 9.3e4`；解落在箱型边界上（轮力饱和）时 OSQP 需要
约 1120 次迭代、单拍约 12 ms；`max_iter` 已从 400 提到 2000。名义工况只要 30~40 次迭代、
0.4 ms，所以**这是饱和工况才暴露的问题**，但饱和恰恰是升降腿/急加速时的常态。

## C 类：需要拍板的设计决策

### C1 §4.3 的 L0 在零空间框架里恒等于零

**实测结论**：`P·Jcᵀ = 1.3e-17`，其中 `P = (Q_uᵀSᵀ)⁺Q_uᵀ` 是执行器解的投影算子。
因为 QR 消力构造保证 `Q_uᵀJcᵀ ≡ 0`，而执行器解正是经过 `P` 投影出来的——**接触力的广义力
落在约束子空间里，数学上不可能影响执行器**。所以方案 §4.3 写的 L0
（`τ_ff = −Jcᵀf*` 的驱动空间投影）取值恒为零。

**佐证**：【实测】把 `f*` 前馈到俯仰任务上，L1 的 −11.0 rad/s² 纠正被 L0 的 +11.1 抹平，
俯仰卡在 0.135 rad 稳态误差上不动。

**含义**：这套框架下 **MPC 的参考轨迹才是可执行的接口**——正好印证方案 §0 自己的结论
（`θ*(t)` 是全系统最重要的信号）。力只能以"它意味着多大加速度"的形式间接使用。

**要定的事**：
- (a) 接受这个结论：L0 从方案里删掉，MPC 只输出参考轨迹（改动最小，与 §0 一致）；
- (b) 保留命令接触力的能力 → 必须换成为把 `f` 留在决策变量里的结构（QP-WBC），也就是
  方案特意避开的那个，需要重新权衡"闭式/定长/可硬实时"这个卖点。

### C2 标称工作点是否迁到 `q₀ ≈ 25°`

【文档】§1.4 论证 `LegConfig.angle_zero = 0.0`（死点）是横滚控制最差的工作点，建议迁到
25°，代价是每髋持续 1.0 N·m、机身低 5.6 mm，收益是法向力增益从 ∞ 降到 39.4、高度权限
从 0 升到 0.025 m/rad。**这个改动会改变所有增益的标称值**，所以方案说要在动架构之前做完。

### C3 接触约束用哪种建模

见 A1 的三个选项。这个决定会影响 `Jc` 怎么构造（要不要补 `−r·ω` 的滚动项）、
`J̇c q̇` 怎么取、以及 SNS 的限值从哪来。

## 建议的上仿真路径

按依赖关系排，每一步都能独立验证：

1. **A2 适配器** + **A1 的第一步（接触行连续加权）** → 用固定的平衡位形跑通"WBC 单拍算出力矩"
   ，断言 `Jc q̈ + J̇c q̇ ≈ 0` 与法向力为正。
2. **方案 §7.4 的 `xfrc_applied` 脚手架**：关掉 WBC，把 MPC 的 `f*` 直接施加到 MuJoCo 上。
   这一步能彻底解耦两层的正确性，且**不需要 WBC**。
3. **B2 状态估计**（至少 pitch/pitch_rate/v_x + 接触状态）→ 让 MPC 用估计值而不是真值。
4. **B1 快慢双环 + SNS 减负** → 实测慢环能不能到 250 Hz。
5. **B3 状态机** → `INIT → PARK → RAISE → BALANCE` 跑通，再谈速度与转向。
6. 最后才是 A3 摩擦锥、A4 接触集切换、粗糙地形。
