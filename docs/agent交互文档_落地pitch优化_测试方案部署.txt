1. 目标与已核实机制
================================================================

1.1 目标

  - 降低**触地瞬间**与**冲击峰**的 |pitch|。
  - 判据基线（不得因本轮改动变差）：gap >= 0.22180 m（硬下限 200 mm）、
    ABORT 0 次、腿长越界 0 次、单支撑 0 次、airborne_zero 0 次。
  - 落地后的位置收敛行为（后向回退 <= 0.03 m、前向位移 0.15~0.40 m，
    见落地姿态文档第 32/33 节）不得回退。

1.2 已核实的机制（代码证据）

  (a) 飞行段 WBC 不参与。`loop.py:419-436`：

        elif flight_profile:
            torque, flight_leg_ref = flight_leg_profile_torque(...)
        ...
        write_actuator_output(d, torque)
        output_source = "flight_leg_profile"

      `write_actuator_output` 覆盖**全部 6 维**力矩（含轮），因此飞行段
      pitch 的唯一驱动是跳跃剖面的腿部力矩。

  (b) 剖面内的摆角 PD 是世界系锚定（`control.py:106-116`）：

        phi_body_ref = phi_body_reference(world_ref, pitch)   # = world_ref + pitch
        F_phi = KP_PHI * (phi_body_ref - phi) - KD_PHI * phi_dot

      世界参考本身随腿长变化（`leg_angle_anchor.py:24-31`）：

        phi_eq(L) = WORLD_TARGET_DEFAULT + PHI_EQ_SLOPE * (L - 0.28)
        phi_body_reference(world_target, pitch) = world_target + pitch

  (c) `+ pitch` 构成正反馈环：

        机体倾角增大 -> 机体系腿角参考同步增大 -> 腿去跟 -> 髋反作用力矩推机体继续倾

      这与用户描述的"控制 phi 反作用到机体导致 pitch 变大"一致，
      且比"次要耦合"更强：它是**唯一的驱动项**。

1.3 量级（用实测常数估算，不作为判据）

  - `KP_PHI = 20.9 N*m/rad`、`KD_PHI = 1.67 N*m*s/rad`（`control.py:53-54`）
  - `FLIGHT_RETRACT_FLOOR = 0.16 m`、`FLIGHT_RETRACT_KP = 3000 N/m`
  - 机体俯仰等效惯量 `I_eff = 0.1142 kg*m^2`（历史实测）
  - 世界系偏差 0.2 rad -> 反作用 4.18 N*m -> 36.6 rad/s^2 -> 0.3 s 内 O(1) rad
  - 由 gap 0.22180 m 反推：起飞竖直速度 ~2.08 m/s、滞空 ~0.42 s
    （仅用于估算预倾的副作用，不是测量值）

1.4 两个候选方向（用户 2026-10-18 提出）

  方向一 启动预倾：地面阶段主动把机体 pitch 偏置一个角度 delta，
    用来抵消空中产生的大 pitch。改的是**初始条件**。

  方向二 不控 phi：不去把 phi 拉到世界系垂直，让它带着倾角落地，
    落地后靠轮驱动让机体整体前向顺时针，用位移换回水平。
    改的是**驱动项本身**。

1.5 两方向的量级上限（分析结论，待实测确认）

  方向一只作用于"释放时刻已有的 pitch"，对收腿/伸腿段由 PD 反作用驱动的漂移无效。
  下表是它的副作用（v_takeoff 取 1.4 节的估算值）：

    | delta (rad) | 抵消角度 | CoM 前移 com_z*delta | 起飞横向 v*sin(delta) | 落地前移 |
    |---|---|---|---|---|
    | 0.05 | 2.9 度 | 1.3 cm | 0.10 m/s | 4 cm |
    | 0.10 | 5.7 度 | 2.6 cm | 0.21 m/s | 9 cm |
    | 0.15 | 8.6 度 | 4.0 cm | 0.31 m/s | 13 cm |

  实现前提：WBC 的 pitch 参考偏移与 MPC 的位置参考偏移必须**同步**，
  否则两个环对打，实际 delta 远小于指令值。

  未验证的前提：漂移与 delta 是否可加（即 d(theta_land)/d(delta) 是否约等于 1）。
  若正反馈使斜率显著大于 1，预倾无法线性标定。

  方向二直接掐掉正反馈，但代价在落地几何：触地时机体已倾斜，
  若腿角锁在机体系，世界系腿角就偏同样的角度，轮子落点远离 CoM 投影，
  冲击峰可能变大。折中版本：只在**收腿段**去掉 `+pitch`，伸腿段恢复世界系目标。

2. 第 0 步：pitch 预算分解（只加日志，零风险）
================================================================

2.1 目的

  把触地 pitch 拆成三段贡献，判断预倾能吃掉多少、根因在哪一段。
  这一步不做，选方向只能靠猜。

    T0 释放时刻（COMPRESS/BRAKE 结束、进入离地）
    T1 收腿段（腿长参考向 FLIGHT_RETRACT_FLOOR 收缩）
    T2 伸腿段（落地前伸腿 + 落地缓冲）

  三个量：theta(T0)、theta(T1)-theta(T0)、theta(T2)-theta(T1)，以及占比。

2.2 记录字段（飞行段每 4 ms 一行，沿用 jump_diagnostic 的采样口径）

    - t、phase、output_source（应为 flight_leg_profile）
    - pitch、pitch_rate
    - phi（t=0 侧腿角，机体系）、phi_dot
    - phi_world = phi - pitch（世界系摆角，符号按现有约定记录并在报告里写明）
    - phi_body_ref（= world_ref + pitch）、world_ref（= phi_eq(l_ref)）
    - 髋力矩 R/L、轮力矩 R/L
    - l_ref、l（R/L 腿长）、l_dot
    - v_z（d.qvel[2]）、gap

2.3 分段判据（在报告里明确写出来）

    - T0：`phase` 首次为 FLIGHT 的那一帧（若相位机定义不同，按实际相位名注明）
    - T1 结束：腿长导数为零且 l 到达剖面最小值（或剖面状态 `flight_leg_ref`
      进入伸腿分支的帧），两者取先到者，并在报告中写出实际帧号
    - T2：T1 结束 -> `output_source` 首次离开 flight_leg_profile

2.4 自检（必须写进报告，与落地姿态文档 4 节同口径）

    - 脚本语法与导入通过
    - 字段名、下标、单位与记录实际一致（pitch 单位 rad、力矩单位 N*m）
    - 单工况冒烟能跑通，三段角度之和等于触地 pitch（误差 <= 1e-9）
    - 同一组输入重复取数两次结果一致
    - 若异常，先说明是工具问题还是数据问题，修好再重跑，修复前结果作废

3. 第 1 步：两个对照工况（不改任何增益/阈值）
================================================================

  两个工况都只"偏置一个量"或"关掉一个耦合项"，不改 KP/KD/限幅/频率。

  3.1 工况 (i) 预倾

    - 输入：`pretilt_pitch = -0.10 rad`，在起跳前 `PRETILT_WINDOW` 内生效

    - 同步要求：WBC 的 pitch 参考偏移 pretilt_pitch、MPC 的位置参考偏移

    - 测量：theta(T0)、theta_land、max|pitch|、gap、起飞水平速度、落地位移、
      是否仍满足 1.1 的判据基线。

  3.2 工况 (ii) 收腿段冻结

    - 改动：收腿段内 `phi_body_ref = world_ref`（去掉 `+ pitch`），
      伸腿段恢复 `world_ref + pitch`。
    - 不改 `KP_PHI`/`KD_PHI`，不改世界参考 `phi_eq(l_ref)`。
    - 测量：pitch 三段贡献（同第 0 步口径）、触地世界系腿角偏移量、
      冲击峰、gap、落地后收敛行为。

  3.3 对照要求

    两个工况各跑 1 次之外，必须保留同一配置下的 baseline（无预倾、无冻结）1 次，

5. 决策树
================================================================

  (i) d(theta_land)/d(delta) 约等于 1 且起飞水平速度增量 <= 0.2 m/s
      -> 预倾可作为微调，叠加在第 6 步的主修法上，delta 取值按第 0 步预算的
         "T0 贡献"决定，不自行加码。

  (ii) 冻结后 pitch 显著下降（>= 30%）且触地世界系腿角偏移在可落范围内
      -> 走分段解耦（收腿锁机体系 + 伸腿恢复世界系），这是主修法。

  两者都不成立
      -> 回到第 0 步数据，重新定位主项，不换方向硬试。

8.2 新增工具：`wheel_leg_mujoco/tools/pitch_budget.py`（只读）

8.3 分段定义（必须写进报告，不得自行调整）

  - 前置：只取“跳过一次”的那一段。起点 = `jump.phase` 首次变为 `COMPRESS` 的帧；
    终点 = `output_source` 首次离开 `flight_leg_profile` 的帧（记作 k2）。
  - T0 末（k0） = `jump.phase` 首次为 `FLIGHT` 的帧。
    若该帧不存在（相位机未用 FLIGHT），改用 `output_source` 首次为 `flight_leg_profile` 的帧。
  - T1 末（k1） = 以下两者先到者：
      (i) `flight_leg_ref[0]` 由 `rising` 变为 `falling` 的帧；
      (ii) `leg_length_R` 首次达到段内最小值后再上升的帧。
    报告中必须写出实际采用哪一条、实际帧号与 t。
  - T2 = k1..k2。
  - 每段帧数必须 >= 50，否则报“段过短”，不强行给结论。

8.4 计算式

  逐帧派生量（侧别 s ∈ {R, L}，摆角下标 1 / 3）：

    phi_world_s = leg_state[idx] - pitch
    l_ref       = flight_leg_ref[1]（非剖面帧为 None）
    phi_ref_world = phi_eq(l_ref)                  （l_ref 为 None 时不给）
    phi_ref_body  = phi_ref_world + pitch
    tau_hip_s   = ctrl[idx]                        （idx = 1 / 3，与 leg_state 同序）
    tau_hip_net = ctrl[1] - ctrl[3]                （左右角度关节轴向镜像，净俯仰反作用取差）
    tau_wheel   = ctrl[4:6]

  每段输出：

    d_pitch      = pitch(t_end) - pitch(t_start)
    d_pitch_rate = pitch_rate(t_end) - pitch_rate(t_start)
    int_tau_hip  = ∫ tau_hip_net dt                      （梯形积分）
    int_tau_wheel= ∫ (tau_wheel_R + tau_wheel_L) dt
    d_phi_world_R/L = phi_world(t_end) - phi_world(t_start)
    max|tau_hip|、max|tau_wheel|、轮力矩恒零帧数

8.5 自检（必须逐条写进报告）

  1. 语法与导入通过；`--help` 可运行。
  2. 字段口径：从 json.gz 中打印实际键名并确认与 8.1 表一致（键缺失则报错退出，不得跳过）。
  3. 三段角度之和与总变化相等（误差 <= 1e-9）。
  4. 驱动源归属（本节最重要的自检）：**只统计飞行段 T1+T2**（T0 在地上，接触力才是主项，
     把 T0 算进去会让积分爆大且符号失真——实测 T0 髋力矩积分 +8.33 N*m*s，比飞行段还大）。
     判三件事：
       (a) 飞行段轮力矩是否恒为零（若是，则轮不是驱动器）；
       (b) 髋力矩积分 `int_tau_hip` 的符号是否与实测 `d_pitch_rate` 一致；
       (c) 解释比例 `(int_tau_hip / I_eff) / d_pitch_rate` 的量级。
     结论只写“哪一组执行器在驱动”，**不设百分比阈值**。
     解释比例远离 1 属正常：腿在摆动时基座俯仰与腿摆角存在动量交换，
     `I_eff = 0.1142` 是腿锁定条件辨识值，单独用它预测会系统性偏高（本工况实测约 10 倍）。
     报告中必须把解释比例与这条限制一并写清，不得当作“模型错误”或“其他驱动源”。
  5. 同一输入重复跑两次，输出逐位一致（浮点按 1e-12 比较）。
  6. 异常先归因于工具再归因于算法；工具修好前的输出作废并标注。

  这三条定下来之前，不得对“反作用方向”下任何结论。

  - -0.30：触地 -42.0 度 -> **-16.6 度**，gap 0.20734（相对基线 -6.5%，仍 > 0.200）；
  - -0.20：触地 -27.5 度，gap 0.21559（-2.8%）；
  - 上限由 gap 卡住，不是由机构卡住。

13.3 结论二：腿长越界不是预倾拉长腿，而是“起飞失败 + 伸腿剖面在地面上跑”

  证据（P12_010m，delta=-0.10）：

  | t | phase | leg_R | v_z | gap | flight_leg_ref.L_ref |
  |---|---|---|---|---|---|
  | 1.000 | COMPRESS | 0.2800 | +0.000 | -0.0005 | None |
  | 1.156 | COMPRESS_BRAKE | 0.2197 | -0.755 | -0.0003 | None |
  | 1.656 | ABORT | 0.4310 | +1.515 | **+0.0000** | **0.4225** |

  - 阶段在 COMPRESS_BRAKE 卡了 **0.5 s**（1.156 -> 1.656），始终未进入 THRUST/FLIGHT；
  - 期间 gap 恒为 0.0000（**从未离地**），而飞行伸腿剖面的 `L_ref` 已经跑到 0.4225；
  - 腿长从 0.2197 被伸到 0.4310（实测最大 0.4381）-> 撞 0.430 上限 -> ABORT。

  因此是两个独立缺陷叠加：

  A. **起飞失败**：v_z 已到 +1.5，gap 仍为 0，腿在伸但机体没被抬起来（预倾角影响推离效率）；
  B. **保护缺失**：未离地时伸腿剖面仍在跑，`L_ref` 未受 `leg_length_max` 约束，一路伸到 0.43+。

  这也是队列里“leg_length_max=0.430 余量仅 0.9~1.3 mm”的既有隐患被暴露，不是本轮新增。

16.1 机理更正（替换第 12.3 节“正反馈”的解释）

  三段预算随预倾的变化（问题排查agent 用 `pitch_budget.py` 离线取数）：

  | delta | T0 地面 | T1 收腿 | T2 伸腿 | 合计 |
  |---|---|---|---|---|
  | 0 | -0.0020 | -0.3060 | **-0.4247** | -0.7328 |
  | -0.20 | +0.0464 | -0.2536 | **-0.0726** | -0.2798 |

  | delta | T1 ∫τ | T2 ∫τ | T1 d_phiW | T2 d_phiW |

  结论（有数据支撑）：

  1. **执行器出力几乎不变**（T1 差 4%，T2 差 16%），所以“预倾让控制器多出力去抵消”不成立；

  3. 所以 **真正的因果变量是“腿摆路径”，不是“机体姿态”**。

21. 落地姿态方案（用户 2026-10-19）：机理、离线核演、可部署版本

21.1 用户给出的机理（本节以此为设计依据）

  地面给轮子的竖直反力，只有在**通过"轮—膝—髋"这条腿轴**时才不产生膝关节力矩。
  腿轴在世界系一旦倾斜，竖直反力对膝就有力臂 -> 小腿绕轮毂接地点转动 ->
  小腿与地面的间隙被主动吃掉 -> 下一步小腿碰地 -> φ 的收敛方向被地面顶死 ->
  控制器继续出力 -> 力矩全部灌进连杆 -> 蹬腿发散。

  推论：控制 φ 的那组测试落地干净，本质是**把腿轴摆到竖直、让力走轴**；
  不控 φ 时腿轴歪，膝力矩大，小腿被“压”进地面。

  小腿 33 mm -> 5 mm、底盘 126 mm -> 55 mm，同期腿长 0.305 -> 0.272（压缩 33 mm）。

21.3 离线核演二：轮力矩控 pitch 路线 —— **否决**

  想用“轮子反作用力矩控机体俯仰、腿不动”来同时满足“腿竖直 + 机体水平”，
  但动量账不成立：

    I_eff / I_wheel = 0.1142 / 0.000898 = **127 : 1**

  要给机体吸收 1.7 rad/s 俯仰角速度，轮子需自旋 216 rad/s，轮缘线速度 **16.6 m/s**；
  空中无外力矩可把动量还回去，触地带 16 m/s 表面速度 -> 必然打滑并再推机体。

  结论：轮力矩只能做 **0.1 rad 量级的小幅瞬时微调**，不能承担整段漂移。
  轮圈腿能用是因为其轮子惯量占比大（本机 127:1），不可照搬。

21.4 离线核演三：pitch 漂移的来源 = 腿长行程

  V17F（φ_body 保持，等价于“不控 φ_world”）的分段（`pitch_budget.py`）：

  | 段 | 腿长变化 | d_pitch |
  |---|---|---|
  | T1 收腿 | 0.28 -> 0.16（-0.12 m）| -0.287 |
  | T2 伸腿 | 0.16 -> 0.305（+0.145 m）| -0.166 |
  | 合计 | 行程 0.145 m | -0.455 |

  估算（数量级验证）：2 kg × 0.145 m × sin(0.13) ≈ 0.0375 kg*m
  -> Δθ ≈ 0.0375 / 0.1142 ≈ **0.33 rad**，与实测 -0.455 同量级。

  结论：**空中 pitch 漂移的主因是腿长行程**（腿的质心横向移动，机体反扭守恒角动量），
  不是执行器选择。想降落地 pitch，最直接的是**减小腿长行程**。

  | 步 | 改动 | 依据 | 风险 |
  |---|---|---|---|
  | 1 | 飞行段守 `φ_body`（去掉 `+pitch`），不守 `φ_world` | 腿相对机体不动 -> 不再按机体姿态注入角动量 | 无（V17F 已跑过等价物）|
  | 2 | **浅收腿**：`FLIGHT_RETRACT_FLOOR` 0.16 -> 0.22（0.22 为待测值）| 行程 0.145 -> 0.085 m，漂移按比例下降 | 收腿不足，需看小腿间隙 |

23. 两条可执行方案：离地角动量注入 + ZMP 预设目标点
================================================================

23.1 前置结论（第 21/22 节推导，不再重复验证）

  1. **飞行段降 pitch 不可实现**：髋是唯一空中力矩通道，`φ_world = φ_body - pitch`，
     换 1 的 pitch 要付 2 的 φ_world；轮子动量比 127:1 否决；腿长受 gap 约束。
  2. **小腿间隙是结构常数 20 mm**（FK 全网格实测），与 (L, φ, pitch) 无关；
     实测的 5 mm = 20 mm 结构余量 − 15 mm 轮子穿透。
  3. 因此剩下的可执行空间只有两处，且互不重叠：
     - **接触姿态**（pitch / 底盘离地）-> 用离地角动量注入（本节方案一）；
     - **接触之后**（后向漂移、二次冲击峰）-> 用预设位置目标点（本节方案二）。

================================================================
23.2 方案一：离地角动量注入（推力段轮子蹬地）
================================================================

23.2.1 物理机制

  推力段机器人仍在地面，轮子蹬地产生**水平地面反力 F**，作用点在轮底（质心下方
  `z_com = 0.264 m`），对质心形成**外部俯仰力矩**。这改变了整机角动量，
  **不经过髋通道**，所以不违反 21 节的 2:1 交换率。

  髋在推力段继续守 `φ_world`（地面上髋有地面反力支撑，不会像空中那样反作用到机体），
  所以**推力方向不变**，不会重现预倾那次的落点后退。

23.2.2 量算（目标：抵消实测漂移 0.455 rad，滞空 0.30 s，推力段 109 ms）

  | 量 | 公式 | 值 |
  |---|---|---|
  | 需要的离地俯仰角速度 | ω0 = Δθ / T_flight | 0.455/0.30 = **1.5 rad/s** |
  | 角冲量 | L = I_eff * ω0 | 0.1142*1.5 = **0.171 N*m*s** |
  | 线冲量 | Δp = L / z_com | 0.171/0.264 = **0.648 N*s** |
  | 水平速度代价 | Δv = Δp / m | 0.648/14.546 = **0.045 m/s** |
  | 每轮力矩 | τ = Δp*r/t /2 | 0.648*0.077/0.109/2 = **0.23 N*m** |
  | 地面摩擦需求 | F = Δp/t | **5.9 N**（远低于 μN，N≈200~300 N）|
  | 落点位移代价 | Δv * T_flight | **1.3 cm** |

  对照限值：轮子 `ctrlrange ±6 N*m`，只需 **0.23 N*m（4%）**。
  对照预倾路线：预倾付出 48 cm 落点后退，这里是 1.3 cm。

23.2.3 实现落点

  | 项 | 位置 | 说明 |
  |---|---|---|
  | 施加 | `jump_command.wheel_torque` 在 THRUST 段叠加 | 该字段已存在 |
  | 新参数 | `takeoff_pitch_moment: float = 0.0`（N*m，每轮），默认 0 = 原行为 | `SimulationConfig` + 命令行 `--takeoff-pitch-moment` |
  | 施加窗口 | 仅 `THRUST` 相位 | 复用现有相位，不新增时长 |
  | 符号 | 由"使机身获得正俯仰角速度"定义；一次运行即可确定 | — |
  | 髋 | 推力段保持现有 `φ_world` 锁定，不改 | — |

  不传参（=0.0）时逐位不变，必须验证。

23.2.4 标定流程（两次运行）

  | # | 配置 | 目的 |
  |---|---|---|
  | 1 | `--takeoff-pitch-moment 0.0` | 对照；记录释放时角速度、触地 pitch、漂移 |
  | 2 | `--takeoff-pitch-moment 0.23` | 记录释放时实测俯仰角速度与触地 pitch |

  线性标定：实测 ω0 与理论 1.5 rad/s 的比例即修正系数；
  若实测 ω0 偏差 >30%，先查推力段力矩是否被限幅/积分吃掉，不要直接放大参数。

23.2.5 判据（方案一）

  | 序 | 项 | 要求 | 理由 |
  |---|---|---|---|
  | 1 | **gap** | >= 0.200 m，且相对对照降幅 <= 1% | 水平力与竖直方向正交，不该掉；掉说明耦合到了推力 |
  | 2 | 释放时俯仰角速度 | 与理论 1.5 rad/s 同号，量级在 0.7~1.5 倍 | 执行是否生效 |
  | 3 | 触地 pitch | 相对对照改善 >= 50%（对照约 -0.455）| 方案目的 |
  | 4 | 落点位移 | 相对对照 <= 0.02 m | 理论代价 1.3 cm |
  | 5 | 腿长 / 关节 | 全程在 [0.114, 0.430]；关节不越 MJCF range | 安全 |
  | 6 | 相位机 | 正常退出，无 ABORT | — |
  | 7 | 不跳回归 | T/CMD 逐位全 0 | 开关默认 0 |

23.2.6 已知风险（必须实测，不得假设）

  1. 推力段只有 109 ms，力矩突变可能被 `ctrlrange` 或积分器吃掉 -> 看判据 2；
  2. 轮子同时承担蹬地，叠加偏置是否改变离地时刻 -> 看判据 1、6；
  3. 漂移本身逐次有差异（-0.455 / -0.384 都出现过），所以幅值可能需按当次漂移缩放；
     在此之前不得直接把它当定值写入默认。
