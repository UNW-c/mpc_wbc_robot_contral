1. 物理

1.1 两个质量块

  下块 m1 = 3.924 kg（两轮 + GH/OP）；上块 m2 = 10.622 kg。
  z1、z2 为两块绝对高度，向上为正。腿长 L = z2 - z1（差值）。

1.2 轮子的牛顿分析

  m1*z1'' = N - m1*g - F          (1)
  N = m1*(z1'' + g) + F           (2)
  F = 腿对上块的作用力（正=撑开；对轮子的反作用为 -F）

  接地时 z1=0、z1'=0，只要 N>0 轮子就被压在地上。
  分离条件（N=0 且 z1''=0）：

  F = -m1*g = -38.5 N（两腿），单腿 -19.3 N            (3)

1.3 力由规划的轮子运动反解，不用弹簧刚度律

  F(t) = -m1*(z1''(t) + g)                                (4)
  tau  = J^T @ [F/2, F_phi]

  论文的虚拟弹簧 F = a*(l0-l)^3 + b*(l0-l) 是"给定轨迹求力"的另一种
  参数化；本工程的腿由电机驱动，直接用 (4) 即可，少一层拟合误差。

1.4 飞行段的动量关系

  z2'' = -k*z1'' - (1+k)*g ,  k = m1/m2 = 0.3694
  => 腿拉（F<0）时机体每秒多掉 k*g = 3.62 m/s^2
     腿撑（F>0）时机体每秒多升 3.62 m/s^2

  这是两块之间唯一的耦合。机体怎么走，完全由 z1(t) 的形状决定。

2. 两个判据（全跳只有两次状态转换）

2.1 离地判据：物理事实

  N_est = m1*(z1'' + g) + F
  数据：mj_objectVelocity / mj_objectAcceleration 直接读轮的 z1'、z1''；
        F = solve(J.T, tau_leg)，J 由 LegKinematics 现算。
  判定：N_est 连续 k 拍 <= 0  -> 接地假设不成立。
  精度：接地段实测比真实 N 低 7.5%（171 vs 185 N/轮，静力学映射忽略
        杆件惯量，论文同样忽略）；离地后该式失效，只用于穿越判断。

2.2 切段判据：计划边界，不是同一个条件

  离地与切段在时间上重合，但语义不同：
    离地：地面给不了那么大的力（物理事实）
    切段：计划要求轮子此刻静止且平衡（z1'=0、z1''=0）
  本版让计划自己保证这一点（见 3.3），所以切段不需要额外调节；
  实测偏差时按 2.3 重锚，而不是新加一个条件。

3. 整跳方案

3.1 三段，不是六段

  C 段  接触（压缩 + 蹬伸 + 释放）：现有 WBC 路径，末端 F -> -m1*g
  F 段  飞行：**一条轨迹** z1(t)，从离地到触地，内部不切换
  L 段  落地：现有 landing_buffer / WBC

  收腿、伸腿、团身、着地准备这些名字在本版里都不存在——
  它们是 z2(t) - z1(t) 的差值的表现。

3.2 飞行段轨迹：一条光滑鼓包

  取 u = t/T，f(u) = 64*u^3*(1-u)^3
  性质：f(0)=f(1)=0，f'(0)=f'(1)=0，f''(0)=f''(1)=0，f(0.5)=1
  规划：z1(t) = h * f(u)
  z2 由动量关系得出：z2(t) = z2(0) + v0*t - (1+k)*g*t^2/2 - k*z1(t)

  于是 z1'(0)=z1'(1)=0（轮子离地与触地都是静止），
  z1''(0)=z1''(1)=0 -> F(0)=F(T)=-m1*g（(3) 的干净离地条件自动满足）。

3.3 两个量都由约束解出，不靠调

  T：触地时 z1=0 且 L = z2 = L_td（落地腿长 0.28）：
     L0 + v0*T - (1+k)*g*T^2/2 = L_td
     => T = [v0 + sqrt(v0^2 - 2*(1+k)*g*(L_td - L0))] / ((1+k)*g) = 0.342 s

  h：要求腿长最小值 = L_tuck = 0.16（间隙约束）：
     注意 L = z2 - z1 = L0 + [v0*t - (1+k)*g*t^2/2] - (1+k)*h*f(u)
     （(1+k) 来自 z2 的动量关系，不能漏）
     min over t of L(t) = L_tuck   =>  h = (0.478 - L_tuck)/1.3694 = 0.2323 m

3.5 这条方案顺手给出的东西

  (1) 离地干净：F(t1) = -m1*g -> N=0，轮子静止离地；
  (2) 触地干净：z1'(T) = 0 -> 轮子竖直速度为 0（当前实测 -2.07 m/s，
      是 427.9 N 冲击的来源）；
  (3) 团身自动出现：L 最小值 0.160，位置在 u=0.5；
  (4) 伸腿自动出现：L 从 0.160 回到 0.280；
  (5) 峰值力矩 14.0 N·m（39%），不再打满；
  (6) 飞行段内部零切换：没有收/伸腿的状态，也没有相位判据。

3.6 与 v5 的差别（为什么 v5 是错的）

  v5 把飞行切成"团身 0.13 s + 保持 + 伸腿"，并单独给每段定边界条件。
  但两块之间只有一条 F，任何"分段"都会在段边界引入力/加速度的不连续，
  然后靠下一段去补偿。v6 用一条 C2 连续的轨迹消掉了这件事，
  峰值力矩反而更低（14.0 vs 26.2 N·m），且触地速度变成 0。

3.7 两个参数的准确含义（这一节回答"这两个是什么"）

  L_tuck  [m]  飞行段允许的最小腿长（收得最深处的腿长）。
    它决定：轮子相对机体被拉多高，也就是离地间隙。
    它不决定：落地缓冲行程（触地腿长固定为 L_td=0.28）、飞行时长 T。
    现值的来源：`FLIGHT_RETRACT_FLOOR = 0.16`（SW1 扫描里唯一过全硬约束）。
    可调范围：机械限位 0.114~0.430，实际受间隙要求限制。

  h  [m]  轮子绝对高度轨迹的幅值（轮子在飞行中段比离地时高多少）。
    **不是独立输入**：h = (L0 + 0.195 - L_tuck)/(1+k) = (0.478 - L_tuck)/1.3694。
    它决定：峰值力/力矩（tau 正比于 h/T^2）。
    它不决定：落地腿长、飞行时长。

  两者的关系与选择（T 固定 0.342）：

    想省力矩就往 0.18~0.20 调，代价是间隙降到 0.20 左右。

3.8 观测与验证：两块可以分别测，这是本建模额外给出的东西

  只看腿长 L(t) 时，两条完全不同的物理过程被压成一个数：
  轮子被拉高 5 cm 与机体被拖低 5 cm，在 L 上都表现为"腿短了 10 cm"，
  无法区分是谁的问题。分开之后每个量都可独立测量、独立预测：

    量      定义                      数据来源
    z1      轮子绝对高度              qpos[2] - L（现有记录即可算）
    z1'     轮子竖直速度              qvel[2] - leg_rate（腿长率）
    z2      机体绝对高度              qpos[2]
    z2'     机体竖直速度              qvel[2]
    L = z2-z1（差值，不再单独看）     leg_state

  三者的误差含义不同，可直接用于诊断：

    z1 偏离计划  -> 腿力/力矩通道问题（力给多了或给少了、被限幅）
    z2 偏离计划  -> 机体的响应问题（冲量时机不对、phi 反作用、俯仰耦合）

7. 风险与未解

7.1 v0（离地时机体竖直速度）用捕获帧实测。若 S2 的释放段改变了 v0，
    T 与 h 会随之变化（公式自动跟随，不需要改代码）。
7.2 F 依赖 m1、m2 的准确值（MJCF）。换轮/加配重必须重测。
7.3 飞行段总角动量守恒（实测 -0.350 +- 0.002 kg*m^2/s），本版不改它；
    机体俯仰只能靠 phi 通道在机体与腿之间分配。轮子无法定俯仰
    （惯量比 127:1，飞行段轮力矩实测 0.00 N*m）。本版不碰 phi。
7.4 h 由 L_tuck 解出，L_tuck 仍是落地间隙/行程的设计输入（0.16）。
    若落地间隙要求变化，改 L_tuck，h 自动跟随。
7.5 不承诺触地 pitch 大幅下降；能确定改善的是离地/触地条件、
    力矩峰值（39% vs 打满）与触地速度（-2.07 -> 0）。

10.8 2026-10-21  轮子水平方向（x）作为控制量：分析

  A. 先给结论

     (1) "控制轮子 x" 与控制 phi 是**同一条通道**（都是改腿的倾角），
         执行器、力矩映射、限幅全一样；变的只是目标与误差的定义。
     (2) 作为**误差/诊断量**它明显更好：d = com_x - 轮心 x 就是俯仰力臂，
         物理含义直接；phi 只是一个关节角，看不出后果。
     (3) 作为**控制目标**，它的净收益是二阶的：实测力臂力矩峰值 2.2 N·m、
         净冲量 -0.149 N·m·s，只占飞行段 omega 暂态（峰值 -4.94 rad/s）的
         约 25%；主导项是腿自身的角动量转移，不是力臂。
     (4) 真正值得做的是 **phi(t) 的相位整形**，不是换目标：
         力矩 = F(t)*L*sin(phi(t))，只要让 |phi| 大的时段避开 |F| 大的时段，
         同一个 phi 摆幅（同一份 H 存储）可以换来更小的力矩冲量。

     腿力 F_L 峰值 81 N；力臂 d 峰值 44.6 mm；乘积峰值 2.2 N·m
     ∫(F_L*d)dt = -0.149 N·m·s
     ∫F_phi dt  = +0.006 N·m·s（phi 通道自身，可忽略）

     相位关系（这就是问题所在）：

       t      F_L     phi_world   d(mm)   F*d(N·m)  omega
       1.427  -25.4   -0.122     +0.1     -0.0     -0.03
       1.457  -79.8   -0.106     +2.9     -0.2     +0.35
       1.517  -16.8   +0.022    -32.2     +0.5     -1.05
       1.547  +24.4   +0.097    -43.8     -1.1     -3.44
       1.577  +50.3   +0.126    -42.4     -2.1     -4.94
       1.607  +56.8   +0.081    -32.7     -1.9     -4.46
       1.727  -79.1   -0.040     -0.3     +0.0     -0.15

     |F| 大（-80 N）时 |d| 接近 0；|d| 大（-44 mm）时 F 已经翻号变推（+50 N）。
     两者叠加出 -2.1 N·m 的峰，位置正好在 omega 峰（-4.94）附近。

  C. 为什么净收益只有二阶

     飞行段 omega 从 -0.03 冲到 -4.94 再回到 -0.15。要产生这个暂态需要
     ∫M dt ≈ I_eff*4.9 = 0.56 N·m·s；实测力臂项只有 0.149 N·m·s（26%）。
     其余来自腿的摆动把角动量在机体与腿之间搬（H_leg 从 +0.33 到 -0.51）。
     所以把 d 压到 0 最多消掉四分之一的暂态，不可能改变量级。

  D. 相位整形是可行的（下一步的候选，不在本轮）

     目标：min ∫|F(t)*L*sin(phi(t))|dt，约束 phi 的净摆幅（决定 H 存储）
           不变或更大。
     可动的形状：phi(t) 的增长时刻、峰值时刻、是否先反向预置。
     判据：飞行段 |omega| 峰值（当前 4.94）、触地 omega（当前 -0.32）、
           以及 z1/z2 偏差不变差。

  E. 不做的

     - 不把控制目标改成"轮子 x 位置跟踪"：等价于换一个 phi 参考，
       收益二阶，却要重写 phi 参考与状态估计，风险大于收益。
     - 不动 KP_PHI/KD_PHI/FEEDFORWARD_COUPLING。

10.9 2026-10-21  把控制量搬到轮子质量块的 (x, z)：可行，且给出下一步方案

  A. 你说的"控制量变多"成立，原因是自由度对应关系

     腿的两个自由度 (L, phi) 与轮子相对髋的平面位置 (x, z) 是一一对应的：
       x = -L*sin(phi) ,  z = -L*cos(phi)          (轮在髋下方)
       Jp = d(x,z)/d(L,phi) = [[-sin, -L*cos], [-cos, L*sin]]
     广义力变换：
       (F_L, F_phi) = Jp^T * (F_x, F_z)
       F_L   = -sin(phi)*F_x - cos(phi)*F_z
       F_phi = -L*cos(phi)*F_x + L*sin(phi)*F_z
     Jp 的 det = L（0.16~0.34 全程非奇异），即两组量完全等价、可逆。

     所以"在轮子上规划 (x, z)"不是换一个目标，而是换一套**物理量纲**：
       - 现在：F_L 由 z 轨迹反解，F_phi 由 phi 的 PD 补；
       - 换成：F_x、F_z 都由轮子轨迹反解，phi 的 PD 与耦合前馈**全部去掉**，
               phi 变成结构输出（就像 L 一直是结构输出一样）。
     这一步同时满足"不控 phi"和"保留 phi 摆动"两个要求——
     因为 phi 仍会摆，只是不再由 PD 推，而是由 x 轨迹决定。

  B. 这样多出来的控制量怎么用：x 轨迹的相位

     上一节已测：力矩 = F_z(t) * d(t)，d = com_x - 轮心 x，实测 ∫F·d dt = -0.1485。
     把 d(t) 平移（形状与幅值不变 -> H 存储不变）后的力矩冲量：

       平移 -40 ms   ∫F·d = -0.1816
       平移 -20 ms   ∫F·d = -0.1924
       平移   0 ms   ∫F·d = -0.1485   （现状）
       平移 +20 ms   ∫F·d = -0.0551   <- 减少 63%
       平移 +40 ms   ∫F·d = +0.0547   （过冲，符号反了）

     即：**同一个摆幅，把轮子的横向偏移推迟 20 ms，力臂力矩冲量降 63%**。
     这正是只能在新坐标系里做的事：以前 d 是 phi 的副产品，没法单独定时。

  C. 下一步方案（S1-x）

     C1 把飞行段出力矩改成 (F_x, F_z) 形式
        输入：轮子绝对 (x, z) 规划；输出：(F_L, F_phi) = Jp^T (F_x, F_z)
        -> tau = J^T [F_L/2, F_phi]（原映射不变，每腿一份）
        z 轨迹：沿用 3.2 的鼓包（不变，h 由 L_tuck 解出）
        x 轨迹：A_x * f(u^k)，f 为同一鼓包形状，A_x = 40 mm（实测摆幅），
                k = 1.0（等价现状，用于回归）或 k = 1.4（峰值从 u=0.5 推到 0.63）
        去掉：flight 段的 _phi_force 与 FEEDFORWARD_COUPLING（phi 不再被 PD 控制）
        保留：z 方向的跟踪项 3000*(L_ref-L)+150*(v_ref-v) 折算到 F_z

     C2 两个 case
        x_k1.0：验证"只换坐标系、不改行为"——应与 s1pd 接近（M1-M4、|omega| 峰）
        x_k1.4：相位后移，看力臂力矩冲量是否按 63% 下降

     C3 判据（在 S1-PD 的基础上）
        主：M1 触地 pitch（-0.5394）、M2 max|pitch|（0.5916）、
            M3 峰值力（201.8 N）、M4 触地 omega（-0.32）
        新增：P7 飞行段 |omega| 峰值（当前 4.94）
              P8 ∫(F_z*d)dt（当前 -0.1485，目标 <= -0.08）
        守卫：G1-G4 不变；z1/z2 偏差不变差

  D. 风险

     D1 去掉 phi 的 PD 之后，phi 完全由 x 轨迹决定，误差无反馈修正。
        若 x 的跟踪有偏差，phi 会跟着偏，落地姿态可能变差。
        缓解：x 方向用同一个跟踪增益（对 x 误差做 PD），保持闭环。
     D2 Jp 在 phi 接近 +-90 度时退化；本工程 phi 在 +-0.6 rad 内，不触发。
     D3 F_x 分量会引入水平反作用到机体（这是它的作用，不是副作用），
        但会改变触地前的水平速度；G2 落点判据继续盯。

  E. 结论

     可行。它把"存动量"和"力臂相位"这两个原本纠缠在 phi 上的东西拆成了
     两个可独立规划的量：z 决定存多少，x 的相位决定花多少代价。
     这是本轮之后最值得做的一步，且不需要新增益。
