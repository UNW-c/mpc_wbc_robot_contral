## 一、系统总览

### 1.1 架构

```
输入（键盘/手柄/程序化）
      │  MotionCommand(velocity, yaw_rate)
      v
┌─────────────────────────────────────────────────────────────┐
│ 监督层  Algorithm/supervision.py                             │
│  ControlSupervisor：模式机（disabled/airborne/single_support/ │
│                      recovery/ground）                        │
│  SupervisedControl：solve_mpc() + solve_wbc() 的唯一入口       │
│  安全：姿态 guard、速度 guard、意外接触、非有限状态             │
└──────────────┬────────────────────────────┬──────────────────┘
               │ 50 Hz                       │ 250 Hz
               v                             v
┌──────────────────────────────┐  ┌──────────────────────────────────┐
│ MPC  Algorithm/mpc/*          │  │ WBC  Algorithm/wbc/task_qp.py     │
│  降阶 6 状态线性模型            │  │  单级 QP：z = [qacc, f, tau]       │
│  凝聚 QP（OSQP）               │─>│  硬约束：动力学 + 接触一致性 +       │
│  输出：优化轨迹 + 轮力          │  │          力矩限 + 法向非负          │
│  接口：OptimizedTrajectory     │  │  输出：4 执行器力矩                │
└──────────────────────────────┘  └──────────────┬───────────────────┘
                                                 v
                                  ┌──────────────────────────────┐
                                  │ 1 kHz MuJoCo 定步长物理        │
                                  │ data.ctrl = [j1,j3,j2,j4] 力矩 │
                                  └──────────────────────────────┘
```

### 1.2 频率与调度

| 层 | 周期 | 频率 | 代码 |
|---|---|---|---|
| 物理 | 0.001 s | 1 kHz | MuJoCo 定步长 |
| WBC | 0.004 s | 250 Hz | `Algorithm/timing.py::ControlTiming.wbc_due` |
| MPC | 0.020 s | 50 Hz | `ControlTiming.mpc_due` |

周期必须是物理步的整数倍、MPC 必须是 WBC 的整数倍（`ControlTiming.__post_init__` 校验）。

### 1.3 启动

```bash
.venv/Scripts/python.exe -m APP.mujoco_mpc_wbc --viewer --output artifacts/xxx
# 无人值守：--duration N --output ...；后端选择：--wbc-backend qp|nullspace（不传则用配置默认 qp，2026-09-27 修复 CLI 死参数）
```

### 1.4 机器人模型规模（MuJoCo"plane"场景实测）

- `nq=11`（浮动基 7 + 4 关节），`nv=10`（浮动基 6 + 4 关节），`nu=4`
- 关节：`floating_base`、`joint1`（右髋）、`joint2`（右轮）、`joint3`（左髋）、`joint4`（左轮）
- 执行器：`j1_ctrl`、`j3_ctrl`（髋）、`j2_ctrl`、`j4_ctrl`（轮）
- 平衡点俯仰 `equilibrium_pitch = 0.000215 rad`

## 二、MPC 建模（规划层，50 Hz）

代码：`Algorithm/mpc/`（`model.py` / `controller.py` / `qp.py` / `planner.py` / `contact.py` / `trajectory.py`）

### 2.1 方案类型

**降阶线性 MPC + 凝聚型 QP（condensed QP）**：

- 模型：不是 SRBD（单刚体）也不是全动力学，而是**由 MuJoCo 在当前接触位形实测的 4x4 线性化**
  （`Algorithm/lqr.py::measure_contact_linearization`），再拼上偏航惯量构成 6 状态模型；
- 线性化来源：`APP/mujoco_balance_model.py::HeldHipModelBuilder`（held-hip 假设：
  髋被"握住"的滚动接触模型，与零速 WBC 的假设一致）；
- 求解：把状态消掉（condensed），QP 只有 `2N = 50` 个力变量（`N=25`），OSQP 求解，
  稀疏结构一次编译、每拍只更新 `q/l/u`；
- 兜底：求解失败时两级（沿用上一拍解的下一格 → LQR 增益），连续 3 拍失败置 `degraded`。

### 2.2 状态（6 维）

```
x = [s, v, pitch, pitch_rate, yaw, yaw_rate]
```

| 状态 | 含义 | 来源 |
|---|---|---|
| `s` | 行驶里程（沿 heading 积分） | `APP/mujoco_mpc_wbc.py::distance` |
| `v` | 前向速度 | heading 速度投影 |
| `pitch` | 俯仰角（相对平衡点） | 四元数分解 |
| `pitch_rate` | 俯仰角速度 | 欧拉率行 |
| `yaw` | 偏航角 | 四元数 |
| `yaw_rate` | 偏航角速度 | 欧拉率行 |

**被删掉的状态及理由**（`Algorithm/mpc/model.py` 文档）：

| 状态 | 删除理由 |
|---|---|
| `p_y, v_y`（横向） | 横向没有执行器，是非完整约束下由 yaw 决定的从动量，不是自由状态 |
| `p_z, v_z`（高度） | 高度由偏心曲柄当位置源直接给定，不是靠法向力积分出来的，交给腿部规划/WBC |
| `roll, roll_rate`（横滚） | 横滚靠左右差动法向力，权限瞬时、无非最小相位问题；单支撑时权限为零，交 WBC |

模型特征值实测：`{-4.702, +4.702, 0, 0, 0, 0}`——不稳定极点 **4.702 rad/s**（俯仰通道）。

### 2.3 输入（2 维）

```
u = [f_right, f_left]     # [N] 两轮纵向地面力
```

- 净驱动力 `= f_right + f_left`
- 偏航力矩 `= half_track × (f_right - f_left)`
- 力 → 力矩换算（`ReducedModel.torque_from_force`）：`j2 = +R·f_right`、`j4 = -R·f_left`

### 2.4 离散化与预测

- 离散化：矩阵指数精确离散（`ReducedModel.discretize`，把输入与漂移项一起增广）；
- `dt = 0.02 s`（50 Hz），`horizon = 25`（视界 **0.5 s**）；
- 已知漂移输入：髋力矩（`hip_torque_drift`）经 `drift_step_map(dt)` 折成每步增量；
  当前配置 `compensate_hip_torque=False`——因为 held-hip 降阶模型**已经包含**髋反作用，
  再补一次会重复计入（`APP/mujoco_mpc_wbc.py` 注释）；
- 状态预推 `prediction_lead`（默认 0）与参考预取 `preview_lead`（默认 0.0，即实际时刻采样；
  2026-09-27 T4 从 0.02 改回，理由见排查记录 #6）

### 2.5 代价函数

```
J = (X - X*)' Q̄ (X - X*) + U' R̄ U + (ΔU - E·u_prev)' R̄_d (ΔU - E·u_prev)
```

- `Q̄`：状态权重（终端步 ×`terminal_scale=5`）
- `R̄`：输入权重（逐轮 `force=0.02`）
- `R̄_d`：输入变化率权重（`force_rate=0.08`）

当前权重（`Algorithm/mpc/qp.py::QPWeights`，2026-09-25 多工况联合扫描定稿）：

| 权重 | 值 | 说明 |
|---|---|---|
| `position` | 80000 | 位置回零（扫描新增） |
| `velocity` | 2000 | 速度跟踪 |
| `pitch` | 51200 | 俯仰（最高） |
| `pitch_rate` | 960 | 俯仰角速度 |
| `yaw` / `yaw_rate` | 60 / 8 | 偏航 |
| `force` / `force_rate` | 0.02 / 0.08 | 输入与变化率 |
| `terminal_scale` | 5.0 | 终端权重倍率 |

### 2.6 约束（全部写成对 U 的线性不等式，共 5N 行）

1. **逐轮箱型**：`|f_i| ≤ min(τ_max/R, μ·f_z,i)`——力矩限 + 摩擦锥退化成的逐轮上下界，
   腾空轮为 0（`wheel_force_limit`）；
2. **偏航力矩**：`|half_track·(f_R - f_L)| ≤ M_z,max(q)`，含 scrub 折扣
   （`scrub_moment_coefficient·|sin q|`）与地板 `yaw_moment_floor=0.5`；
3. **俯仰带**：`|pitch| ≤ 0.785 rad`（45°，用户 2026-09-22 指定）；
4. **速度带**：`|v| ≤ 1.60 m/s`。

约束 1 永远可行（U=0）；3/4 不可行时自动松掉重解一次（标记 `relaxed`）。

### 2.7 输入输出

**输入**（`WheelMPC.solve`）：

| 参数 | 类型 | 含义 |
|---|---|---|
| `state` | `ChassisState` | position/velocity/pitch/pitch_rate/yaw/yaw_rate/hip_angle/hip_torque/normal_forces/contact |
| `command` | `MotionCommand` | velocity、yaw_rate（驾驶入口只接受速度指令） |
| `feedback` | `ReferenceFeedback` | 接触/俯仰反馈（供 planner 状态机） |
| `disturbance_acceleration` | `(3,)` | 扰动加速度（前向/俯仰/偏航），进预测 |

**输出**（`MPCSolution`）：

| 字段 | 含义 | 谁消费 |
|---|---|---|
| `trajectory` | `OptimizedTrajectory`（states (N+1)×6、forces N×2、dt、start_time） | **WBC 采样**（主要接口） |
| `force` | 本拍轮力 `[f_right, f_left]` | 记录/诊断 |
| `predicted_states` | 预测轨迹（含当前状态） | 参考、诊断 |
| `reference` | `ReferenceTrajectory`（planner 的参考） | 位置参考（WBC 位置环） |
| `pitch_reference` / `velocity_reference` / `position_reference` | 便捷属性 | 诊断 |

**WBC 的消费方式**：`solution.trajectory.sample_at(t + preview_lead)` → `MotionSample(state, acceleration, force)`；
`state` 供 pitch/yaw PD 与速度参考；`acceleration` 是 MPC 前馈（pitch 任务里 `acceleration[1]`）。

## 三、WBC 建模（执行层，250 Hz）

代码：`Algorithm/wbc/task_qp.py`（主）、`Algorithm/wbc/projection.py`（接触消力与任务容器）、
`Algorithm/wbc/sns.py`（限幅与结果类型）

### 3.1 方案类型

**单级 QP 全身控制**（不是零空间法）：

- 零空间法（旧，`--wbc-backend nullspace`）：任务当硬等式逐级投影，执行器少于任务维数时
  低优先级任务被耗尽（scaling 恒 0），力矩是反解副产品；
- **单级 QP（当前）**：`qacc` / 接触力 `f` / 关节力矩 `tau` 全部是决策变量，
  任务只进**代价项**（软目标按权重竞争，不会被清零），"期望状态"是"尽量达到"。

### 3.2 决策变量（19 维）

```
z = [qacc (nv=10), f (nc=5), tau (na=nu=4)]
```

- `qacc`：广义加速度（浮动基 6 + 4 关节）
- `f`：接触力，**排列 = [切R, 法R, 切L, 法L, 共模横]**（双支撑 5 行；
  单支撑 3 行；共模横 = 两侧横向力均值，法向下标 `(1,3)`）
- `tau`：4 个执行器力矩

### 3.3 硬约束（四类）

1. **浮动基动力学等式**：`M·qacc + h = S'·tau + Jc'·f`
   （`h = qfrc_bias - qfrc_passive`，MuJoCo 被动力在方程右端）
2. **接触一致性等式**：`Jc·qacc + contact_bias = 0`——接触点不穿透/不分离的加速度级约束；
   没有这条时 QP 可以随意组合 `f` 与 `tau`"满足"任务，解在物理中不可实现
3. **执行器力矩上下限**：`limits.lower ≤ tau ≤ limits.upper`（来自 `actuator_ctrlrange`）
4. **接触法向非负**：`f_n ≥ 0`（不能拉地面）；摩擦锥暂未加入（2026-09-22 用户决定）

不可行兜底两级：去掉接触一致性重解（`f` 回归自由）→ 仍不可行输出零力矩（`fallback_used=True`）。

### 3.4 任务（软目标）

任务定义在 `APP/mujoco_mpc_wbc.py::tasks()`。任务行来自
`MuJoCoDynamics.kinematics`：

| 行 | 含义（雅可比 = 行向量） |
|---|---|
| `rows[0]` | 沿 heading 的前向速度 |
| `rows[1]` | roll 角速度（欧拉率） |
| `rows[2]` | pitch 角速度（欧拉率） |
| `rows[3]` | yaw 角速度（欧拉率） |

任务表（当前权重 `_TASK_QP_WEIGHTS`）：

| 任务 | 雅可比 | 目标加速度 | 权重 | 激活 |
|---|---|---|---|---|
| `pitch` | `rows[2]` | MPC 前馈 `acceleration[1]` + PD(`kp=80, kd=10`) | 100 | 恒开 |
| `roll` | `rows[1]` | `-kp·roll - kd·roll_rate`（目标 0） | 100 | `max(roll_gain_scale(hip), 1.0)` |
| `yaw` | `rows[3]` | MPC 前馈 + PD(`kp=80, kd=10`) | 50 | 恒开 |
| `height` | `np.eye(nv)[[2]]` | `kp_h·(h*-h) - kd_h·ż`（`kp_h=100, kd_h=12`） | 50 | `max(排程因子, 1.0)` |
| `forward_velocity` | `rows[0]` | `vg·(v_cmd - v) - pg·(s - s_ref)`，限幅 ±50 | 50 | 恒开 |
| `regularization` | `np.eye(nv)[hip_v]`（髋关节行） | `kp_r·(q_hip* - q_hip) - kd_r·q̇_hip`（`kp_r=60, kd_r=6`） | 1 | 恒开 |

说明：

- **绝对回零结构**：速度任务目标用"指令速度 - 实测速度"+"位置误差"，
  不用相对 MPC 参考的 PD（实验证明相对参考 PD 会因参考更新滞后失效）；
  位置参考取 planner 参考位置（HOLD 为原点、DRIVE 跟随实测），防 DRIVE 被拉回；
- `forward_velocity` 的 `pg=320`（位置增益）/`vg=320`（速度增益）是 2026-09-25
  联合扫描最优；`acceleration_limit=50` 只防大误差时目标爆炸；
- 任务残差/达成值/激活度每拍记录（`task_residuals`/`task_goal`/`task_activation`）。

### 3.5 输入输出

**输入**（`SupervisedControl.solve_wbc` → `TaskQpResolver.resolve`）：

| 参数 | 类型 | 含义 |
|---|---|---|
| `mass` | `(nv, nv)` | 质量矩阵（每拍从 MuJoCo 取） |
| `selection` | `(nu, nv)` | 执行器选择矩阵（含 gear） |
| `dynamics_bias` | `(nv,)` | `qfrc_bias - qfrc_passive` |
| `contacts` | `ContactBlock` 元组 | 每个块的雅可比 + 偏置 + 所属轮 |
| `balance_tasks` / `motion_tasks` | `TaskLevel` 元组 | 任务（含雅可比/目标/偏置/激活） |
| `limits` | `ActuatorLimits` | 力矩上下限 |
| `decision` | `ControlDecision` | 模式与使能（决定是否平衡/运动） |
| `dt` | float | WBC 周期 |

**输出**（`SNSResult`）：

| 字段 | 含义 | 谁消费 |
|---|---|---|
| `torque` | 4 执行器力矩 | **`data.ctrl`**（写入 MuJoCo） |
| `qacc` | 广义加速度解 | 诊断、接触力恢复 |
| `hierarchy.outcomes` | 每个任务的残差/达成 | 记录（诊断） |
| `contact_residual` | 接触一致性残差 | 记录/停机判据 |
| `dynamics_residual_norm` | 动力学残差 | `feasible` 判据（<1e-5） |
| `fallback_used` / `feasible` | 兜底/可行性标记 | 停机判据、计数 |

### 3.6 求解器参数

- OSQP：`eps_abs=eps_rel=1e-7`、`max_iter=20000`、`polish=True`、warm start；
- 正则：Hessian 加 `1e-9·I`；`torque_weight=1e-3`、`force_weight=1e-3`（最小二乘正则）；
- 日志限流：只在 fallback 状态跳变时输出（250 Hz 循环）。

## 四、监督层（模式与安全）

`Algorithm/supervision.py`：

- `ControlSupervisor.update()`：输入接触/时间/使能/稳定标志 → `ControlDecision`
  （模式 = disabled / airborne / single_support / recovery / ground，含 context 计数与 `reset_reference`）；
- 模式判据：双支撑且稳定 `touchdown_dwell=0.10 s` 才进 ground；
- `SupervisedControl.solve_mpc()`：`motion_enabled`（ground）才更新 MPC，否则 reset 并返回 None；
- `SupervisedControl.solve_wbc()`：`balance_enabled`（ground/recovery/single_support）才出平衡力矩，
  否则显式零力矩返回 None；
- 安全（`APP/mujoco_mpc_wbc.py::run`）：`attitude_guard=0.785 rad`（45°）、
  `speed_guard=1.60 m/s`、`unexpected_body_contact`、`nonfinite_state`、`torque_limit`、
  `negative_predicted_normal_force`——触发即停机并记录 `stop_reason`。

## 五、参考生成（VelocityPlanner）

`Algorithm/mpc/planner.py`：

- **输入**：`MotionCommand(velocity, yaw_rate)`（驾驶入口只接受这两项）+ 实测状态；
- **模式**（`ReferenceMode`）：RESET / HOLD / DRIVE / BRAKE / CAPTURE 等；
- **限值**（`MotionLimits`）：`max_speed=1.20`、`commanded_acceleration=0.80`、
  `max_braking=2.00`、`max_acceleration=2.00`（yaw 类似）；
- **输出**：`ReferenceTrajectory`（参考状态 (N+1)×6、速度、位置、偏航）+ `valid` 标志；
- 位置参考语义：HOLD 时锚定原点（保持回位误差），DRIVE 时跟随实测（不把车拉回）。

## 十、2026-09-29 追加：默认配置与跳跃模块（第 18～21 次排查）

以下为追加说明，前文不改；与前文冲突时以本节为准。

### 10.1 当前默认（不传参数就是这一套）

```bash
.venv/Scripts/python.exe -m APP.mujoco_mpc_wbc --viewer          # 默认 tuned-fast-accel，跳跃开启，空格起跳
.venv/Scripts/python.exe -m APP.mujoco_mpc_wbc --viewer --no-jump
```

- MPC：`APP/mujoco_mpc_wbc.py::default_app_mpc_settings()`，包括 tuned-fast 权重、`hip_angle_limit = 0.8`、S 曲线（jerk 限制）、倾角辅助限值、俯仰前馈。算法层 `MPCSettings()` 的默认值**没有改**。
- WBC：`tracking_velocity_gain / position_gain = 14 / 49`（ω = 7），`_TASK_QP_WEIGHTS["hip_tracking"] = 200`，`hip_guard = 1.70`。
- `--preset old / new / tuned-*` 仍然可用。

### 10.2 跳跃链路

| 文件 | 职责 | 关键类 / 函数 |
|---|---|---|
| `Algorithm/contact_state.py` | 离地检测（法向力阈值 + 时间滤波 + 相位门控） | `GroundContactEstimator` |
| `Algorithm/jump.py` | 跳跃状态机 PREPARE → THRUST → FLIGHT → LANDING → RECOVER → IDLE / ABORT | `JumpController`、`JumpParams` |
| `Algorithm/mpc/controller.py` | PREPARE 的预倾参考 | `WheelMPC.pitch_bias_target` / `pitch_bias_rate` |
| `APP/mujoco_mpc_wbc.py` | 接入、力矩换算、CLI | `_jump_step`、`_jump_torque`、`request_jump`、`--jump` / `--no-jump` |

- THRUST / FLIGHT / LANDING 期间 MPC / WBC 脱离（`override_balance`）。着地后由监督层的 RECOVERY → GROUND 接管，MPC 在落地点重新锚定。
- 关键参数（`JumpParams`）：`preload_pitch` −30°、`preload_rate` 3 rad/s、`prepare_tolerance` 5°、`prepare_dwell` 4 ms（蓄力 136 ms）、`recover_duration` 4 ms（落地收敛约 0.5 s）。
- 指标：轮底离地约 385 mm；零速度到 2.0 m/s 都不停机。

### 10.3 已知限制

- 被推离地（非跳跃状态）没有飞行 / 着地控制律（第 14 次排查 L0～L3，未做）。
- 跳跃期间不响应速度指令。**更正（第 29 次排查）**：`JumpController.request()` 只要求状态机处于 IDLE，
  **没有**速度 / 俯仰条件，高速行驶时按空格同样会起跳（实测在 v ≈ 2.5 m/s 完成 PREPARE 并起跳）；
  高速起跳冲击较大（髋力矩 ±10 N·m、轮力矩 ±5 N·m 均饱和），是否加接受条件待定。
- 跳跃中俯仰峰值 36～39°，距离 45° 保护线余量小。
- 详见 `docs/落地优化交接文档.md`。

### 10.4 第 28～30 次排查新增的开关（默认关闭）

| 开关 | 位置 | 作用 | 默认 | preset 启用 |
|---|---|---|---|---|
| `MotionLimits.unwind_before_brake` | `Algorithm/mpc/planner.py` | 加速度与目标反向时先用起步 jerk 卸到 0 | False | tuned-agile |
| `MPCSettings.preserve_ramp_on_recontact` | `Algorithm/mpc/controller.py` + `supervision.py` | 0.25 s 内的短时脱离只软复位（保留斜坡与 commanded） | False | tuned-agile |
| `SimulationConfig.contact_idle_off_duration` | `APP/mujoco_mpc_wbc.py` | 非跳跃相位的离地确认时间 | None（0.008 s） | 不启用 |
| `SimulationConfig.contact_lift_height` | 同上 | 非跳跃相位离地的运动学旁证 | None | 不启用 |
| `MPCSettings.drive_hip_angle_limit` | `Algorithm/mpc/controller.py` | 速度指令驱动时放宽髋角约束（其余按 `hip_angle_limit`） | None | tuned-agile = 1.2 |
