## 2026-10-05（续）：轮腿 MPC-WBC 连接修复 / 腿角预算部署换档

详细记录见 `wheel_leg_mujoco/MPC-WBC部署方案.md` 第 10、11 节。范围只在 `wheel_leg_mujoco/`，**未改 `Algorithm/`**。

**设计层排查（不跑测试，只读 .md + 核对代码）找出 7 条问题**，其中 2 条结构性：

- **F-1（严重）WBC→MPC 反馈回路全断**：`simulation.py` 从未调用 `feedback.observe()`（circleg `APP:593` 有）；
  且 `WeightedSaturationResolver` 返回 `outcomes=()`，`observe` 会早退 → `planner` 的 `blocked` 永不成立、
  `capability` 永不降级。
- **F-2（严重）WBC 后端选 `wls` 而非设计路径**：circleg 默认 `qp`、不允许 `wls`；`weighted.py` 自称"对照用途"。
  WLS 越限直接 `clamp` → 返回的 `τ` 与 `q̈`/接触力不再动力学一致；且接触力不是决策变量。
- F-3 WBC 采样用了 `prediction_lead`，circleg 用 `preview_lead`（两个不同参数）。
- F-5 降阶模型是"髋自由"工作点（ZJU 评审 §2.E 已点名），与 WBC 实际的位置跟踪腿角不符。
- F-6 §5.6 自己写明"ZMP 要在有加速度指令的工况下才看得出来"→ "ZMP 无效"结论不成立。

**已修复**（新建 `gbc_mpc_wbc/wbc_limited.py`，限幅自洽 WLS：利用 `τ` 对 `q̈` 仿射，
一维精确步长求交取 `s_max`，`τ` 由最终 `q̈` 反解 → 永不 clamp；同时补 `outcomes`；
`simulation.py` 补 `feedback.observe()` 并新增 `preview_lead`）。

自检全过：`max|τ − recover_torque(q̈)| = 0.000e+00`、接触残差 2.9e-14、`clip_applied` 0 次、
`outcomes` 8 条（旧为 0）、重复运行逐位一致。**但实测 +1.5~+3.0 m/s 推扰下限幅从未被激活
（`min s` 恒为 1.000），所以 P0-2 是潜伏修复，不改变现有结果**；P0-1 是唯一可观测变化
（`motion_residual` 从恒 0 变为峰 0.364，但未达 `residual_limit=0.50`）。

**参数扫描与部署换档**：`hip_angle_limit` × `position` 二维联合扫描（15 组 8 可行，`artifacts/tuning/grid10`）。
确认**腿角峰恒等于 `hip_angle_limit`**（100.1/125.1/150.1/175.2/200.1，与 `position` 无关）。
用户选定部署：`hip_angle_limit` **0.15 → 0.125**（`position` 仍 40000）——
腿角峰 150→125 mrad（−17%）、位移峰 167→192 mm（+15%）、位移收敛 1.78→1.98 s（+11%）、
俯仰峰 0.845→0.769°。`objective.DEFAULTS`（评价基线）未动。

**用户决定**：不改 `leg_input` 8 状态模型、不做阻尼建模、不考虑 QP。

**新增**：`tools/view.py` 的 `--hip-angle-limit` / `--position-weight`（仅本次运行有效，不改 `TUNED`）。

**验证来源**：headless 扫描 + 自检脚本（自动）；viewer 实测由用户操作（`results/view_test/session_20261005_181646.json.gz`，

### 问题 A：零输入受扰动位移收敛慢

**现象（实测）**：

- 1 kHz 时间线（0.2 m/s 冲量，扰动 t=5.0）：扰动后第一拍 fv 任务残差即
  **49.6/50**（位置环要求 50 m/s² 减速，实际达成约 0.3 m/s²）；
- 实测减速率 **-0.31 m/s²**（0.2 m/s 需约 0.6 s 停下，期间冲出 8 cm）；
- 力矩仅用 7-20%（髋 0.13-0.3 / 轮 0.08-0.8 N·m，限值 10/5）——不是执行力不足；
- persist 工况（40N/3Nm/0.20s）：位移收敛 T_pos=6.30 s。

**根因（探针实验证据链）**：

| 任务组合（快照，目标 fv=-5） | fv 达成 | 髋角加速度 |
|---|---|---|
| fv 单独 | -4.99 | — |
| fv+pitch | -4.99 | **308 rad/s²** |
| fv+reg（权重 1） | -3.58 | — |
| fv+pitch+reg | **-0.94** | 2.6 |

- QP 的最优减速解需要髋关节 **308 rad/s²** 的角加速度（用腿部反作用产生减速力，
  髋力矩只需 1.5-2.1 N·m）；
- `regularization`（髋零目标，权重仅 1）以平方代价 1×308²≈95k 压过 fv 收益
  50×25≈1.25k——**权重 1 的任务可压死权重 50 的任务**（代价平方放大）；
- 放松 reg 权重至 0.001 单步可释放减速（-4.56），但闭环崩溃——**308 rad/s²
  在真实动力学里不可执行**。

**构型耦合（物理层面，非猜测）**：

- 髋轴与俯仰轴共线（代码/文档）：髋力矩直接作用于机身俯仰；
- 轮地切向力（减速力）的反作用力矩直接进机身俯仰；
- 历史实测：“力到俯仰角速度的耦合系数是速度通道的 50 倍”——纵向加速度
  的物理权限主要在俯仰通道；
- 结论：减速的动力学路径必然经过“俯仰/髋”通道；QP 找到的高速髋摆动解
  不可执行，可执行的路径是“姿态缓慢倾斜配合”——需要时间。
- 方案验证（全部实测否定）：pitch 规划（目标 -2~+2 → fv 恒定 -1.0）、
  髋规划（目标 -100~+100 → fv 恒定 -1.03）、力跟踪（单步 -3.9 / 闭环姿态 45° 失控）、
  摆腿前馈（正负对称恶化，曲柄质心权限不足）。

1. 静止状态探针（只给 fv 任务）：纵向加速度可达 **-10~-26 m/s²**

## 2026-09-25：QP 求解重写（接触一致性硬约束）与算法验证

用户决定：不再与零空间法对比，直接重写 QP 求解；摩擦锥约束先删除，效果不好再加回。
本阶段完成重写与算法级验证，未做 QP 版 MuJoCo 闭环验证。

### 根因推理（代码证据）

- 零空间法（`SaturationResolver`）把 `Jc qacc + bias = 0` 作为硬约束联立动力学求解，
  解始终在接触流形上。
- 旧雏形 `TaskQpResolver` 的接触力 `f` 是完全自由的决策变量（`contact_bias` 只用于诊断），
  QP 可以随意组合 `f` 与 `tau` 来"满足"任务——模型内自洽（动力学残差 3.4e-07），
  真实物理不可实现（力矩未打满 2.4/5.0、pitch 权重 33 倍无效、姿态失控 0.78 rad）。
- 结论："任务定义与决策变量的对映"问题 = 缺接触一致性约束。

### 重写内容（`Algorithm/wbc/task_qp.py`）

- 硬约束四类：浮动基座动力学等式、**接触一致性等式
  `Jc qacc + contact_bias = 0`（新增核心）**、执行器力矩上下限、接触力法向非负。
- 摩擦锥删除（用户 2026-09-22 决定）；法向非负保留。
- 任务全部为代价项软目标（加权最小二乘），按权重竞争、不会被清零。
- 两级不可行兜底：一级不可行 → 去掉接触等式重解 → 仍不可行 → 零力矩 +
  `fallback_used=True`，每级记日志，不静默失败。
- 诊断修复：`HierarchyResult.outcomes` 逐任务填入真实 `achieved/residual`，
  反馈层可读残差；`scaling` 统一填 1.0（QP 无逐级缩放语义）。

## 2026-09-22：WBC 换单级 QP（新增 task_qp）与任务权重扫描

背景：用户 viewer 实测后判定 MPC 参数迭代无效，提出瓶颈在 WBC——力矩发挥不出来。
诊断证实了这一点。

### 诊断证据（零空间法，前向 0.10 m/s 冲量）

- `max |torque| = 0.380 N*m`，URDF 轮限值 5.0，**仅用 7.6%**。
- `forward_velocity` 的 `scaling` 全程为 0（零空间耗尽）；`roll` / `height` 也恒为 0（死点排程关闭）。
- 扰动前后 scaling 完全不变，即“制动”这件事根本没被下达。

### 新增文件 `Algorithm/wbc/task_qp.py`

单级 QP，决策变量 `z = [qacc (10), f (5), tau (4)]`（共 19 维），osqp 求解：

- 任务全部作为**代价项**（软目标，按权重竞争，不再有“耗尽”）；
- 硬约束：浮动基座动力学等式、力矩上下限（髀 ±10 / 轮 ±5）、法向非负、
  摩擦锥（接触力排列为 `[切向, 法向, 切向, 法向, 共模]`）。
- 接口与 `SaturationResolver` 一致，可运行时替换。

### 实测结果

1. **力矩确实用起来了**：`max |torque| = 2.24 ~ 2.60 N*m`（限值 5.0），
   比零空间法高约 6 倍。动力学残差 3.4e-07。所以“QP 能出力”已证。
2. **但姿态失控**：`maxpitch ≈ 0.78 rad`，撞 45° 的 `attitude_guard` 停机；
   同时位置也回不到原点（`end_pos` 达 ±0.2 m）。
3. **任务权重对姿态无效**：`pitch_w` 从 3 提到 100（33 倍），姿态峰值不变
   （0.7836 → 0.7832），而且力矩并未打满（2.4 vs 限值 5.0）。
   说明问题不在权重，而在任务定义与决策变量的对映。

## 2026-09-22：WBC 分配方法与速度目标对照（结论：WBC 不是瓶颈）

为定位“受扰后减速慢、回归慢”的根因，做了三组对照。结论是 WBC 层不是限制。

- 新增 `Algorithm/wbc/weighted.py`：加权整体最小二乘（WLS）WBC，与 `SaturationResolver` 同接口；所有任务在接触/动力学硬约束的零空间里按权重同时分配，不会出现低优先级任务被清零。
- `APP/mujoco_mpc_wbc.py`：`forward_velocity` 任务改为直接跟踪指令速度（`self.command.velocity`），不再使用 MPC 轨迹的当前节点；新增 `self.command` 保存最近一次 MPC 周期的指令。
- 三组对照（前向 0.10 m/s 冲量，10 s）：零空间+旧目标、WLS+旧目标、WLS+新目标，实际减速度均为 -0.055 m/s²、姿态峰值 0.081、回归 4.40 s，**三者无差异**。
- 原因：`pitch` 与 `forward_velocity` 在物理上争同一自由度——这台机器人减速必须靠俯仰（力到俯仰角速度的耦合系数是速度通道的 50 倍），而 `pitch` 任务要求保持竖直。因此只要 MPC 不规划“为减速而俯仰”，WBC 无论怎么分配都不会减速。
- 实测尺寸：`nv=10`，接触约束秩 5（零空间 5 维），执行器 4 个，而任务需求 7 维（pitch 1 + 髋 2 + roll 1 + yaw 1 + height 1 + forward_velocity 1），所以严格优先级下低优先级任务必然耗尽。
- `scaling=0` 的语义澄清：`NullSpaceHierarchy` 在 `exhausted` 分支不调用 `limiter.scale()`，所以该值表示“未参与求解”，不是“算出来是 0”。此前误读为“被缩放为 0”。
- 工作点：机器人站在 `hip=0` 死点，`roll` 与 `height` 的激活因子为 0（`schedule.py` 的 `|sin q|` 排程），这两级实际关闭。这是 §1.4 已知的“横滚最差工作点”。

上述改动未采纳为默认：`weighted.py` 仅作对照保留；`forward_velocity` 的目标源改动保留待评估。

| 阻尼与优先级分离 | 阻尼高优先级任务的记录达成量为 0.9901，低级叠加后最终达成量变成 1.9703 | 阻尼仅用于本级增益；剩余空间采用质量加权 SVD 基；诊断从最终解重算 |
| 饱和分配 | 高级目标 1、独立低级目标 100、执行器限值均为 1，原全局缩放得到 `[0.01,1]` | 逐级缩放纠正增量得到 `[1,1]`，保留已达到的高级输出；每次 resolve 两次层级调用 |
| 降级输出一致性 | 旧路径裁剪力矩后返回的 qacc 未同步变化 | 最小加速度基线超限时退出任务跟踪，用实际有界力矩正向计算 qacc，并标记 fallback；不宣称最优 SNS |
| 任务退出与归因 | activation=0 仍占权限；耗尽级无增量槽位导致预算下标越界 | activation 缩放本级纠正增量，零值释放；每级固定归因槽位。部分激活跨零的秩切换仍不保证力矩连续 |
| 接触分解 | SVD 的 U 与 QR 的 R 混用，最小反例重构误差 0.531843；按行数截取漏掉实际降秩 | 同一 SVD 的基和坐标，按实际秩分解；回代允许冗余接触行 |
| 缩放区间交集 | 两执行器分别要求 s∈[0.8,1]、[0,0.2]，原函数返回 0.2 | 累积上下界并检查交集为空 |
| 多频率联调 | MPC 和 WBC 原来均为 50 Hz，1 kHz 仅积分物理 | 新增 `ControlTiming`，解析联调 MPC 50 Hz、WBC 250 Hz、物理 1 kHz；每次 WBC 读取最新状态并采样优化轨迹 |
| 解析测试对象修正 | 速度扰动投影改变指定状态值，使 A 不满足位置导数=速度；重复接触函数覆盖正确定义；轮质量错误放在旋转轮缘点 | 约束同时固定指定速度；保留几何切点；轮质量放回轮心；轮相位不再改变质量矩阵与重力项 |

`scaling` 的新语义是本级纠正增量比例，不是用户速度实现比例。权限耗尽的正则任务不再虚报完成。
当前饱和分配保守地沿本级方向缩放，不搜索全部执行器冗余方向中的最大任务缩放，不宣称完整最优 SNS。
Hermite 插值保证位置、速度和加速度的微分一致性，但区间内部未额外验证全部 MPC 约束。

### 2 回退前的实现

**六相状态机**（`gbc_mpc_wbc/jump.py`，纯计算、不持有模型）：
`IDLE -> PREPARE（压缩） -> THRUST（蹬伸） -> FLIGHT（腾空） -> LANDING（着陆） -> RECOVER（恢复）`，
异常走 `ABORT`。接口为 `JumpParams` / `JumpObservation` / `JumpCommand` / `JumpController`。

**蹬伸前馈反解**（`solve_thrust_feedforward`）：按目标弹道高度反解恒定蹬伸力

```
speed = sqrt(2*g*target_apex)            # 目标离地速度
work  = 0.5*m*speed^2 + m*g*com_rise     # 需要的总功（动能 + 重力势能）
force = work / stroke                    # 恒定蹬伸力
torque_peak = max |J^T @ [force, 0]|     # 单关节力矩峰值，用于可行性判定
```

把 `force` 当作**沿腿轴**的作用力，用腿的闭链雅可比转成四关节力矩：`tau = J^T @ [force, 0]`。
腿力矩另行限幅（`leg_torque_limit`），轮力矩按俯仰 PD 出（`_clip_wheel`）。

**腿长网格 + 能力表调度**：`L=0.14~0.42` 取 8 点，每点单独烘焙能力表与降阶模型参数，
MPC 每次求解前按**实测腿长**换挡重建。

**WBC 建模跳跃力**（`JumpForceHolder`）：工厂每次 WBC 调用都新建 resolver，因此这份力
必须由 simulation 持有、每拍写入，经 `limited` 后端的 `external_force` 通道进入动力学
`M qdd + h = S^T tau + J^T f + tau_jump`。**只施加不建模，WBC 会去对抗它**（实测：轮力矩需求
被推到 11.83 N.m，超过 ±6 限幅，`maximum_scale` 归零，全部任务塌成 0）。

**力矩合并语义**：jump 接管（`override_balance=True`，即蹬伸段与腾空段）时**整向量覆盖**
WBC 力矩；未接管（压缩段）时完全由 WBC 执行，jump 只提供腿长目标。

**蹬伸段逐拍核对**（`t` 为仿真时间，`w_gap` 为轮地最小间隙）：

### 4 过程中定位到的 bug 与教训

| # | 现象 | 根因 | 教训 |
|---|---|---|---|
| 1 | 机体没有向上加速度，"单纯变成变腿长"，轮子反向发力 8.3 N.m | 把"jump 接管时覆盖 WBC 力矩"改成整向量叠加，于是 WBC 腿长任务自带的速度阻尼项 `kd_h*Ldot`（`wbc.py:211`）把 209 N 蹬伸力抵消成约七分之一 | 力矩合并是**语义**问题：覆盖与叠加等效于两套完全不同的控制器 |

| 5 | 符号约定教训 | 同一个"轮力矩对俯仰的作用"在地面（经地面反力撬动）与空中（直接反作用）机理不同、符号相反 | 已按接触状态拆成 `WHEEL_PITCH_SIGN_GROUNDED=-1` / `WHEEL_PITCH_SIGN_AIR=+1`；符合全局规则第 15 节 |
