文档用途：提供给测试agent-ds执行
更新时间：2026-10-09

一、文档分工

1. agent交互文档_WBC跳跃重规划.txt
   用途：问题排查agent记录分析结果、证据链和给用户看的方案。

2. agent交互文档_WBC跳跃_测试方案部署.txt
   用途：问题排查agent给测试agent-ds部署测试方案、执行顺序和停止条件。

3. agent交互文档_WBC跳跃_数据与测试结果反馈.txt
   用途：测试agent-ds填写测试配置、原始数据、事件时序、判定和失败证据。

测试agent-ds只读取本文件获取任务，只向“数据与测试结果反馈”文件写入结果，不修改分析结果文件。

二、总原则

1. 当前任务是定位跳跃失败根因，不是调参和优化性能。
2. 未经用户明确批准，禁止修改增益、权重、阈值、限幅、时间常数、滤波器、模型参数、MPC腿长拟合和WBC后端。
3. 每次测试只能改变本阶段明确批准的单一诊断对象，不能同时改变MPC、WBC、状态机和接触检测。
4. 测试前必须完成语法/导入、字段口径、单工况冒烟和同输入重复性自检。
5. 测试结果失败时如实反馈，不通过扩大力值或放宽判据掩盖失败。
6. 禁止使用print、printf、console.log等裸调试输出，使用分级日志。
7. 测试agent-ds不负责修复算法，只负责按本文件部署和反馈证据。

三、当前已知根因线索

1. V4中tau_jump确实进入最终data.ctrl，但WBC原始输出反向抵消tau_jump，最终总力矩接近站立力矩。
2. V4删除了腿长任务，却没有增加质心竖直运动任务，因此WBC没有明确的压缩运动目标。
3. 旧Q1-B中轮子几何上先离地，质心仍在下降；THRUST尚未实际执行就进入FLIGHT，随后因陈旧接触状态进入LANDING。
4. WBC预测接触力是基于假定接触拓扑求出的模型量，不能单独作为离地真值。
5. 正负Fz符号测试只证明映射方向，不等于负力可以作为有效压缩控制。

四、测试总顺序

必须按照以下顺序执行，不得跳过前一阶段直接部署完整跳跃：

E0：已有结果和工作树复核
E1：质心Jacobian和质心任务接口自检
E2：固定接触下WBC质心竖直任务响应
E3：只验证压缩与制动，不验证完整飞行
E4：释放命令与离地交接
E5：着地恢复和MPC重新锚定

如果某阶段失败，停止后续阶段，在反馈文件中写明失败原因和下一步请求。

五、E0：已有结果复核

目的：确认已有V4/Q1-B证据，不重复运行完整3秒仿真。

必须确认：

- V4结果文件身份、工况和代码版本；
- tau_jump是否进入最终data.ctrl；
- WBC原始力矩是否抵消tau_jump；
- WBC任务列表是否缺少质心竖直任务；
- predicted_normal与normal_forces是否分开记录；
- 旧Q1-B中COMPRESS、THRUST、FLIGHT、LANDING、ABORT和airborne的实际时间。

通过条件：已有证据字段完整、读取口径一致、无需重复全量仿真。

六、E1：质心Jacobian接口自检

本阶段只验证观测和任务接口，不部署完整跳跃，不调参数。

需要核对：

1. 质心位置与现有robot_com()一致。
2. J_com_z乘qvel与实际质心竖直速度一致。
3. J_com_z乘qacc加bias_com_z与有限差分质心加速度一致。
4. 质心子树、质量、世界坐标z轴、单位和符号正确。
5. 重复输入结果逐项一致。
6. 任务维度与WBC nv一致。

失败处理：如果接口口径、单位或有限差分不一致，停止，不进入E2。

七、E2：固定接触下WBC任务响应

目的：验证WBC能否根据质心竖直任务改变总力矩和质心加速度。

对照仅包含两组：

A组：原姿态/腿角/接触任务，不启用质心竖直任务。
B组：相同状态、相同接触、相同所有参数，只启用经过E1验证的质心竖直任务。

必须记录：

- 质心竖直期望加速度和实际加速度；
- qacc；
- 总data.ctrl；
- 左右预测法向力；
- 接触残差；
- 动力学残差；
- WBC任务残差和scaling；
- 是否触发力矩限幅；
- pitch、pitch_rate和腿角变化。

判定：

- B组目标改变且实际质心响应方向一致，说明WBC任务接口有效；
- 任务输入正确但实际响应被约束抵消，报告约束/可实现性问题，不调权重；
- WBC输出改变但质心响应不一致，检查任务Jacobian、bias和符号，不先改参数。

八、E3：压缩与制动

目的：验证压缩阶段是否由WBC质心任务产生受控下压，而不是腿长终点PD或负接触力。

要求：

1. 不使用leg_length_target作为压缩主控制输入。
2. 不叠加tau_jump到WBC最终输出。
3. 不使用负法向力作为压缩命令。
4. 压缩只验证到制动准备，不进入完整FLIGHT。

每个物理步记录：

- t、phase、previous_phase；
- com_xz、com_vxz；
- 左右轮毂位置和速度；
- 左右轮最低点、gap、geometry；
- L_R、L_L、Ldot_R、Ldot_L；
- pitch、pitch_rate；
- predicted_normal_R/L；
- 实际normal_forces_R/L；
- contact_estimator_R/L；
- WBC任务目标/实际值；
- data.ctrl、output_source；
- feasible、scaling、残差和限幅。

通过条件：质心按目标下降，轮毂保持支撑，gap未出现持续离地，腿长按预期变化，pitch不发生失控发散。

失败条件：轮毂先抬升、gap持续为正、质心继续下降、实际接触力归零，或WBC任务不可行。失败后停止E4。

九、E4：释放和离地交接

前提：E1、E2、E3均通过，并获得继续执行批准。

离地候选必须同时检查：

- 当前phase允许离地；
- WBC已经求解并写入当前跳跃参考；
- 至少完成一个物理步；
- 左右几何接触持续消失或左右gap持续为正；
- 实际法向力通过off_force/off_duration；
- WBC预测支撑状态与实际接触状态没有明显冲突。

WBC预测法向力只允许触发UNLOAD_CANDIDATE，不允许单独触发FLIGHT。

必须验证：

- 是否存在THRUST尚未实际写入就进入FLIGHT；
- 是否存在FLIGHT只持续1个物理步就进入LANDING；
- 是否使用陈旧contact_estimator触发LANDING；
- 是否出现airborne_zero覆盖有效输出。

十、E5：着地、恢复和MPC重锚定

前提：E4已确认真实离地和释放有效。

必须记录：

- 首轮几何接触；
- 双轮几何接触；
- 首轮实际法向力恢复；
- 双轮实际法向力恢复；
- contact_estimator变化；
- WBC恢复调用；
- LANDING、RECOVER、GROUND切换；
- MPC重锚定时刻和参考状态；
- pitch、pitch_rate和腿长恢复情况。

不得用单帧any(contact)直接恢复完整控制器。

十一、每阶段停止条件

遇到以下任一情况立即停止当前阶段：

- 工具自检失败；
- 记录字段与真实对象不一致；
- 同输入重复结果不一致且原因未查明；
- 出现NaN/Inf；
- 状态机非法跳转；
- 未经批准的参数或阈值被修改；
- 结果需要调参才能继续解释。

三、必须一次性部署的代码接口

按下面顺序修改，修改完后只做一次编译/导入检查。

1. `control.py::wbc_stage()`：保留`tasks.tasks()`生成的完整任务对象。COMPRESS、COMPRESS_BRAKE、THRUST阶段，仅把`length_R`和`length_L`分别替换为`activation=0.0`；不得改变它们的Jacobian、bias或desired。LANDING、RECOVER恢复原有腿长任务权限。
2. `control.py::wbc_stage()`：跳跃阶段仍使用`desired_com_acceleration_z`生成`com_vertical`；MPC `sample_raw`可以记录为shadow，但不得进入跳跃期WBC任务目标。
3. `wbc.py::Gbc486Tasks.tasks()`：增加可选的跳跃姿态参考策略。支持`current_posture`和`frozen_posture`。冻结策略只在jump开始第一帧捕获pitch、roll、angle_R、angle_L，速度参考设为0，之后COMPRESS、COMPRESS_BRAKE、THRUST不重新捕获。
4. `control.py`：增加诊断策略开关，至少支持`disable_angle_diagnostic`、`disable_attitude_diagnostic`和`com_only_diagnostic`。这些策略只能把对应任务activation设为0，任务对象必须继续出现在trace中；不得删除任务。
5. `control.py`：对每个任务写出`name`、`jacobian`、`desired`、`bias`、`activation`、`achieved`、`residual`、`residual_norm`、`scaling`和`exhausted`。
6. `jump.py::JumpObservation`和`loop.py`：改成独立的`leg_length_R`、`leg_length_rate_R`、`leg_length_L`、`leg_length_rate_L`字段。状态机分别检查R/L机械范围、压缩方向和压缩终点；需要双腿满足时使用R且L条件。
7. `loop.py`：逐帧写出R/L的wheel gap、geometry contact、contact estimator、normal force、predicted normal force。不得以均值或最小值覆盖原始字段。
8. 若上述任一接口无法在当前代码中实现，保留已完成改动，记录文件、行号和错误，继续执行不依赖该接口的静态/快照检查，不得用删除任务或改阈值替代。

问题排查agent：一次部署、一次批量运行的最终执行规则（2026-10-09）

用户已要求取消每轮测试后的等待审批。本节优先级高于本文档中要求“测试一轮后等待问题排查agent批准”的旧文字。测试agent-ds应一次性部署本节全部代码接口和诊断策略，然后一次性运行完整矩阵，全部结果写入反馈文档，最后统一等待问题排查agent分析。

一、一次性部署内容

以下内容必须在同一个工作区、同一个部署批次完成；部署完成后只做一次语法/导入检查，不在每个候选策略之间重新修改代码。

1. WBC任务保留和权限控制

   - `control.py::wbc_stage()`不得再用tuple过滤删除`length_R`、`length_L`、`angle_R`或其他任务。
   - 跳跃COMPRESS、COMPRESS_BRAKE、THRUST阶段保留两条腿长TaskLevel，只将`length_R`、`length_L`各自`activation=0.0`。
   - LANDING、RECOVER阶段恢复腿长任务原有activation和标称腿长恢复参考。
   - COMPRESS/THRUST的主控制输入仍为`desired_com_acceleration_z`，不得使用`leg_length_target`作为压缩/释放输入，不得叠加`tau_jump`。

2. 姿态/腿角参考策略接口

   在不改变默认GROUND逻辑的前提下，为跳跃控制增加可选策略参数，至少支持以下值：

   - `current_posture`：沿用现有pitch、roll、angle_R、angle_L参考逻辑；用于B0。
   - `frozen_posture`：在跳跃开始的第一帧捕获pitch、roll、angle_R、angle_L实际值，捕获后整个COMPRESS、COMPRESS_BRAKE、THRUST阶段保持不变；对应速度参考全部设为0；用于B1。
   - `disable_angle_diagnostic`：保留angle_R、angle_L任务但activation=0；只用于任务归因诊断，不作为最终控制策略。
   - `disable_attitude_diagnostic`：保留pitch、roll任务但activation=0；只用于任务归因诊断，不作为最终控制策略。
   - `com_only_diagnostic`：保留所有任务对象但除com_vertical外均activation=0；只用于求解可行域上限诊断。

   参考策略必须通过任务activation或显式参考参数实现。禁止通过删除任务、交换任务顺序、修改TASK_WEIGHTS或改变com_vertical权重实现。

3. WBC逐任务记录

   对`balance + motion`的每个TaskLevel和`result.hierarchy.outcomes`按任务名一一对应，写出：

   - name、Jacobian、desired、bias、activation；
   - achieved、residual、residual_norm；
   - scaling、exhausted；
   - 所属策略、phase、WBC调用序号；
   - WBC feasible、qacc、dynamics_residual、raw torque、data.ctrl。

   activation=0的任务也必须有完整记录；不能因任务关闭而从日志中消失。

4. 左右腿独立观测和接触记录

   - `JumpObservation`使用`leg_length_R`、`leg_length_rate_R`、`leg_length_L`、`leg_length_rate_L`。
   - `loop.py`直接从`leg_state`和对应Jacobian行分别读取左右腿，不得使用腿长或腿速均值。
   - 状态机分别检查两腿机械范围、压缩方向和压缩终点；需要双腿满足时使用明确的R且L条件。
   - 记录`wheel_gap_R/L`、`geometry_contact_R/L`、`contact_estimator_R/L`、`normal_force_R/L`、`predicted_normal_R/L`。原始字段必须保留，即使状态机最后使用聚合条件。
   - 禁止使用`np.min(gap)`替代双侧gap；禁止用单一均值作为单腿异常判断。

5. 批量运行接口

   建议在现有诊断工具上增加一个批量入口，例如`tools/jump_batch_diagnostic.py`，由一个命令依次运行下列策略。若测试agent-ds使用其他文件名，必须在反馈中说明实际入口和参数，不能改变矩阵内容。

   - `B0_current_posture_length_off`
   - `B1_frozen_posture_length_off`
   - `B2_current_posture_length_on_diagnostic`
   - `B3_disable_angle_diagnostic`
   - `B4_disable_attitude_diagnostic`
   - `B5_com_only_diagnostic`
   - `C0_full_jump_current_posture`
   - `C1_full_jump_frozen_posture`
   - `D0_mpc_shadow_disconnect_check`
   - `E0_actuator_mapping_check`

   每个策略使用相同模型、同一初始状态、同一jump参数、同一外力、同一duration和同一随机种子；输出使用独立文件名，不覆盖此前结果。

二、批量执行顺序和每项职责

1. 先执行A0/A1接口静态检查和JumpPlanner固定输入表。A0/A1失败仍继续生成其他独立诊断，但在汇总中标记“接口不完整”。
2. 执行A2六个WBC快照变体，使用同一个qpos/qvel/contact快照。A2用于区分腿长任务、腿角任务、姿态任务和com_vertical可行域，不可用不同时间帧比较。
3. 执行B0、B1、B2、B3、B4、B5短时压缩仿真。每组只运行一次；发生ABORT时保存首个异常帧前后20帧后继续下一组。
4. 执行C0、C1完整状态机仿真，重点记录COMPRESS到COMPRESS_BRAKE、THRUST和FLIGHT的真实边界。不得因为某组压缩失败而跳过另一组。
5. 执行D0验证跳跃期MPC sample只做shadow；执行E0验证执行器名称、selection、gear、ctrl和qfrc_actuator逐索引对应。

三、一次性批量运行禁止事项

1. 不得在B0失败后修改代码再运行B1；所有策略必须在同一部署版本下运行。
2. 不得将B3、B4、B5的诊断结果直接合并成默认控制器；它们只用于定位任务竞争。
3. 不得把`length_on_diagnostic`结果用于压缩/释放控制；它只回答“开启腿长任务是否改变com_vertical残差”。
4. 不得把`frozen_posture`变成每帧重新捕获；否则无法验证冻结参考。
5. 不得在测试agent-ds侧修改MPC腿长参数、WBC权重、接触阈值、selection、模型、执行器顺序或外力。
6. 不得用视频主观判断替代逐任务残差、左右腿数据和phase时序。

四、统一验收输出

批量结束后只提交一次反馈，按以下顺序写入数据与测试结果反馈文档：

1. 部署版本、git状态、完整批量命令；
2. A0/A1静态和状态机结果；
3. A2六变体逐任务对照表；
4. B0-B5每组首个异常帧、压缩位移、质心位移、相位和WBC任务残差；
5. C0/C1完整phase转移时序和提前切换检查；
6. D0的MPC sample输入/输出差异；
7. E0执行器映射表和逐索引qfrc_actuator核对；
8. 每项PASS、FAIL或NOT_RUN及客观原因；
9. 所有JSON、日志、视频和快照的绝对路径。

本轮完成后测试agent-ds停止，不自行修复、不自行调参、不自行选择“看起来最好”的策略。由问题排查agent根据完整矩阵统一审批下一步修复方案。

问题排查agent：一次性完整测试批次（2026-10-09）

本批次用于在测试窗口关闭前一次性收集定位压缩失败所需的全部证据。测试agent-ds必须按A0、A1、A2、B、C、D、E的顺序执行；每个子项只运行一次。任何子项失败都要保留结果并继续执行同一批次中不依赖该结果的后续子项，禁止自行调参、重复运行、删除任务或改变测试顺序。

一、统一前提

1. 先部署上一节规定的接口修复：保留length_R/length_L任务、跳跃压缩和释放阶段分别将两条腿长任务activation设为0、补齐逐任务残差、JumpObservation改为左右腿独立字段。
2. 不修改MPC参数、MPC腿长拟合参数、WBC权重、com_vertical目标值、wheel actuator selection、接触阈值、MuJoCo模型、执行器顺序、外部力方式和关节限幅。
3. 跳跃压缩目标固定为desired_com_acceleration_z=-4.905 m/s^2；COMPRESS_BRAKE目标保持当前代码定义；本批次不讨论飞行高度优化。
4. 所有测试记录git commit、工作区变更摘要、model_variant、preset、backend、nominal_length、jump_height、jump_stroke、jump_time、duration、timestep和完整命令。
5. 每次仿真必须记录原始左右腿字段，禁止只记录平均腿长、平均腿速、最小gap或合并法向力。

二、A0：代码边界和接口静态验收

只做一次，不启动长时仿真。

1. 编译/导入control.py、wbc.py、jump.py、loop.py、simulation.py和诊断工具。
2. 静态确认control.py不再通过任务名删除length_R、length_L、angle_R或angle_L；允许用replace(task, activation=0.0)保留任务对象。
3. 静态确认JumpObservation不再只有单个leg_length和leg_length_rate；必须有R/L四个独立字段。
4. 静态确认状态切换代码没有使用0.5*(R+L)、np.mean、np.min后的单值来判断压缩方向、压缩终点或单侧离地。
5. 静态确认wbc_task_trace对每个任务都有desired、achieved、residual、activation、scaling、exhausted字段。
6. 若A0失败，记录具体文件、行号和缺失字段；继续执行A1和B的纯接口诊断，但不得运行C/D/E并宣称结果可用于定位。

三、A1：JumpPlanner左右腿独立状态机单元检查

不运行MuJoCo长仿真，直接使用固定JumpObservation表驱动JumpPlanner。每个表项一次，记录输入、上一状态、输出状态、原因。

1. 两腿均在压缩：R/L腿长均大于compression_end，R/L腿速均为负，输出必须保持COMPRESS或按现有制动规则进入COMPRESS_BRAKE。
2. 右腿停止压缩、左腿继续压缩：右腿速为0或正，输出必须报告右腿方向异常；不得用均值继续COMPRESS。
3. 左腿停止压缩、右腿继续压缩：对称验证，必须报告左腿方向异常。
4. 两腿均到达压缩终点且两腿速度均满足释放条件：只允许按合法前态进入THRUST，不得跳过COMPRESS_BRAKE（若当前状态机要求先制动）。
5. COMPRESS状态输入人为设置两腿gap一正一负：不能只凭gap最小值判断整体离地，必须保留R/L gap和几何接触原值；状态输出要说明使用的双腿条件。
6. FLIGHT输入仅一侧接触：不得进入LANDING；两侧几何接触和接触估计都恢复后才允许进入LANDING。
7. 检查所有非法跳转：IDLE不能直接进入THRUST/FLIGHT，COMPRESS不能直接进入FLIGHT，ABORT必须保持ABORT。
8. A1只验证状态流和独立字段，不修改状态阈值，不把异常改成警告继续运行。

四、A2：WBC任务接口和逐任务诊断验收

使用同一保存的仿真状态快照，固定contact、qpos、qvel、mass、selection和dynamics_bias，分别调用一次WBC求解。所有变体必须使用同一个快照，不能用不同时间帧比较。

变体如下，所有任务对象都保留，只改变activation或参考值：

1. A2-BASE：所有原有任务activation=1，加入com_vertical=-4.905。
2. A2-LENGTH-OFF：仅length_R和length_L设activation=0，其他任务和目标与BASE完全相同。这是跳跃正式接口候选。
3. A2-ANGLE-OFF：在A2-LENGTH-OFF基础上仅将angle_R和angle_L activation=0，作为冲突定位对照，不得把该变体直接作为正式修复。
4. A2-ATTITUDE-OFF：在A2-LENGTH-OFF基础上仅将pitch和roll activation=0，作为冲突定位对照。
5. A2-FROZEN：在A2-LENGTH-OFF基础上，pitch、roll、angle_R、angle_L仍保留activation=1，但将其参考冻结为跳跃开始快照的实际姿态/腿角和零速度；不改变WBC权重。
6. A2-COM-ONLY：只作为诊断上限，在同一快照保留接触和动力学硬约束，其他软任务全部activation=0；不得作为最终控制方案。

每个变体必须输出：任务名全集、每任务Jacobian行、desired、bias、activation、achieved、residual、residual_norm、scaling、exhausted、qacc、WBC torque、predicted normal force R/L、dynamics residual、actuator saturation和feasible。

A2判定：

1. 若A2-LENGTH-OFF相对A2-BASE显著降低com_vertical残差，说明原腿长任务确实竞争；正式代码必须采用保留任务并activation=0，不能删除任务。
2. 若A2-ANGLE-OFF显著改善而A2-LENGTH-OFF无改善，说明腿角任务是当前主要竞争候选；只能报告证据，暂不直接删除腿角任务。
3. 若A2-ATTITUDE-OFF显著改善，说明姿态任务对压缩方向有执行器投影；下一步使用A2-FROZEN判断是姿态误差追踪还是姿态Jacobian本身造成竞争。
4. 若A2-FROZEN改善，正式修复方向是阶段参考冻结；若不改善而A2-COM-ONLY改善，说明任务空间仍有冲突，需要由问题排查agent复查优先级/可行域。
5. 若所有变体的com_vertical achieved都接近同一非目标值，不能继续归因于任务冲突，必须报告com_vertical Jacobian、接触约束或执行器可行域证据。
6. A2中feasible=True不能作为任务成功判定。

五、B：同一初始状态的跳跃短时仿真对照

每个场景只运行一次，duration=2.0 s或现有诊断工具支持的最短完整窗口，jump_time、jump_height、jump_stroke和外部力完全一致。不要在B阶段改变MPC或接触参数。

1. B0：正式候选接口，MPC sample在跳跃期间不进入WBC；length_R/L保留但activation=0；姿态/腿角使用当前参考。
2. B1：与B0唯一差异为姿态/腿角参考冻结到jump开始快照；length_R/L仍activation=0。
3. B2：与B0唯一差异为保留length_R/L activation=1，作为腿长任务竞争对照；禁止用它作为正式控制结果。
4. B3：与B0唯一差异为WBC逐任务诊断变体中已证明最相关的单个任务activation=0；若A2没有明确赢家则不执行B3，报告“无唯一任务归因”。
5. 每个场景必须保留完整COMPRESS过程；若出现ABORT，记录ABORT前至少20帧和首次异常帧，不能只保留汇总值。

B每帧必须记录：

- phase、previous_phase、phase_transition、abort_reason；
- jump.active、disconnect、airborne_active、mpc_called、wbc_called、output_source；
- sample_raw是否存在、sample是否消费MPC、desired_com_acceleration_z；
- pitch、pitch_rate、roll、roll_rate、com_xz、com_vxz；
- leg_length_R/L、leg_rate_R/L、compression_progress_R/L；
- wheel_gap_R/L、geometry_contact_R/L、contact_estimator_R/L、normal_force_R/L、predicted_normal_R/L；
- wbc_task_trace中pitch、roll、angle_R、angle_L、length_R、length_L、com_vertical的desired/achieved/residual/activation/scaling/exhausted；
- wbc_raw_torque、data.ctrl、tau_jump、qacc、dynamics_residual、feasible、torque saturation。

B验收只回答压缩阶段：

1. 双腿是否持续接触；
2. 质心是否持续下降；
3. 两腿是否持续缩短且没有一侧先反向；
4. com_vertical残差何时首次转正；
5. pitch/roll/角度任务是否在异常帧产生非零主动目标；
6. data.ctrl是否等于WBC原始力矩；
7. 是否发生状态机错误跳转或错误airborne_active。

六、C：完整状态机和释放边界

只有B数据完整时执行；仍然每个场景一次。

1. C0：使用B0正式候选接口运行完整jump，不设置compression_only；必须记录COMPRESS、COMPRESS_BRAKE、THRUST、FLIGHT、LANDING的实际转移时间。
2. C1：使用B1冻结参考接口运行完整jump，其他变量不变。
3. 在COMPRESS未完成前如果出现airborne_active、FLIGHT或THRUST，立即标记“提前切换”，记录前后20帧的左右gap、左右法向力、相位、decision.contact和WBC输出。
4. THRUST只有在前态为COMPRESS_BRAKE、两腿达到释放条件、WBC已求解并且WBC力矩已写入data.ctrl后，才算真实执行；不能只看JumpCommand生成。
5. FLIGHT必须由左右独立接触/间隙证据确认；不能由腿长达到release_end单独触发。
6. 如果C0/C1均在压缩阶段失败，停止后续飞行优化，问题排查agent根据A2/B数据定位；测试agent-ds不得继续调释放参数。

七、D：MPC旁路和泄漏检查

不改变MPC参数，只验证跳跃期是否真正解耦。

1. 对B0第一次跳跃WBC帧，同时保存sample_raw和传入tasks.tasks的sample标识。
2. 用同一qpos/qvel和WBC输入分别构造sample=None、sample=sample_raw两次任务，比较jump阶段最终任务目标和WBC力矩；正式路径必须使用sample=None或明确冻结参考，不能使用sample_raw。
3. 记录MPC的state、acceleration、force、fallback、relaxed，但只能作为shadow；若sample_raw异常而WBC正式输入和输出不变，说明MPC不是该阶段直接原因。
4. 普通GROUND帧必须保持原行为，sample仍可为sample_raw；本项不能把GROUND也切断。

八、E：执行器映射和符号一次性复核

这是排除“正确WBC力矩写到错误电机”的最小检查，不修改执行器顺序。

1. 读取当前selection、actuator name、joint name、gear、ctrlrange和leg_actuators顺序，保存为映射表。
2. 在同一静态状态分别对每个腿执行器施加单独单位测试输入，记录对应joint qfrc_actuator/广义力变化，只允许一个执行器非零。
3. 分别检查右前、右后、左前、左后四个执行器的符号；检查wheel actuator在jump selection被清零后是否仍有非零WBC torque。
4. 对比WBC raw torque向量、data.ctrl向量和MuJoCo实际qfrc_actuator；必须逐索引一致，不能只看力矩范数。
5. 若映射错误，停止C的物理结论，先报告映射表和首个错误索引；不得通过改符号或交换执行器数组临时修复。

九、最终一次性反馈格式

测试agent-ds只需在反馈文档填入以下顺序，不要写主观结论替代数据：

1. A0静态结果；
2. A1状态机表和非法跳转结果；
3. A2六个WBC变体对照表；
4. B0/B1/B2/B3每组首个异常帧和汇总；
5. C0/C1状态转移时序；
6. D的sample解耦结果；
7. E的执行器映射表；

FL7：消除 THRUST→FLIGHT 手接处的腿力矩阶跃（方案 A，问题排查agent，2026-10-09）

一、根因（有证据，不是推断）

FL6 run01 逐帧数据：

  t=1.424  THRUST  out=wbc_update          L=0.2807 phi=-0.1242  ctrl=[-23.7,+24.0,...]
  t=1.425  FLIGHT  out=flight_leg_profile L=0.2830 phi=-0.1241  ctrl=[+36.0,-36.0,...]  <- 1 ms 内反向步进 ~60 N·m
  t=1.430  FLIGHT  out=flight_leg_profile L=0.2913 phi=-0.1224  dphi/dt=+0.19
  t=1.440  FLIGHT  out=flight_leg_profile L=0.2954 phi=-0.1126  dphi/dt=+0.98
  t=1.450  FLIGHT  out=flight_leg_profile L=0.2911 phi=-0.1007  dphi/dt=+1.19

推理链：
1. 压缩/制动/推进全程（1.0~1.424）phi 恒为 -0.1263，dphi/dt 仅 0.001~0.03 rad/s。起跳前 phi 状态是干净的。
2. t=1.425 相位切换，腿力矩 1 ms 内从 -23.7 跳到 +36.0 N·m（撞上 clamp）。
3. 此时腿仍在惯性伸长（L 从 0.283 继续升到 0.2955）。
4. 该力矩阶跃经双连杆质量矩阵耦合（M_L,phi != 0）打进 phi，20 ms 内 dphi/dt 从 0.03 冲到 1.19 rad/s。
   自由飞行无外力矩，之后积分到落地 +0.6 rad。
5. FL6 的 phi PD（kp=7/kd=1.1）此时力矩约 1.3 N·m，压不住 36 N·m 的驱动。

阶跃的数值来源（control.py::_pd_force）：
  F_L = KP*(l_ref - L) - KD*L_dot
进入飞行时 l_ref 用 `base - RATE*dt` 初始化，P 项约 0，但 D 项直接用实测腿速：
  -KD * (+1.3 m/s) = -150*1.3 = -195 N  -> torque 直接顶 clamp 36 N·m。

结论：问题不是 phi 参考值错，也不是起跳段把 phi 摆歪，而是**飞行剖面在第一步对一条仍在伸长的腿施加满额收腿力矩**。

二、本轮改动（方案 A：把手接处从阶跃改为连续）

只改 `control.py::flight_leg_profile_torque` 与其在 `loop.py` 的状态变量，不动任何增益/限幅。

1. 剖面状态由一个标量 `retract_reference` 改为二元组 `(L_ref, v_ref)`（参考腿长、参考腿速），
   `loop.py` 里的 `flight_leg_ref` 相应改存二元组。
2. **进入上升段时捕获实测状态**：`L_ref = L_entry`（取两腿中较大者），
   `v_ref = L_dot_entry`（对应腿的实测腿速）。因此手接第一步：
   `F_L = KP*(L_ref-L) + KD*(v_ref-L_dot) = 0`，腿力矩不再跳变。
   捕获时刻：状态为空（首次进飞行），或由上一步的下落段重新进入上升段。
3. 上升段每步：`v_ref` 以加速度上限 `FLIGHT_RETRACT_REF_ACCEL` 向 `-FLIGHT_RETRACT_RATE_LIMIT` 收敛；
   `L_ref += v_ref*dt`，再 clip 到 `[leg_length_min+MARGIN, leg_length_max]`，
   **并且不得上穿入口腿长 `L_entry`（`L_ref = min(L_ref, L_entry)`）**。
   依据（离线复算，见三.2）：不加这条挡位时，参考腿速从入口的 +2.25 m/s 慢慢降，
   参考本身会先继续伸长约 0.14 s，腿被带到 0.4336 m（顶到上限），收腿窗口被吃掉。
4. 腿长力改为“参考速度误差”形式：`F_L = KP*(L_ref - L) + KD*(v_ref - L_dot)`。
   下落段取 `L_ref = nominal`、`v_ref = 0`，即退化为原来的 `KP*(nominal-L) - KD*L_dot`，行为不变。
5. 力矩 clamp、收腿下限、phi PD（F_phi）、落地缓冲、其余全部不变。

三、`FLIGHT_RETRACT_REF_ACCEL` 的依据（不引入新魔术数）

在捕获时刻由实测值导出，作为一次性的定值参与后续斜坡：

  FLIGHT_RETRACT_REF_ACCEL = (|v_ref_entry| + FLIGHT_RETRACT_RATE_LIMIT) / max(v_z_entry / g, eps)

含义：让参考腿速在**弹道到达顶点前**从进入值完成到收腿速率上限的建立。
v_z_entry 取捕获时刻的机体竖直速度（已有入参 `vertical_velocity` 可用），g 取 `jump.GRAVITY`。
典型值：v_z=1.4 m/s -> t_apex=0.143 s，(1.3+1.5)/0.143 = 19.6 m/s²。
不做成写死的 20，因为 v_z 与 v_ref_entry 每次不同；同样不做成无限陡（否则退化为阶跃）。

FL11：修正世界系腿摆角变换的符号错误（问题排查agent，2026-10-09）

一、根因（几何实证，不是推断）

FL10 部署的换算式 `phi_world = phi_body + pitch` 符号错了。实测：

  设 base 纯俯仰四元数 [cos(θ/2),0,sin(θ/2),0]，保持腿关节不变，mj_forward 后
  用 `data.xpos` 直接量取髋体→轮体的世界向量，取 `atan2(rx, -rz)`：

  θ(base pitch)   euler_pitch   phi_body  几何实测世界系腿角   几何-phi
   +0.00            +0.0000      -0.1263    -0.1263            0.0000
   +0.10            +0.1000      -0.1263    -0.2263           -0.1000
   +0.20            +0.2000      -0.1263    -0.3263           -0.2000

  故正确换算式为：

    phi_world = phi_body - pitch     =>     phi_body_ref = PHI_WORLD_REFERENCE + pitch

FL10 用了 `phi_body_ref = PHI_WORLD_REFERENCE - pitch`。落地时 pitch=-0.2694，
FL10 的参考= -0.1263-(-0.2694)=**+0.143**，控制器把 phi 往前推到 +0.144；
按正确口径换算到世界系应为 -0.1263 的位置，实际却是 +0.144-(-0.27)=**+0.41**。
即：**控制器主动把腿向世界系前方多摆了 0.41 rad**，落地必然是前斜腿。

FL12：腿摆角耦合前馈（力 + 角度）+ 新增益（问题排查agent，2026-10-09）

一、背景：FL11 的失败与离线辨识

FL11 实测：世界系角度从 -0.122 一路被推到 +0.27，落地世界系误差 0.341 rad；
FLIGHT 段 max|pitch| 反而从 FL10 的 0.2690 涨到 0.4250。
归因：不是增益小，是**扰动大**。FL11 落地时误差 0.341 rad，而 PD 只给出 7*0.341=2.4 N·m，
而腿长通道的耦合力矩约 22 N·m（约 9 倍）。

离线辨识（自由飞行、无接触，工作空间法 + 直接加速度法交叉核对，髋体→轮体解析链）：

  L目标   phi静平衡   m_eff_L   Lambda_phi   c=|a10|/a11
  0.140   -0.2620    0.306     0.01332      0.1577
  0.160   -0.2349    0.316     0.01670      0.1625
  0.200   -0.1899    0.357     0.02315      0.1603
  0.240   -0.1547    0.408     0.02875      0.1536
  0.280   -0.1263    0.465     0.03319      0.1472
  0.310   -0.1080    0.509     0.03551      0.1433
  0.330   -0.0968    0.540     0.03641      0.1412

定义：`[Ldd; phidd] = A [F_L; F_phi]`，A00=1/m_eff_L，A11=1/Lambda_phi，
A01=A10 为耦合。前馈系数 c = |A10|/A11（每 1 N 腿长力需要多少 N·m phi 力矩抵消反应）。

结论：
1. `c` 在 L=0.14~0.33 全段只变化 0.141~0.163（±7%）→ **可用常数 c=0.15**。
2. `Lambda_phi` 变化 0.0133~0.0364（2.7 倍），在设计点上取标称值 0.0332。
3. `phi_eq(L)`（静平衡摆角）斜率 ≈ **0.97 rad/m**——腿一收，静平衡摆角就变，
   这是“角度前馈”的物理来源，可由 `standing_pose` 离线算出（同一条曲线）。

二、本轮改动（三项，仅飞行段）

1. **力前馈**（`control.py`，仅`vz<0`的下落段、即现有 `F_phi` 生效的同范围）：

     F_phi += FEEDFORWARD_COUPLING * F_L      FEEDFORWARD_COUPLING = 【待自检测定，批准前不填】

   **不得使用任何离线值。**排查agent最初的 0.15 是用“单腿施力”口径测的，与控制器
   “两腿对称施力”口径不一致；测试agent算出的 -0.056（对称）/ -0.09（单腿）与之也不吻合；
   排查agent按对称口径重测（F_L=100 N、F_phi=0 时 phidd_R=-1149 rad/s^2）得出 |c|>0.2、
   超出扫描区间。三者互不吻合，故 c 的**数值与符号都必须实测**。
   测定后把数值与符号一并写入代码常量，并在反馈报告里写明实测过程与交叉点。
   注释里必须写清：实测口径（两腿同时、共模 phidd）、实测位形、交叉点。
2. **新增益**（用户 2026-10-09 批准同时使用）：

     KP_PHI = 20.9 N*m/rad     （原 7.0）

   依据：`kp = Lambda_phi*omega^2`、`kd = 2*zeta*Lambda_phi*omega`，Lambda_phi=0.0332（一、实测），
   omega = 2*pi*4 = 25.1 rad/s（4 Hz）、zeta = 1.0。4 Hz 远低于腿长 PD 的约 9 Hz，不与腿长通道抢带宽。

FL15：释放段前馈路线（摆腿前馈 / ZMP 参考 / pitch 速率前馈）——分阶段（问题排查agent，2026-10-10）

一、需求与约束（用户 2026-10-10）

候选手段：
  a) 排查起跳时（离地瞬间）腿摆角/摆角速度产生的根源；
  b) 摆腿（phi）前馈；
  c) ZMP 参考规划；
  d) pitch 前馈（预倾）。

**硬约束（用户明确）**：
1. **只在释放过程（THRUST）部署**；压缩过程禁止——在压缩预倾会被释放段反作用抵消，
   且会改变整体姿态、与控制器干涉。
2. 前馈目标是“**提前校正**”，不是飞行中回授（外环已废弃）。

二、关键物理判断（本方案的出发点）

1. **飞行段的角动量在离地瞬间就定下了**。释放段结束时离地，之后无外力矩。

2. 释放段很短（约 0.11 s），**摆“角度”靠不住**（用户已实测到这一点），
   但**摆“角速度/角动量”靠得住**：角速度在离地后守恒，不会被释放段本身抵消。
   → 本方案主打 **速率级前馈**，不是角度级。
3. phi 与 pitch 是同一自由度的两个目标（世界系腿角 = phi_body - pitch）。
   释放段地面反力可以同时改变两者的速率，所以适合在此处做**联合预置**。

FL16：释放段摆角前馈改走 external_force（修复 B2 结构问题）（问题排查agent，2026-10-10）

一、根因（查实，不是推断）

B2 实现（`control.py:418-433`）是在 `solve_wbc` **之后**把 phi 力矩硬加到总力矩：
WBC 求解时按“没有这个力矩”算接触力/加速度，加完就不再匹配——姿态/接触任务被开环破坏，
轮子又还在地面，地面反力实际分配变了而 WBC 假设没变。→ 对应实测“状态很奇怪”。

对照 VP1 的做法（折进 `dynamics_bias`+限幅）又被 QP 完全吸收（实测净力矩逐位不变）。
两次都不对的真正原因：**前馈没进入 WBC 的动力学约束**。

接口事实（已读代码）：
- `Algorithm/supervision.py:257,278-282`：`solve_wbc(..., external_force=None)`，
  注释写明“external_force：调用方直接注入的广义等效力（跳跃用，方案 v3 第 6 节）”；
- `Algorithm/wbc/*.py`：进入动力学约束 `M*qdd + h - S^T*tau - tau_ext = 0`（`h = h - external_force`），
  **要求 nv 维**，维度不合法直接抛错；
- `control.py:372-373` 现在 `external = None`。

二、本轮改动（一项，语义必须同时改）

1. 前馈从“解后硬加”改为**传入 `external_force`**：

     tau_ff = 将 J^T*[0, F_phi] 映射到 nv 维广义坐标（只在两条腿的腿关节列非零，其余 0）
     solve_wbc(..., external_force=tau_ff)

   **同时**：输出端不再另加这个力矩——**直接用 WBC 解出的总力矩**。
   这是避免双重计数的关汿：WBC 解出的 `S^T*tau_wbc` 已经是“包含前馈在内”的结果，
   再加一次就会变成 `S^T(tau_wbc + tau_ff)`，与假设不符。
   （两种做法只能取其一，本轮选“WBC 自己算进去”。）
2. **20 ms 线性斜坡必须在本轮实现**（重要）：文档 B2 规格写明“进入 THRUST 后 20 ms 线性
   0→1.58 N”，而上一轮 FL15B2 实际实现的是**常量阶跃**（与文档不符）。斜坡要在 FL16 路径里做，
   即 **`external_force` 的幅值在进入 THRUST 后 20 ms 内线性从 0 升到 1.58 N**，尔后保持到相位切换。
   依据：常量阶跃会重演 FL7/FL8 已实测的“力阶跃→姿态/摆角注入”。
   幅值 1.58 N（每腿）、只在 THRUST 生效、压缩/飞行段不动、可关具名开关默认关。

一、目标（用户 2026-10-10）

把“世界系腿角 → 机体系目标”的换算**解耦成一个独立接口模块**，让压缩/释放/飞行**三个阶段都能调用**，

FL21 判定与 FL22：提前启用 phi 阻尼 + 废弃代码清理（问题排查agent，2026-10-12）

一、FL21 判定：**通过（实质目标达成）**

| 指标 | FL19 | FL21 | 判定 |
|---|---|---|---|
| 交接帧 phidd 突降（-154.5） | 存在 | **消失** | 达成 |
| 交接窗口 phidd 峰值 | — | -46% | 部分 |
| FLIGHT 最小 prate | -4.188 | -2.9% | 未达 |
| FLIGHT `max|pitch|` | 0.5391 | **0.5040（-6.5%）** | 更优 |

**判据更正（排查agent）**：阶跃改斜坡**只改变频率含量（去 jerk），不改变冲量**（∫F_phi dt 不变）。
所以“单帧突降消失”才是修复的真效果；“窗口峰值降一个量级 / 最小 prate 明显下降”**是我的错误预期**。

**真正决定注入量的是**：切换时刻 `F_phi` 的幅值主要由阻尼项 `kd*phidot = 1.67*3.8 ≈ 6.3 N*m` 决定，
而阻尼一个快摆的腿 = **把腿的角动量转给机体**（角动量守恒，必然），斜坡救不了。
→ **注入量 = 切换时刻腿的摆角动量，它来自收腿过程对腿的加速。**

**当前最优组合：FL19（收腿下限 0.20）+ FL21（F_phi 斜坡）= `max|pitch|` 0.5040。两处均保留。**
