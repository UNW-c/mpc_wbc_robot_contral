## 1. 物理口径（已定，不要重开）

两个质量块，各自独立：

```
下块（两轮 + GH/OP）：m1 = 3.924 kg   状态 (z1, z1', z1'')、(x1, x1', x1'')
上块（其余全部）    ：m2 = 10.622 kg  状态 (z2, z2', z2'')、(x2, x2', x2'')、theta2 及其导数
整机 14.546 kg      ：k = m1/m2 = 0.3694
```

导出量（**永远不作为规划量或判据**）：`L = |p2-p1|`、`L'`、`phi`、`L'' = a2-a1` 连线分量。

耦合关系：

```
上块：m2*z2'' = F*cos(phi) - m2*g        ->  F*cos(phi) = m2*(z2''+g)
下块：m1*z1'' = N - m1*g - F*cos(phi)    ->  N = m1*(z1''+g) + F*cos(phi)
F(t) = -m1*(z1''+g) = m2*(z2''+g)         （飞行段动量守恒推出的同一式）
分离条件：N = 0  <=>  F = -m1*g = -38.5 N（单腿 -19.3 N）
         此时（下块被地面钉住、z1''=0）上块加速度 z2'' = -(1+k)*g = -13.43 m/s^2
切向：tau_t = m1*L*(L*phi'' + 2*L'*phi' + g*sin(phi_w))
```

圆周坐标（分析用）：`a_r = L'' - L*phi'^2`、`a_t = L*phi'' + 2*L'*phi'`。

**离地是一个过程**：弹簧由压缩转拉伸，拉力增到等于下块重力，下块速度降到 0。
不是"某个阈值被跨过"，也不是"时间到了"。

## 3. 已确认的核心问题（按优先级）

### P0-A 部署口径错误：纵向通道是"差值"

事实（`--leg-length-thrust` 打开时）：

```
control.py 把 length_R/L 任务的 desired_acceleration 设成
a_L = jump.desired_com_acceleration_z
=> 命令下发的实际是"腿长加速度 L''"，一个差值量
```

地面段下块被接触钉住（`a1 = 0`），所以 `L'' = a2`，数值上碰巧等于上块加速度；
**腾空或下块自由时它无法表达两块各自的运动**。实测验证：
命令 +21.24 时，按"命令=z2''"预测 N=368 N，实测 369/372 N；
按"命令=a_com"预测 452 N，不符。

结论：纵向通道必须改成两个量（`a1`、`a2`），`L''` 由相减导出。
**这是部署层改动，需用户批准，不要自行动手。**

### P0-B 释放段以"时间"为终点，导致上块终点位置超计划

s7a_on 实测：

```
稳态：命令 z2''=+21.24，实测 +21.4（跟踪误差 <1%，通道健康）
释放：从 1.428 s 起 25 ms 内降到 -9.81（这一版目标值本身也是错的，见 §4）
切相：t=1.454，N=47 N（未到 0），上块位置 z2=0.354（计划 0.283，+71 mm）
     上块速度 z2'=+1.76（全程上升，没收敛）
```

链路：释放期间上块仍以 `L'≈2.4 m/s` 上升 → 上块终点位置 +69~71 mm →
飞行计划的初始分离变大 → T 变长（0.281→0.31~0.36 s）→ 触地更快（-1.39→-1.74）。

**修法方向（待执行）**：
1. 释放段的终点由**实测状态**定义（`N <= 5 N` 或实测 `z2'' ≈ -13.43`），不用时间。
2. THRUST 的 `a2` 曲线要按计划提前下降，使 `z2` 终点落在计划位置——
   这是规划层的事，不是改"触发腿长阈值"。

### P1 落地收敛的包线（上一轮发散的真正原因）

| run | 触地 vz | 触地 pitch | 触地 L | 结果 |
|-----|---------|-----------|--------|------|
| s2_on | -1.89 | -0.537 | 0.298 | 收敛 |
| s7a_reg | -1.39 | -0.539 | 0.283 | 收敛 |
| base01 | -1.52 | -0.733 | — | 收敛 |
| s7a_on | -1.74 | -0.523 | **0.352** | **发散** |

**发散与触地速度无关，与触地时的腿长（即两块分离）有关。**
触地分离 0.352 时，落地缓冲要多压 72 mm，反应放大 → 质心被推向后
（com_vx -0.88 vs 收敛组 -0.43）→ 俯仰从 -0.59 过冲到 +0.48 → 轮离地 →
`airborne_active` 把输出置零（`airborne_zero` 3967 帧）→ 翻倒滚出 2 m。

**落地判据（必须带）**：触地 `|L-0.28| <= 10 mm`；触地后 1.5 s 内不得出现
连续 3 拍 N=0；触地后 1.5 s 内 `|com_vx| <= 0.6 m/s`。任一不满足即判
"落地不可收敛"，优先于任何 pitch 指标。

### P2 pitch 优化（必须在 P0/P1 之后才谈）

已验证的通行点：S1-PD（M1 -0.5394、M2 0.5916、M3 201.8 N、M4 -0.32）对基线
base01（-0.7328 / 0.7945 / 427.9 / -1.55）。飞行段方案的收益是真的。

剩下的 pitch 来源（按可信度）：

3. 离地角动量 97% 产生在 THRUST 相（第一段 COMPRESS+BRAKE 的两项力矩
   几乎精确抵消：净 +0.009；THRUST 相 N 翻倍、切向力归零，净 +0.34）。

## 4. 上一任犯过的错（不要重复）

1. **把腿长/释放/收伸腿当规划单位**——违反 AGENTS 第 8 节。这些只是两块
   速度差的表象。任何"释放段要多久""触发点提前多少毫米"的表述都是违规。
2. **"换算修正"改错了方向**：曾把离地目标从 `-13.43`（`z2''`）改成 `-9.81`
   （按 a_com 推的）。但该 run 走的是长度通道，命令就是 `z2''`，
   所以 `-13.43` 本来是对的；改成 `-9.81` 后 `F=0`、`N=38.5 N`，永远到不了 0。
   **这次改动需要回退。**
3. **用差值口径下结论**：写"腿多伸了 69 mm"，正确写法是"上块终点位置
   比计划高 69 mm（下块 z1=0 不变）"。
4. **在归因前给参数级建议**：应先做"规划错 / 跟踪错"归因（命令值与实测值逐拍比）。
5. **作废的数据**：早期用 `body_subtreemass` 逐体求和算的 `J_leg`、角动量分解
   全部作废（父体含子体，重复计数）。项目自带的 `total_angular_momentum_y`
   用 `mj_objectVelocity` + `body_mass` 是对的，可用。
6. **S5-a / S6 两个实验无效**：S5-a 的回归与 s1pd 不等价（-0.794 vs -0.592）；
   S6 是空操作（跳跃期 `sample=None`、轮任务被摘，改参考不进执行器）。
7. **别信注释**：`release_acceleration()` 的 docstring 说它返回 `z2''`，
   但被赋给 `desired_com_acceleration_z`；实际口径取决于命令行开了哪个通道开关
   （`--leg-length-thrust` 与非该开关是两条不同路径）。**每次先确认这次 run 用了哪个通道。**
