# 轮腿机器人跳跃模块 设计文档

本文件描述跳跃模块的**设计思路与依据**，面向需要复刻或改造该模块的工程师。
不描述具体函数实现；代码细节以源码为准。

适用范围：`wheel_leg_mujoco/gbc_mpc_wbc/`（当前在用的串联腿轮腿机器人）。
`Algorithm/jump.py` 是轮圈腿机器人的另一套跳跃实现，本文末尾单独一节说明其关系。

---

## 一、要解决的问题

### 1.1 机器人构型与执行器权限

整机 14.546 kg，两条串联腿，每条腿两个主动关节（腿长、摆角），两个轮子各一个驱动。
执行器力矩上限：髋 ±40 N·m，轮 ±6 N·m。腿长机械范围 [0.114, 0.430] m，轮半径 0.077 m。

这六个执行器在不同接触状态下的权限完全不同，这是整个跳跃设计的前提：

| 状态 | 能做什么 | 不能做什么 |
|---|---|---|
| 双轮着地 | 腿长可推地（竖直力），摆角可调质心水平位置，轮可加/减速 | 无法让质心离地而不改变姿态 |
| 单轮着地 | 上述能力减半，且轮与腿的力分配变成超静定 | 无法独立控制俯仰与水平 |
| 空中 | 只有髋能给机体反力矩 | 轮子几乎无用（见下）；地面反力不存在 |

两条关键的权限边界，都来自实测：

1. **空中只有髋能做姿态。** 俯仰角速度与腿摆角速度受总角动量守恒约束，两者是**交换关系**：
   腿相对机体的惯量与机体自身惯量之比决定交换率，实测约为 **2:1**（改 1 rad 摆角，pitch 变 0.5 rad）。
   因此"空中把 pitch 拉平"必然要付出两倍的摆角代价。
2. **轮子不能用来控姿态。** 轮子等效惯量与机体俯仰等效惯量之比约 **127:1**（0.000898 对 0.1142），
   要吸收 1.7 rad/s 的俯仰角速度需要轮子转到 216 rad/s（轮缘 16.6 m/s），落地必然打滑。
   轮子只具备 0.1 rad 量级的微调权限。

结论：**跳跃的可行性完全由"地面期怎么储能与怎么用力"和"飞行期怎么摆腿"决定，姿态控制没有第三个执行器可用。**

### 1.2 硬约束

| 约束 | 数值 | 含义 |
|---|---|---|
| 轮最大离地间隙 | 需保持 **200 mm** 以上 | 越障能力的下限，也是飞行段收腿量的设计目标 |
| 腿长机械范围 | [0.114, 0.430] m | 越界即结构干涉 |
| 髋角限幅 | 关节限位，控制侧取 0.9 倍软限 | 留 10% 余量防止贴限位 |
| 离地判定 | 轮最低点几何间隙 > 1 mm | 不能用接触力判离地（见 3.3） |

### 1.3 为什么跳跃难

- **地面期六个执行器全耦合**：推地产生的竖直力、轮子的扭矩、摆角的力矩都会耦合到俯仰上，
  单独给一条腿加力就会改变姿态。
- **飞行期没有反力**：飞行段的任何姿态调整都要用动量交换，而交换率是 2:1。
- **落地是开环的**：触地瞬间的速度、姿态、腿长都是飞行段决定的，落地控制只能修不能防。

设计上因此采取"**把问题切成互不干扰的相位**"的策略，而不是在一个统一的优化里同时解所有东西。

## 二、总体设计思路

### 2.1 三层切分

```
            ┌──────────────────────────────┐
            │  相位机：现在该做什么         │   jump.py
            │  只由测量量与闭式量触发       │
            └──────────────┬───────────────┘
                           │ 每拍给出一组"任务"，不给力矩
            ┌──────────────▼───────────────┐
            │  参考生成：腿长/摆角要多少     │   control.py（飞行与落地）
            │                              │   MPC 规划器（地面）
            └──────────────┬───────────────┘
                           │
            ┌──────────────▼───────────────┐
            │  力矩执行：谁来出力、出多少   │   WBC（地面）
            │                              │   力雅可比（飞行/落地）
            └──────────────────────────────┘
```

这样切分的理由：

- 相位机只回答"哪一段"，不掺和"多少"。它的输入全是观测量，输出是语义化的任务
  （等效力大小、腿长目标、是否独占轮力矩、是否断开控制器、质心竖直加速度目标）。
- 参考生成与力矩执行分开，是因为两者对不同相位的适用性不同（见 2.2）。
- 相位机不持有模型、不读状态、不做定时等待，因此可以离线单测、可以换控制周期而不改逻辑。

### 2.2 核心取舍：地面用 MPC+WBC，飞行用开环剖面 + PD

| 相位 | 用什么 | 为什么 |
|---|---|---|
| 压缩 / 制动 / 释放 | MPC + WBC（把跳跃需求转成任务） | 有接触，可以解接触力分配；六个执行器的耦合由 WBC 统一处理 |
| 飞行 | 腿剖面（开环参考 + PD），**完全绕开 MPC** | 没有接触，接触力模型失效；飞行期只需要两个独立目标：腿长、摆角 |
| 落地 | 腿长 PD 缓冲 + 摆角 PD | 触地瞬间不需要优化，需要的是快速吸收与不失控 |

这条取舍是整个设计里最重要的一条：**不要试图让同一个优化器同时管地面和空中**。
飞行段 MPC 的输出没有物理意义（它算的是地面反力），继续用它只会引入不可解释的力矩。

### 2.3 力的给定方式：给加速度目标，不给关节力矩

跳跃需求最终是一句话："质心要以 a 向上加速"。设计上不让相位机去算关节力矩，而是：

- 地面相位：把 `a` 作为**质心竖直加速度任务**交给 WBC，由 WBC 结合接触与雅可比去分配；
- 飞行/落地相位：直接给腿长与摆角的期望力，再由力雅可比换成关节力矩。

理由：竖直力到关节力矩的换算依赖几何与接触状态，属于动力学层的知识；
相位机如果自己算，就把几何耦合硬编码进了状态机，换模型即失效。

### 2.4 为什么把竖直目标交给 WBC，而不是像 VMC 那样直接解算力矩再叠加

这是本模块最有争议的一条设计选择，值得单独写清楚。曾经有三种可选做法。

**做法 A：VMC 式直接解算。** 按 `F = m(g+a)/2` 算出单腿等效力，用力雅可比换成关节力矩，
再叠加到 WBC 的输出上。

**做法 B：把竖直加速度作为 WBC 的一个任务。** 交给 WBC 的质心竖直任务，由求解器统一分配。

**做法 C：把加速度目标挂到腿长行。** 不走质心任务，直接挂到两条腿的腿长行上。

本模块地面相位的默认路径是 **B**，压缩/制动保留 A 作为诊断开关（两者互斥，不能同时生效），
C 作为可选通道。选择 B 的四条理由，按重要性排序：

1. **任务语义与执行器语义不是一回事。** VMC 给的是关节力矩，它隐含了一个几何假设：
   "腿长方向就是竖直方向"。而腿长力经过力雅可比之后会同时产生摆角方向的分量，
   机体姿态一变，同一个关节力矩对应的竖直力就变了。**要给竖直力，就该在竖直力的层面上给，
   而不是在关节力矩层面上给。**
2. **开环叠加与求解器的接触力分配会打架。** 地面期 WBC 按接触约束解出"腿该出多少力"，
   如果再叠加一份独立算出来的力矩，等于对同一个自由度给了两次指令，谁大听谁的。
   本模块后来不得不把前馈力矩折进 WBC 的限幅与偏置里，让求解器"对已施加的力矩记账"——
   这本身就是对叠加式做法的补丁，反过来证明了它的别扭。
3. **跳跃期的执行器是争抢的。** 双轮着地时有六个执行器要应付腿长、摆角、姿态、轮速、
   质心竖直、位置等多个任务。VMC 只负责其中一个方向，其余仍需 WBC 补；两条路径各管一半，
   分配结果就没有统一的最优性。
4. **结构上的事实：MPC 的力输出从来没有进入 WBC。** 也就是说"力矩由谁算"这个问题必须明确回答，
   不能靠"上层算好了传下来"。本模块的回答是：**任务给 WBC，力矩由 WBC 算**。

做法 C 存在的意义是：当姿态任务与竖直任务抢权重、竖直目标被压掉时，直接把目标挂到腿长行
可以绕开权重竞争。但它的代价是把"质心竖直"这个物理量降级成"腿长"这个执行器量，
在腿不竖直时两者不等价。因此它只作为可选通道，不作为默认。

## 三、分相位设计

相位序列：`IDLE -> COMPRESS -> COMPRESS_BRAKE -> THRUST -> FLIGHT -> LANDING -> RECOVER -> IDLE`，
任何异常进 `ABORT`。

### 3.1 COMPRESS（蓄力下压）

- **物理意图**：把腿压短，为加速段提供行程；同时让质心获得一个可控的向下速度。
- **怎么给**：不直接给腿长目标，而是把支撑力降到**半重**（a = −0.5 g，即法向合力 0.5 mg）。
  这是"受控下压"，不是自由落体——自由落体会在终点产生不可控的冲击。
- **为什么是 −0.5 g**：需要满足接触可行域 −g < a < 0（否则轮子离地）；取半重是本方案的取值，
  不是试出来的。
- **退出**：逐腿判断"剩余距离 ≤ 制动距离"，制动距离由当前下降速度与制动加速度闭式算出。
  逐腿而不是取均值，是因为两条腿的实际行程会有差异，取均值会让某一侧先撞到终点。

### 3.2 COMPRESS_BRAKE（压缩制动）

- **物理意图**：在到达压缩终点前把下降速度刹到零，避免腿长过冲越过终点。
- **怎么给**：支撑力升到 **1.5 倍重**（a = +0.5 g）。
- **退出**：双腿都满足"已到终点且下降速度已被刹回"，才进 THRUST。任一侧未满足都继续制动。

### 3.3 THRUST（蹬伸）

- **物理意图**：在压缩行程内把质心加速到离地速度。
- **力的来源是闭式反解，不是调参**：

```
v_takeoff = sqrt(2 g h)                     目标高度 -> 离地速度
a         = v_takeoff^2 / (2 * com_rise)    加速段需要的质心加速度
com_rise  = kappa * compression_stroke      行程 -> 质心抬升（kappa 由模型实测）
F_leg     = m (g + a) / 2                   单腿等效力
```

  三个式子是同一组关系的三种用法：给高度和行程解力；给力反解需要多大行程（`stroke_for_force`）。
  设计的价值在于：**高度、行程、力只有两个自由度**，任给两个，第三个自动确定，不存在"试出来的增益"。

- **离地判据用几何间隙，不用接触力**：这是踩过的坑。蹬伸期轮子仍压在地面时，
  法向力估计已经会掉到零（实测腿只伸了 2 mm 就被判离地），若据此断开控制，
  机体在最需要控姿的时刻失去控制，俯仰直接冲到 −19.6°。
  因此离地判据取**轮最低点的几何间隙 > 1 mm**；力的判据只做辅助。
- **兜底判据**：腿长到达释放上限也算推离完成（实测释放段腿的伸展量约等于机体上升量，
  轮子几乎不离开地面）。正常应由间隙张开触发，兜底判据只防"间隙测量不可用"。

### 3.4 FLIGHT（飞行）

- **物理意图**：在空中做两件互不干扰的事——收腿（保离地间隙）与摆角（准备落地）。
- **设计要点**：飞行段相位机只输出"断开控制器 + 力矩保持"，真正的控制交给腿剖面。
  原因是飞行段的控制目标与地面完全不同，塞进相位机只会让状态机承担参数整定职责。
- **上升段收腿**：把腿长参考以受限速率收到下限。下限取 **0.16 m** 而不是机械下限 0.114 m，
  原因是离地间隙：少收 0.06 m，间隙会掉约 0.038 m。
  收腿用"参考速率限幅 + PD 跟随"，而不是轨迹插值：轨迹插值在离地时刻会引入速度阶跃，
  而速率限幅天然把加速度限住。
- **下降段伸腿**：把腿长参考以受限速率伸回标称长度，找地面。
  伸腿速率上限与收腿同值，理由是同一个执行器、同一组 PD。
- **速度参考必须等于位置参考的斜率**：PD 里的 kd 项与 kp 项如果对同一个误差反号，
  会互相抵消，实测净力均值只剩 −0.9 N（等于没控）。因此位置参考与速度参考必须成对给出。
- **摆角控制（φ）**：见第四节，这是飞行段唯一能做姿态的手段。

### 3.5 LANDING（落地缓冲）

- **物理意图**：吸收触地冲击，把腿长拉回标称。
- **怎么给**：同一组腿长 PD，参考取**标称长度**（弹簧阻尼语义：受压时向标称推回）。
  不能取压缩目标——那会产生向下的腿力，与缓冲相反。
- **摆角同时接管**：触地后如果摆角不控，腿会被地面带着转，等于放弃了唯一的姿态通道。
  因此落地缓冲里同时叠加摆角 PD，参考仍是世界系锚定值。

### 3.6 RECOVER（恢复）

- **退出判据三条件**：几何接触恢复、算法层接触判定成立、姿态与腿长都进入正常包线。
  三者缺一不可：只看接触会在机构仍在弹跳时提前交还控制；只看姿态会在轮子还没站稳时交还。
- **交还后的状态**：位置参考跟随实测（见 3.7），因此不会出现"参考在远处、机器人在近处"的持续拉拽。

### 3.7 落地重锚（不在相位机里，但决定落地效果）

相位机只管"什么时候落地"，落地后的**参考坐标系**由外层处理：

- 落地那一拍把 MPC、接触估计器、监督器全部重置，并用当拍的实测位置作为参考起点；
- 同一拍丢弃落地前的那次 MPC 解并强制重算，避免 WBC 继续跟踪落地前的轨迹；
- 位置参考在制动期间**跟随实测**，不再把位置锚定在落点。

最后一条是设计上的取舍：前向位移是期望结果，不是要消除的误差。
原地起跳因为触地速度接近零，会自然退化成"停在原地"。

## 四、摆角参考为什么取世界系

### 4.1 物理依据

站立静平衡时，质心必须落在轮子接触点的正上方（或正下方附近）。腿的摆角决定了质心的**水平位置**，
而这个水平位置是相对于**世界**定义的，不是相对于机体。

如果参考取机体系（"腿相对机体保持某个角度"），那么机体每俯仰一点，腿的世界角度就跟着变，
质心的世界水平位置随之漂移，平衡被破坏。取世界系之后：

```
phi_body_ref = phi_world_ref + pitch
```

即"机体系目标 = 世界系目标 + 当前俯仰"，俯仰变化被自动补偿。

### 4.2 参考值随腿长变化

质心的水平偏移随腿长变化，因此静平衡摆角是腿长的函数，用线性拟合：

```
phi_eq(L) = -0.1263 + 0.97 * (L - 0.28)
```

斜率与锚点来自离线拟合（来源为部署文档的拟合结果，非自行选取）。
注意拟合区间只到 L = 0.14 m，更短的腿长属于外推，这是已知限制。

### 4.3 摆角环与腿长环的耦合前馈

腿长 PD 的力会通过机构耦合进摆角（实测表现为摆角加速度的共模偏移）。
设计上用一条前馈补偿：

```
F_phi += c * F_L
```

系数 c 由实测辨识（对称双施加、共模摆角加速度过零的条件），实测区间 −0.037 ~ −0.063，取 −0.052。
**这是辨识值，不是试凑值**；换机构或换传动比必须重新辨识。

### 4.4 摆角控制的启用斜坡

摆角环带宽约 25 rad/s（时间常数 40 ms）。如果离地瞬间直接把摆角力从 0 切到满值，
会形成一个阶跃扰动。因此在进入飞行后的 40 ms 内把 F_phi 从 0 线性升到 1，
上升段与下降段都启用这个斜坡（把阻尼提前到上升段）。

## 五、实践中遇到的问题

这一章分两部分：

- 5.1 – 5.3 回答三个**为什么要这样设计**的问题（独立模块、压缩期隔离 MPC、摆角必须控住）；
- 5.4 – 5.13 记录从"能动"到"能用"之间必须跨过的坑，每条给出：现象、根因、修正。

复刻时先读 5.1 – 5.3 弄清结构上的必然性，再拿 5.4 – 5.13 当自检清单。

### 5.1 为什么把跳跃做成一个独立模块

跳跃不是"给控制器的参考加一个偏置"，而是一段有时序、有相位、有失败出口的行为。
在这段时间里，其他功能的语义全部改变：位置环不能再按常规追参考、姿态任务不能再按平衡逻辑跑、
腿长任务的目标也不能还是标称值。因此设计上把跳跃单独成模块，并给它三条硬边界：

- **只做纯计算**：不持有模型、不读传感器、不写执行器、不推进物理；
- **不含等待型定时器**：所有状态切换只由测量量或由模型闭式算出的量触发；
- **只输出语义化任务**：等效力、腿长目标、是否独占轮力矩、是否断开控制器、质心竖直加速度目标。

这样做换来三件具体的能力，都不是理论上的好处：

1. **可以分段验证。** 压缩、释放、飞行、落地可以各自单独跑（诊断工具支持"压缩完就停"、
   "确认离地就停"），哪个相位坏了一眼能看出来。如果跳跃逻辑散在控制链里，任何一个相位都只能整轮跑。
2. **可以换控制周期而不改逻辑。** 相位机不关心自己是 1 kHz 还是 200 Hz 调用。
3. **状态只有一份。** 相位、每跳锁存、失败原因都在一个对象里。曾经出现过同一份状态被两个对象各持一份，
   改了其中一个、另一个仍是旧值，表现为"参数设了但没生效"。

反过来，如果把相位判断放到输出级（例如让输出级去看几何间隙判断是否离地），
就会把几何知识塞进执行层，并且让"一次跳跃"的状态分散到多个对象，这是设计上明确禁止的。

### 5.2 为什么压缩过程要关掉 MPC 并重锚 WBC 的目标

MPC 的模型与权重是**围绕标称腿长**建立和整定的：质量分布、腿的等效惯量、雅可比、
以及位置/速度/姿态的权重配比，都在标称构型附近得到。

压缩过程会把腿长从标称缩短约 0.12 m，模型与真实构型明显偏离；与此同时位置参考还在原处。
于是 MPC 会把"腿变短造成的质心下降"理解成位置与姿态的偏差，规划出一个**反向的纠正趋势**。
这个纠正与压缩需求直接对撞，表现是：压不下去、姿态被推着走，严重时发散。

因此压缩开始后采取两条措施：

1. **冻结参考推进**，让 MPC 的结果退出控制链，跳跃需求直接以任务形式交给 WBC 执行；
2. **落地与恢复时重新锚定**：把 MPC、接触估计器、监督器的内部状态统一重锚到当拍的实测状态，
   让下一段控制从一个干净、与实测一致的起点重新起算，而不是接着压缩前的旧预测往下走。

**证据等级**：这是**测试结论**——关掉 MPC 并重锚之后，压缩能正常完成、姿态不再发散，
这是被反复复现的现象。但"MPC 的纠正趋势"这一具体机理没有逐拍取证，
属于合理推断而非实测证实，列为待验证项。写在这里是为了让复刻者知道**为什么要这样隔离**，
而不是宣称机理已经查清。

### 5.3 为什么必须控制 leg angle（phi）

真实原因在**力的方向**上，不在"姿态好不好看"上。

**压缩期施加的是竖直方向的等效力，不是沿腿方向的力。** 压缩的目的是让质心按指定的竖直加速度下压，
所以给的是竖直等效力。但只要腿与竖直方向有一个夹角 phi，这个竖直力就会被分解成两部分：

```
沿腿方向（真正压缩腿长）：F_along = F * cos(phi)
垂直腿方向（推动摆角）：   F_perp  = F * sin(phi)
```

`F_perp` 对髋（曲柄）形成一个力矩，方向是**把腿继续推离竖直**。而 phi 越大，`F_perp = F*sin(phi)`
就越大——这是一个**正反馈**：不控它，摆角会自己越张越大。

两点让这个正反馈无法忽略：

1. **压缩期的力本身很大**（由目标高度与行程闭式算出的单腿等效力在百牛量级），
   即使 phi 只有几度，垂直分量也有几十牛的规模；
2. **静平衡位置本来就不是 phi = 0**。世界系平衡摆角约 −0.126 rad（见第四章），
   也就是说这个垂直分量在站立时就已经存在、需要髋持续出力顶住。压缩只是把它放大。

**后果是机械干涉，不是姿态难看。** 结构上有一个与腿长、摆角、俯仰都无关的常数：
小腿最低点相对轮子最低点只有约 **20 mm** 的结构间隙。一旦轮子压进地面（压缩期实测可到 15 mm），
小腿只剩约 5 mm 余量。摆角被正反馈推大之后，**小腿会先于轮子碰到地面**。
而这种接触不在轮子的接触模型里——相位机与 WBC 都看不到它，于是表现为：
姿态莫名异常、腿长越界、压缩终点到不了。

### 小腿触地之后的连锁后果

小腿一旦碰到地面，问题就不再是"姿态难看"，而是**模型与实际不一致**，后果分三层：

**第一层：多出一个模型外的接触点。** MPC 与接触估计器只建模了两个轮子的接触。
小腿触地属于**未建模接触**：支撑点的位置不对、反力方向不对、力的大小也完全不在规划里。
规划器仍然按"只有两个轮子着地"去预测，从这一拍起，预测状态与实际状态开始分叉。

**第二层：闭链的收敛行程被地面卡住。** 腿是闭链机构，腿长变化需要闭链走完一段收敛行程。
小腿成为支点之后，这段行程被地面挡住：腿长不再跟随指令，压缩目标永远到不了；
两个关节持续出力顶在地面上，力矩被顶到饱和，而腿长读数停在那里不动。

**第三层：MPC 在一个错误模型上做优化。** 它看到的腿长不跟随、姿态偏差不收敛，
就把这些当成"模型误差"去纠正，规划出更大的动作；而真实系统里那些动作被地面吃掉了，
于是纠正无效、偏差继续累积，越纠越偏。表现出来就是：压缩终点到不了、姿态异常、
腿长越界，最后进中止。

**这就是摆角必须控住的真正目的**：不是为了让腿"站得直"，而是为了让**接触集合始终只有两个轮子**，
使 MPC 的模型与实际一致。只要接触集合变了，后面所有的规划都失去意义。

所以摆角在所有接触相位都必须被控住，而且控的是**能对抗这个垂直分量的方向**：

- 地面相位由 WBC 的腿长与姿态任务承担；
- 飞行相位用世界系锚定的摆角 PD（见第四章）；
- 落地缓冲里同样叠加摆角 PD，否则触地后腿会被地面带着转。

这也是摆角参考取**世界系**的第二个动机：世界系锚定让摆角不随机体姿态漂移。
若取机体系，机体一低头，腿的世界角就跟着往前倒，正反馈的起点被直接拉大。

### 5.4 WBC 的腿长任务把正在伸长的腿拉回标称

**现象**：蹬伸期腿长上不去，等效力与腿长任务对撞。

**根因**：WBC 的腿长任务参考固定为标称长度 L0，跳跃期实际目标是压缩终点。
两个目标同时存在时，谁大听谁的。

**修正**：跳跃激活且给出腿长目标时，**替换**WBC 腿长任务的参考，而不是叠加。

### 5.5 腿长 PD 的位置项与速度项互相抵消

**现象**：收腿段的净力均值只有 −0.9 N，等于没控。

**根因**：速度参考与位置参考不一致时，kd 项与 kp 项对同一个误差反号。

**修正**：速度参考必须严格等于位置参考的斜率；参考不再变化时速度参考同步归零。

### 5.6 压缩终点既是目标又是退出阈值（零容差）

**现象**：某些工况下腿压不到压缩终点，相位永远停在压缩制动里，
等效力常驻把腿一路伸到 0.43 m 以上，最后 ABORT。

**根因**：压缩终点与"压缩完成"的判定阈值是同一个数，没有任何容差。
只要机构差几毫米压不到，就永远退不出这个相位。

**修正（未实施，属已知缺陷）**：退出阈值与压缩目标必须分开，退出判定要有明确的容差，
并且要有相位超时兜底。

### 5.7 落地重锚搬动参考锚点，产生零输入扰动

**现象**：落地瞬间机体明显被"踢"一下。

**根因**：重锚时不仅换了坐标系，还把参考位置整体搬到了实测位置以外的点，
参考速度随之出现阶跃，控制器把这当成真实误差去追。

**修正**：重锚只允许重置坐标系与参考速度，不许平白搬动参考位置。

### 5.8 落地后位置目标不再跟随实测，导致持续后退

**现象**：落地后机器人一直往后退约 0.24 m 才停。

**根因**：制动期间位置参考被冻结在落点，而实测位置在后退，误差持续累积，
控制器一直在追一个"回不去的点"。

**修正**：制动期间位置目标**跟随实测**，让参考速度归零，误差不再累积。

### 5.9 落地那一拍仍在使用落地前的规划结果

**现象**：落地瞬间 WBC 跟踪的是空中规划的轨迹。

**根因**：MPC 有固定节拍，落地那一拍不一定到期，于是沿用了上一拍（落地前）的解。

**修正**：落地重锚那一拍丢弃旧解并强制重算（MPC 与 WBC 当拍都算）。

### 5.10 参考速度用实测速度播种（正反馈）

**现象**：落地后速度发散。

**根因**：参考速度取自实测速度，实测往前 → 参考往前 → 更往前。

**修正**：参考速度只能来自指令，不能来自实测。

### 5.11 飞行段的"力矩保持"其实被腿剖面完全覆盖

**现象**：想通过给轮子小力矩来控制飞行姿态，实测毫无效果。

**根因**：飞行腿剖面会写满全部六个执行器通道，轮力矩被逐帧覆盖为 0。

**修正**：不要指望在飞行段用轮子做任何事；需要轮子做功只能在有接触的相位。

### 5.12 越界保护不完整

**现象**：腿长实测到 0.43 m 以上（超过机械上限）仍未触发 ABORT。

**根因**：越界检查发生在相位机的入口，某些路径（例如重锚、相位切换同拍）绕过了它；
且检查只覆盖部分相位。

**现状**：**已知缺陷，未修**。

### 5.13 观测口径错误会得出完全相反的结论

**现象**：从 trace 里读"曲柄参考"字段，发现恒为 0，于是判断"ZMP 没有工作"。

**根因**：读的是参考状态里**补零的占位列**，不是真正的曲柄参考。真正的值在控制器内部。

**修正**：任何"某功能是否生效"的判断，必须先用代码确认字段的实际含义与写入点；
不能因为字段名看起来对就直接用。这一条曾经导致一整轮实验方向错误。

## 六、被否决的优化方案（附实测理由）

这一节是复刻时最需要的部分：**下面每一条都是花了代价才确认的边界**。

### 6.0 全部尝试的汇总

目标都是同一个：降低落地姿态角（基线约 −0.73 rad）。下面所有方案都无法接受。

| 方案 | 最好结果 | 致命代价 | 判定 |
|---|---|---|---|
| 压缩时预倾机体 | 触地姿态改善最多 60.5% | 落点后退 0.48 m（原地跳变向后跳） | 方向性否决 |
| 飞行段冻结摆角（不控制 phi） | 改善 36% | 落地后 72 ms 出现 802.9 N 二次冲击峰 | 形状否决 |
| 冻结摆角 + 收腿到底 | 姿态漂移减小 | 离地间隙掉到 0.177 m（低于 200 mm）、腿长越界 | 硬约束否决 |
| 触地前腿角终端预置 | 改善 7%（0.053 rad） | 效率仅 0.26:1；可用幅度内先发散 | 收益否决 |
| ZMP 预设目标点（位置参考偏移） | 终点 1:1 可控 | 曲柄参考不动，落地行为逐位不变 | 无效 |
| ZMP 速度指令驱动 | 曲柄确被激活（0→0.18 rad） | 方向不受指令控制（由"刹车"主导） | 不可控 |
| 轮子蹬地注入角动量 | 水平冲量确有注入 | 角速度变化与理论符号相反、仅 2.1%；触地姿态恶化到 −1.21 | 机理不成立 |
| 轮子反作用控制姿态 | —— | 惯量比 127:1，需轮缘 16.6 m/s | 先验否决 |
| 缩短压缩行程 | 改善 3% | 改善量在噪声量级 | 收益否决 |

**共同结论**：飞行段的姿态由"离地时的角动量"决定，而唯一能做角动量交换的通道是髋，
它与姿态是 2:1 交换。任何"把姿态压下去"的方案都要么把腿推到极端，要么改变起跳方向。
真正有效的只有"接受姿态、把落地恢复做好"。


### 6.1 不做空中的主动姿态控制

空中只有髋一个通道，且与 pitch 是 2:1 交换；轮子的动量账是 127:1。
试图在飞行段"把 pitch 拉平"会得到两类结果：

- 腿的世界角被推到极端（因为要付两倍代价），触地时腿几乎水平；
- 一旦为此改动了飞行段的俯仰目标，起跳方向也会变（见 6.2）。

**结论：飞行段的姿态是"接受"的，不是"控制"的。** 能做的只有摆角（为落地准备）。

### 6.2 预倾起跳（让机体提前后仰）——否决

让机体在压缩时后仰，靠蹬伸的前翻冲量把机体"转正"，理论上能降低离地时的俯仰角速度。

实测：负向预倾确实能显著降低触地 pitch（−0.30 rad 时降低 60.5%），
但代价是**落点后退 0.48 m**——"原地起跳"变成了"向后跳"。
这是方向性问题，不是幅度问题，因此不可接受。

### 6.3 飞行段冻结摆角（放弃摆角补偿）——否决

思路是把摆角完全冻结，让机体在飞行段保持姿态不变。

实测：触地 pitch 从 −0.7328 改善到 −0.4547（−36%），落点与后退量都优于基线，
但落地后 72 ms 出现 **802.9 N 的二次冲击峰**（触地峰只有 223 N）。
形状判据不通过：落地后出现二次冲击意味着腿在触地后被重新压缩，随后的姿态调整不可控。

### 6.4 触地前把腿角终端预置（把落地后要用的后摆行程提前用掉）——否决

思路来自姿态录像：收敛到水平时机体已经把腿大幅后摆，说明"让机体抬平所需的摆角行程"是在地面支撑下完成的。
如果把这段行程提前到触地前，触地点就会从质心前方移到质心后方，触地后的低头力矩变成抬头力矩。

实测（腿角终端预置量 vs 触地 pitch）：

| 预置量 | 触地 pitch | 变化 |
|---|---|---|
| 0 | −0.7328 | 基线 |
| −0.30 | −0.8069 | 恶化 0.074 |
| +0.20 | −0.6799 | 改善 0.053，但触地后扎到 −1.2382、3 s 内前冲 2.93 m |

- 有效方向存在，但效率只有 **0.26 rad pitch / rad 摆角**，比 2:1 交换低一个数量级；
- 原因是：**图 4 那条后摆行程是在地面支撑下完成的**（地面提供反力矩），
  触地前只靠髋关节反作用，效率就掉到 0.26:1；
- 想改善 0.2 rad 需要 0.9 rad 预置，而 +0.20 已经出现发散。

**结论：借地面反力的动作必须发生在落地之后，提前不了。**

### 6.5 用输入通道（速度指令）驱动 ZMP 前探——否决

思路：落地后与"有速度指令"共用同一条控制通道，给一个前向速度指令让规划器产生加速度，
再由 ZMP 曲柄参考生成前倾。

实测：ZMP 曲柄参考确实被激活（落地后从 0 升到 0.18 rad，腿随之摆动），
但**方向不受指令控制**——正向、负向、不同幅值的指令结果完全一致（末位置都在 −0.42 m）。

原因是：落地后机体速度为负（往后滚），规划器的第一优先级是"刹车"，
刹车必然产生正向加速度、进而产生前摆曲柄；指令的符号被这个更迫切的需求淹没。

**结论：ZMP 曲柄在落地窗口里由"刹车"驱动，不能作为主动前探的手段。**

### 6.6 参考速度不能用实测速度播种

落地后如果按实测速度重建参考速度，会形成正反馈：实测往前 → 参考往前 → 更往前。
参考速度只能来自指令。这一条是从一次实际发散中总结出来的。

### 6.7 收腿下限不能再抬（也不会再降）

下限 0.16 m 是"离地间隙 200 mm"这条硬约束的直接结果。少收 0.06 m 间隙掉 0.038 m，
因此这一项没有优化空间——动它就等于放弃越障能力。

### 6.8 轮子蹬地在离地瞬间注入角动量——否决

**思路**：离地前给轮子一个力矩，轮子对地面的反作用会给机体一个反向角动量，
理论上可以抵消一部分离地俯仰角速度，代价是一点水平速度。

**实测**：水平冲量确实注入了（单轮冲量从 0.0996 升到 0.4555 N·s，峰值力 8.3 N 升到 23.6 N），
但角速度变化是 **−0.032 rad/s**，而理论预测是 **+0.82 ~ +1.05 rad/s**——**符号相反，幅值只有 2.1%**。
同一时间窗口内髋通道的角动量收支比它大一个数量级，注入的那点角动量被髋的姿态保持动作吃掉了。
副作用：触地姿态恶化到 −1.2105，腿长越界到 0.4376，最终 ABORT。

**否决理由**：机理不成立。地面期髋的摆角保持本身就是一个很强的姿态调节器，
外部注入的角动量会被它当成扰动吃掉；想在离地瞬间"存"角动量，存不住。

### 6.9 缩短压缩行程——否决

**思路**：行程短一点，离地时腿更直，姿态更接近竖直。

**实测**：行程从 0.12 缩到 0.10，触地姿态从 −0.7328 到 −0.7101（改善 3%）；
但离地间隙从 0.22180 掉到 0.21483，且这一量级的差异与工况离散度同阶。

**否决理由**：收益在噪声量级，不是可用的优化手段。
