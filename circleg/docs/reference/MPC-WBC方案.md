## 0. 两个必须先接受的前提

**(1) 零空间法不表达不等式。** 它求的是等式任务的最小范数解。要挂上力矩限与
摩擦锥，必须额外用 **SNS 饱和 + 任务缩放 + 摩擦锥解析化**（§5），代价是丢掉
全局最优性，换来闭式、定长、可硬实时。对 1 kHz 的 WBC 这个交换值得。

**(2) 控制权限只有 4 维，需求有 5 维。** 严格优先级下必然牺牲一维。账要先算清：

| 执行器组合 | 直接控制 | 不可回避的副作用 |
|---|---|---|
| 两轮同向滚（净切向力） | **俯仰**（唯一手段）/ 前向速度 `v_x` | 二者共用同一维，不可兼得 |
| 两轮反向滚 | 偏航 `ψ` | scrub 摩擦损耗（§1.2） |
| 两髋同向（和） | 机身高度 `z` | **±20 N·m 直接俯仰力矩**（§1.5）+ 寄生偏航（§1.3） |
| 两髋反向（差） | 横滚 `φ` | 法向力再分配，受单边性限幅（§1.6） |

需求 `{θ, φ, ψ, z, v_x}` 共 5 维，权限 4 维。结论：

> **`v_x` 在 WBC 里必然被牺牲到最低优先级。速度跟踪完全靠 MPC 给出的俯仰参考
> 来实现。因此 MPC 输出的 `θ*(t)` 是整个系统里最重要的一个信号。**

注意两轮的关节轴反向（`joint2` 为 `(0,1,0)`，`joint4` 为 `(0,-1,0)`），所以
"同向滚"在指令层是差动、"反向滚"是共模——但在 WBC 里这套记账由 `S` 与 `Jc`
自动完成，`WheelTorqueMixer` 那套手工符号处理会整块消失。

## 1. 六条构型级硬限制

每条都给出量化结论和它对方案的具体要求。不先解决，实现必然失败。

### 1.1 两接触点连线方向的力矩恒为零 → 俯仰无瞬时力矩权限

接触力作用在接触点上，绕两接触点连线的力矩恒等于零。设 `u ∥ (P₂−P₁)`：沿 `u`
的等值反向力对产生零合力、零合力矩，故地面力到机身力扳手的映射 `R⁶→R⁶` 核维数 1、
像维数 5，缺失的输出方向正是 `M·u`。

轮心因 C2 装配纵向错开 `0.12·sin q`，故 `u = (0.12·sin q, 0.24, Δz)`：

| 髋角 q | `u` 方向 | 不可控力矩方向 | 后果 |
|---|---|---|---|
| 0 / π（死点） | `(0, 0.24, 0)` 纯横向 | 俯仰 `M_y` | 俯仰**完全欠驱动**，只能靠"先加速再减速" |
| π/2（中行程） | `(0.12, 0.24, 0)` 偏 `atan(0.5)=26.57°` | 偏 26.6° 的 roll/pitch 组合 | **横滚与俯仰力矩不再独立**，只有垂直于 `u` 的组合方向可控 |

粗糙地形上两接触点高度不同，`Δz ≠ 0`，`u` 还会向 z 倾，不可控方向进一步偏离横向。

**对方案的要求**：MPC 中接触点位置 `r_i` 必须是 `q` 的时变参数（按计划腿轨迹每拍
重算）；俯仰/横滚的代价权重必须写在 `u` 对齐的基底里，否则 QP 在缺失方向上无正则、
条件数爆炸。

**这也是 MPC 在本机器人上真正有价值的原因**：俯仰不可直接施矩，恢复动作必须跨时间
安排。现有单点线性化 LQR 只能靠 `|B[3]| ≈ 14·|B[2]|` 隐式表达；MPC 的时域展开是它
的原生表达。

### 1.2 横向：过约束与 scrub（**修正原方案**）

两轮平面都在 x–z 平面内（轴沿 ±y，无 camber），轮心纵向错开。接触点 y 向速度：

```
v_i,y = v_y + ψ̇·Δx_i − φ̇·Δz_i
```

平地上两接触点同高，`Δz_i` 相同，`φ̇` 项在两式中完全相同、相减即消。于是

```
v_y + ψ̇·Δx_右 = 0
v_y + ψ̇·Δx_左 = 0      Δx_左 ≠ Δx_右  ⟹  ψ̇ = 0
```

**只要腿不在死点，对两点都施加硬横向无滑就让偏航在数学上不可行。**

但**"横向不加约束"同样是错的**：横向没有任何执行器，去掉约束后横向既不受约束
又不被驱动，模型会允许自由侧滑。真实物理是：这是一个**运动学过约束**，现实中以
**scrub（两接触点同时部分滑移，摩擦力顶在锥边界）** 的形式化解。

**采用方案**：在两接触点**中点**施加单一集中横向无滑约束（1 行，经典非完整移动
机器人模型），残余 scrub 作为有界扰动前馈补偿。

```
接触约束行数 = 2×法向 + 2×纵向 + 1×集中横向 = 5
独立速度自由度 = nv − 5 = 10 − 5 = 5
驱动 4 → 净欠驱动 1 维，即俯仰（与 §0 的权限账一致）
```

**scrub 的量化后果**（这是原方案漏掉的一阶效应）：

- 每点相对中点的滑移速度 `v_scrub,i = ψ̇ · 0.06·sin q`。`ψ̇ = 1 rad/s` 中行程时
  为 **60 mm/s**。
- 滑移时横向摩擦顶在锥边界 `μf_z = 46.6 N`，两个力反向、力臂各 `0.06·sin q`，
  产生**阻碍偏航的库仑力矩**：

```
M_scrub = 2 × 0.06·sin q × μ·f_z = 5.59 · sin q   N·m
```

- 可用偏航力矩只有 `2 × 31.25 × 0.12 = 7.5 N·m`。

> **中行程时 scrub 摩擦吃掉 74.5% 的偏航权限；死点处为零。** 偏航权限随腿行程
> 变化 4 倍。MPC 必须把这条建模进去，否则会反复规划中行程做不到的转弯。
> 运行策略上：**尽量在死点附近转向**。

这是库仑型（与 `ψ̇` 符号相关、幅值不随 `ψ̇` 变化）的力矩，不是黏性阻尼，
低速下会造成偏航死区与极限环。建议在偏航任务里做符号前馈补偿 + 死区内切换为
积分作用。

### 1.3 升降腿 ↔ 偏航的非完整耦合（**原方案漏项**）

髋转动时轮心在机身系里以 `∓0.06·cos q·q̇` 平移，**两侧方向相反**。若纵向不滑移，
机身必须转动才能同时满足两个接触点：

```
0.12·ψ̇ = 0.06·cos q·q̇     ⟹     ψ̇ = 0.5 · cos q · q̇
```

| 动作 | 寄生偏航 |
|---|---|
| `q̇ = 1 rad/s`，死点附近 | **0.5 rad/s** |
| 半行程升降 `0 → π/2` | `∫0.5cos q dq = 0.5 rad = ` **28.6° 净偏航** |
| 全行程 `0 → π` | `0.5[sin q]₀^π = 0`，恰好抵消 |

> 演示动画里"两轮反向滚动"的动力学后果就是这个偏航。**任何部分行程的升降都会
> 留下最多 28.6° 的航向漂移。**

**对方案的要求**：偏航任务必须带前馈项 `ψ̇_ff = 0.5·cos q·q̇`（由腿轨迹计划直接
给出），不能只做反馈。WBC 的接触投影在偏航任务存在时会自动产生补偿轮力矩——
但前提是偏航任务的优先级足够高（见 §4.3 的优先级调整）。

### 1.4 死点的双重奇异（**原方案只说了一半**）

`dz/dq = 0.06·sin q` 同时决定两个互为倒数的增益：

| 髋角 q | `sin q` | 高度权限 `dz/dq` (m/rad) | 髋→法向力增益 `1/(0.06 sin q)` (N per N·m) | 支撑所需髋力矩 (N·m) |
|---|---|---|---|---|
| 0（死点） | 0 | **0** | **∞** | 0 |
| 5° | 0.087 | 0.0052 | 191 | 0.09 |
| 25° | 0.423 | 0.0254 | 39.4 | 1.00 |
| 90° | 1.0 | 0.0600 | 16.7 | 2.36 |

两个方向的后果相反，不要混：

- **高度控制**：死点处权限为零，逆解要求 `q̈ → ∞`。需阻尼最小二乘，阻尼 ∝ `1/(sin²q+ε)`。
- **法向力/横滚控制**：死点处增益发散。`[5°, 90°]` 上变化 **11.5 倍**。
  力矩涟波、摩擦、估计噪声在死点附近会被放大 11 倍直接进入法向力与横滚。
  横滚回路增益必须 ∝ `sin q` 排程。

**因此推翻原方案的一个默认**：现有 `LegConfig.angle_zero = 0.0` 把标称姿态停在
死点上，那是**横滚控制最差的工作点**。

> **建议把标称工作点移到 `q₀ ≈ 25°`。** 代价：每髋持续 1.0 N·m（限值的 10%，
> 真机上是发热成本），机身只低 5.6 mm（`0.1986` vs `0.1930`，因为 `cos` 在 0 附近
> 变化极慢）。收益：法向力增益从 ∞ 降到 39.4，高度权限从 0 升到 0.025 m/rad，
> 横滚与高度同时变得可控。**这个改动的性价比极高，建议在 M1 就做。**

死点自锁（零力矩承载）作为**驻车/待机姿态**保留，不作为控制工作点。

### 1.5 髋力矩是 ±20 N·m 的直接俯仰力矩（**原方案漏项，最危险的一条**）

髋轴沿 y，即**俯仰轴**。髋力矩直接作用在机身俯仰方向上：

| 来源 | 俯仰力矩 |
|---|---|
| 两髋合计（`j1_ctrl` + `j3_ctrl`，各 ±10 N·m） | **±20 N·m** |
| 两轮全部切向力 × 质心高（`62.5 × 0.177`） | 11.06 N·m（死点）～ 18.0 N·m（全伸） |
| 比值 | **髋是轮子俯仰权限的 1.1 ～ 1.8 倍** |

两面性：

- **风险**：任何升降腿动作都是一阶俯仰扰动，幅度超过轮子的全部恢复能力。
  现有"髋 PD + 轮 LQR"分离架构对这个 20 N·m 的交叉耦合**完全无知**，这大概是
  现在升降腿容易失稳的根本原因。
- **能力**：髋可当作**类反作用轮的快速俯仰执行器**（人体平衡里的 hip strategy）。
  机身俯仰惯量 `iyy = 0.053191`，20 N·m 给 376 rad/s²。但它是**冲量受限**的：
  行程只有半圈，且会同时改变机身高度与法向力分配，只能用于瞬态。

**对方案的要求**：这条交叉耦合在完整模型的 WBC 里由 `M` 和投影算子**结构性地
自动处理**——这是换 WBC 相对现有架构最大的单项收益。但要求：
(a) MPC 必须知道髋的俯仰贡献，否则它规划的 `f*` 会被髋动作破坏；
(b) 俯仰任务（L1）必须在高度任务（L4）之上，让高度任务只能在俯仰的零空间里动作；
(c) 不要把髋力矩限幅设得过宽，`±10 N·m` 的满量程用在高度任务上是危险的，
建议给高度任务单独设一个更紧的软限（如 ±4 N·m，即现有 `HipConfig.torque_limit`），
把余量留给 L1 的俯仰用途。

### 1.6 单支撑时横滚完全不可控（**原方案漏项**）

所有四个关节轴都沿 ±y，**没有任何执行器有横滚轴分量**。横滚力矩的唯一来源是
两接触点之间的法向力差：

```
M_x = Δf_z × 0.12,  受单边性限制 |Δf_z| ≤ m·g = 93.2 N
⟹  |M_x| ≤ 11.2 N·m（一轮完全卸载时）
```

单轮离地时 `Δf_z` 不可调、`M_x ≡ 0`（点接触 + `condim=3`，无侧倾抗力）：

> **单支撑 = 横滚完全不可控 = 必然侧翻。这不是"性能下降"，是失效。**

**对方案的要求**：
(a) MPC 的接触计划里"双支撑"是硬前提，不存在可选的单支撑相；
(b) 粗糙地形（`main.py --terrain rough`）上单轮离地必须有专门的**落地恢复行为**：
立刻让离地侧髋朝增加腿长方向运动去找地面，其余任务全部降权；
(c) 需要接触状态估计 + `N_0` 的平滑重建（§5.3）；
(d) 横滚是仅次于俯仰的安全关键量，优先级必须高于偏航和高度（§4.3）。

## 2. 整体架构、频率与计算预算

```
用户指令 ──► 参考生成 100 Hz：v_x*, ψ̇*, z*  +  腿行程计划 q*(t), q̇*(t)
                    │                              │
                    ▼                              │（时变接触几何 + 前馈项）
        ┌───────────────────────────────┐          │
        │ 上层 MPC  50 Hz / dt = 0.02   │◄─────────┘
        │ N = 25 → 0.5 s 视界           │  SRBD + 接触力为决策变量
        │ 输出 f*(t), θ*(t), θ̇*(t), θ̈*(t)│◄── 任务缩放因子 s 回馈（§5.4）
        └───────────────────────────────┘
                    │ 零阶保持 + 三次插值
                    ▼
        ┌───────────────────────────────┐
        │ WBC 慢环 200~500 Hz           │  QR 消力 + 递归零空间 + SNS
        │ 输出 τ_slow + 有效增益          │
        └───────────────────────────────┘
                    │
        ┌───────────────────────────────┐
        │ WBC 快环 1000 Hz              │  仅俯仰角速度阻尼 + 力矩饱和（标量运算）
        └───────────────────────────────┘
                    ▼  τ ∈ R⁴
        状态估计 1000 Hz：姿态 EKF + 接触运动学里程计 + 接触状态
```

### 2.1 频率论证

开环不稳定极点 **+7.65 rad/s（131 ms，实测）**。交叉验证：单摆公式
`√(g/h) = √(9.81/0.177) = 7.44 rad/s`，与实测差 3%，两者互证。

一个有用的推论：`h` 从死点的 0.177 m 伸到全伸的 0.2887 m 时，
`√(9.81/0.2887) = 5.83 rad/s`（172 ms）。

> **伸腿让发散时间常数变长 28%，平衡变容易。** 而静态可恢复倾角
> `arcsin(F_max/mg) = arcsin(62.5/93.2) = 42°` 与腿长**无关**（分子分母同乘 h）。
> 所以高姿态的收益纯粹来自"反应时间更长"。高速行驶时应主动伸腿。

- MPC 20 ms 一拍 → 每拍放大 `e^(7.65×0.02) = 1.165`，够用但**不足以独立稳定**。
- 视界 0.5 s = 3.8 倍时间常数，足够展开非最小相位机动。
- **1 kHz 快环里必须有独立的俯仰角速度阻尼项。** 这不是可选项。

### 2.2 计算预算（**原方案漏项**）

WBC 每拍需要：`mj_fullM`、`mj_jac` ×2、`J̇c q̇`、`Jcᵀ` 的 QR、6 级递归零空间
（每级 1 个阻尼伪逆）、SNS 最多 4 轮迭代。矩阵都很小（≤10×10），但 numpy 的
Python 调用开销约 5–20 µs/次，一拍 100+ 次操作。

> **估计：纯 Python + numpy 的完整 WBC 只能跑 300～600 Hz，达不到 1 kHz。**
> 这个数字必须在 M2 实测确认，但方案设计上就应该假定它成立。

三条应对（按推荐顺序）：

1. **快慢双环**（推荐）：慢环 250 Hz 跑完整层级，快环 1 kHz 只做
   `τ += −k_d·(θ̇ − θ̇*)` 和力矩饱和。俯仰阻尼是唯一真正需要 1 kHz 的东西，
   它恰好是最便宜的标量运算。
2. 接受非实时仿真（开发期完全可以，`--headless` 下 RTF 0.3 也能验证算法）。
3. numba / Cython 化热点，或用 `mujoco.mjx`。**不要在 M2 之前做**，会掩盖逻辑 bug。

MPC 侧：condensed QP 约 150 变量、350～450 约束行，OSQP 求解 0.5～2 ms。
真正的风险是**Python 端每拍重建 QP 矩阵**（时变 `r_i`、yaw 旋转）会比求解本身更慢。
必须预分配稀疏结构、只用 `osqp.update(Px=..., Ax=..., l=..., u=...)` 更新数据，
绝不重建 sparsity pattern。

### 2.3 状态估计（必须先升级，现有 3 状态 KF 撑不住）

| 量 | 来源 | 难点 |
|---|---|---|
| 姿态 `φ θ ψ` | `imu_quat` + `imu_gyro` 四元数 EKF | 仿真可直读，但按真机结构写，避免后期返工 |
| 机身速度 `v` | 加速度计积分 + 接触运动学里程计融合 | **必须补上轮心相对机身的运动项 `∓0.06·cos q·q̇`**。现有纯轮速里程计漏了这一项，MPC 会把它当成真实速度误差去追 |
| 机身高度 `z` | 由 `q1, q3, φ, θ` + 双轮触地闭式反解 | 单轮离地时该反解失效，需切换到积分推算 |
| 接触状态 | 法向力估计 + 轮速/机身速一致性检验 | 无力传感器（§8），只能模型估计 |
| 法向力 `f̂_z` | 三源交叉：MPC 的 `f*`、QR 回代的 `f`、髋力矩 ÷ 曲柄力臂 | 死点附近第三源增益发散（§1.4），需按 `sin q` 加权 |

顺带清理：`Algorithm/estimator.py:96` 的偏航噪声混合用了绝对目标 `3.0`，
`leg_progress > 0.125` 之后转向反而**降低**里程计标准差（更信任），意图大概是反的。

### 2.4 启动与失效状态机（**原方案漏项**）

MPC 需要有效的接触状态才能工作，不能冷启动。

| 状态 | 进入条件 | 使能的任务 | 退出条件 |
|---|---|---|---|
| `INIT` | 上电 | 无（零力矩） | 双轮触地 + 姿态收敛 |
| `PARK` | 双轮触地 | 髋位置保持在死点（自锁） | 收到使能指令 |
| `RAISE` | 使能 | 髋 → `q₀ = 25°`，俯仰任务已开 | `\|q − q₀\| < 2°` |
| `BALANCE` | 姿态收敛 | 全部，MPC 在环 | 指令停止 / 失效 |
| `RECOVER` | 单轮离地（§1.6） | 离地侧找地面，其余降权 | 双轮恢复 |
| `FAULT` | `\|θ\| > 35°` 或轮速饱和持续 200 ms | 零力矩 + 髋回死点 | 人工复位 |

`RAISE` 阶段必须在俯仰任务已经闭环之后才动髋，否则 §1.5 的 20 N·m 俯仰扰动会
直接把机器人推倒。

## 3. 上层 MPC 详细设计

### 3.1 模型：SRBD，不是纯质点

"刚体质点简化模型"按 **SRBD（集中质量 + 固定转动惯量）** 落地。
**纯质点模型（LIP 那类）会丢掉转动惯量和力矩平衡，而俯仰动力学恰好是这台机器人
唯一真正需要 MPC 的东西**，必须保留转动部分。

```
状态 x = [φ θ ψ | p_x p_y p_z | ω_x ω_y ω_z | v_x v_y v_z]  (12) [+重力常项 → 13]
决策 u = [f_右(3), f_左(3)] × N = 6 × 25 = 150
```

在 **yaw 对齐的水平框架**下线性化，惯量按当前 yaw 旋转。**不设横向位置任务**——
y 方向本质非完整，横向力只作为转弯向心力出现。

三个必须做的模型修正（**原方案漏项**）：

| 修正 | 数值 | 不做的后果 |
|---|---|---|
| **轮子反射惯量** `I/R² = 0.0082496/0.0256 = 0.322 kg/轮` | 等效质量 +0.645 kg = **+6.8%**（9.501 → 10.146 kg） | MPC 高估加速度 6.8%，`a_max` 从 6.58 虚报到实际 6.16 m/s² |
| **惯量随行程变化** | 腿占质量 15.7%，质心高变化 1.6 倍（0.177→0.289 m） | 单一常值惯量在高姿态误差大；建议按 `q` 做 5 点插值表 |
| **髋的俯仰贡献** | ±20 N·m（§1.5），超过轮子权限 | MPC 规划的 `f*` 被髋动作破坏；须把 `τ_hip` 作为已知输入项进入俯仰方程 |

### 3.2 约束（全部线性，保持凸 QP）

| 约束 | 形式 | 数值 |
|---|---|---|
| 单边性 | `f_z ≥ f_min` | `f_min = 2 N`（零法力会让摩擦锥退化） |
| 摩擦锥（金字塔化） | `\|f_x\| ≤ μf_z`，`\|f_y\| ≤ μf_z` | `μ = 1.0`（XML `friction="1.0"`） |
| **轮电机力矩** | `\|f_x\| ≤ τ_max/R` | `5/0.16 = 31.25 N` |
| **偏航权限（含 scrub）** | `\|M_z\| ≤ 7.5 − 5.59·sin q` | 中行程只剩 1.91 N·m（§1.2） |
| **`f_z` 的构型相关上界** | `\|Δf_z\| ≤ min(τ_hip,max/(0.06 sin q), 运动学速率界)` | 死点处力界不绑定，**速率界绑定**（`ż = 0.06 sin q·q̇`） |
| 横滚（单边性） | `\|M_x\| ≤ 11.2 N·m` | 一轮完全卸载（§1.6） |
| 机身高度 | 髋轴高度 `∈ [0.105, 0.215]` | 由 `0.16 − 0.06cos q`，两端各留 5 mm 避死点 |
| **软关节限位** | `q ∈ [5°, 175°]` | 四个关节 `limited="false"`，可无限旋转，必须软限位（§8） |
| **俯仰-高度几何约束** | `\|θ\| ≤ θ_max(z)` | 低姿态 + 大俯仰时机身网格会触地（§8），需几何扫查标定 |
| 接触计划 | 恒双支撑，离地轮 `f=0` 仅用于 `RECOVER` | §1.6 |

一个关键结论（量级估算，基于已核对常数）：总质量 9.50 kg，标称单轮法向力 46.6 N，
`μ=1` 给 46.6 N 摩擦上限，力矩上限只有 31.25 N。

> **平地上绑住性能的是电机力矩，不是摩擦锥。** 摩擦锥只在单轮法向力掉到标称的
> 67% 以下（剧烈横滚 / 升降腿）或粗糙地形上才先触发。调参重点：先榨干力矩，
> 摩擦锥主要防"抬腿瞬间打滑"。

### 3.3 代价函数与俯仰参考

```
J = Σ ‖x_k − x_k*‖²_Q + ‖u_k‖²_R + ‖u_k − u_{k−1}‖²_RΔ  + 终端代价
```

- 权重按 §1.1 的 `u` 对齐基底写，**不要直接写 roll/pitch**。
- 优先级：俯仰角与俯仰角速度最高，其次 `v_x`、`ψ̇`，再是 `z`、横滚。
- `RΔ`（力变化率）**不能省**：WBC 以 250～1000 Hz 跟踪 50 Hz 的力轨迹，
  力序列不平滑直接变成力矩抖动。
- **俯仰参考不是常值零**，而是所需加速度对应的准静态平衡倾角：

```
θ*(t) = atan( a*(t) / g )
```

  现有代码的 `velocity_pitch_gain = 0.12 × v_err` 是这个式子的线性近似
  （`atan(a/g) ≈ a/g`，`1/g = 0.102`，所以 0.12 相当于把误差增益折进去了）。
  换成解析式后这个手工参数可以删掉，而且大倾角下更准。
- 终端代价：驱动到 `(v_x = v_x*, θ = atan(a*/g), θ̇ = 0)` 的稳态流形，
  并给足权重，否则 0.5 s 视界末端会出现"存钱式"倾倒。

### 3.4 实现要点

- **OSQP 稀疏结构复用**：预分配 `P, A` 的 sparsity pattern，每拍只 `update` 数据。
- **warm start**：上一拍解左移一格 + 末尾复制，通常让迭代数降到 1/3。
- **时序**：MPC 在 `t` 拿到的状态是 `t−Δ` 的（估计延迟），求解又要 1～2 ms。
  必须做**一步状态预推**（用上一拍的 `f*` 前推 `Δ + t_solve`），否则 50 Hz 下
  相位滞后会吃掉稳定裕度。
- **失败回退**：QP 不可行或超时时，**沿用上一拍解的下一格**，并计数；
  连续 3 拍失败 → 降级到"只保俯仰"的应急 LQR（保留现有 `Algorithm/lqr.py` 作为
  这个安全网，不要删干净）。

## 4. 下层零空间 WBC 详细设计

### 4.1 消去接触力：正交（QR）分解，不用 QP

浮动基约束动力学（`nv = 10`，`na = 4`，接触约束 5 行，§1.2）：

```
M q̈ + h = Sᵀ τ + Jcᵀ f
Jc q̈ + J̇c q̇ = 0
```

对 `Jcᵀ` 做正交分解 `Jcᵀ = [Q_c  Q_u][R; 0]`，左乘 `Q_uᵀ` 把 `f` 解析消掉：

```
Q_uᵀ(M q̈ + h) = Q_uᵀ Sᵀ τ            ← 无力项，直接解 τ
τ = (Q_uᵀ Sᵀ)⁺ Q_uᵀ (M q̈ + h)
f 由 Q_cᵀ 分块事后回代                  ← 用于摩擦锥校验（§5.2）
```

这条路（Mistry / Righetti / Buchli / Schaal 的 orthogonal decomposition 逆动力学）
是**非 QP 处理"浮动基欠驱动 + 接触"的正确工具**，闭式，无迭代。

`Q_uᵀSᵀ` 是 `5×4`（`nv−5 = 5` 行，4 列），超定 → 伪逆给最小二乘解。
**它的条件数是关键健康指标**，死点附近会恶化，必须逐拍监控（§7.3）。

### 4.2 递归零空间

```
N_0 = I − Jc⁺Jc                                 （接触零空间，最高硬优先级）
q̈_0 = Jc⁺(−J̇c q̇)
q̈_i = q̈_{i−1} + (J_i N_{i−1})⁺(ẍ_i* − J̇_i q̇ − J_i q̈_{i−1})
N_i = N_{i−1} − (J_i N_{i−1})⁺(J_i N_{i−1})
```

伪逆用 **M 加权动力学一致逆** `J̄ = M⁻¹Jᵀ(J M⁻¹ Jᵀ)⁻¹`。机身占总质量 **84.3%**，
质量高度集中，用普通伪逆的话高低优先级任务之间的惯量耦合会很明显。

**`J̇c q̇` 绝不能丢（原方案漏项）。** 滚动接触点的向心加速度为 `v²/R`：

| 速度 | `v²/R` | 相对重力 |
|---|---|---|
| 0.5 m/s | 1.56 m/s² | 0.16 g |
| 1.0 m/s | **6.25 m/s²** | **0.64 g** |
| 2.0 m/s | 25.0 m/s² | 2.55 g |

常见的 `J̇c q̇ ≈ 0` 近似在这里直接崩。MuJoCo **没有** `mj_jacDot`，两个可行办法：

1. **推荐**：把 `qacc` 置零后调 `mj_objectAcceleration`（或 `mj_rnePostConstraint`）
   取接触点的加速度，那正好就是 `J̇c q̇` 偏置项，一次调用拿到，无需差分。
2. 对 `Jc` 做一步有限差分：`(Jc(q ⊕ Δt·q̇) − Jc(q))/Δt · q̇`。注意 `q ⊕` 必须用
   `mj_integratePos`（四元数不能直接加，§8）。

### 4.3 任务优先级表（**已按 §1.5 / §1.6 重排**）

| 级 | 任务 | 维 | 执行机构 | 前馈项 | 排序理由 |
|---|---|---|---|---|---|
| **硬** | 接触一致性 `Jc q̈ + J̇c q̇ = 0` | 5 | — | `J̇c q̇`（§4.2） | 构成 `N_0`；横向为单一集中约束（§1.2） |
| **硬** | 浮动基欠驱动 | 6 | — | — | 已由 QR 分解处理 |
| **0** | MPC 接触力前馈 `τ_ff = −Jcᵀf*` 的驱动空间投影 | — | 全部 | `f*` | WBIC 式；MPC 的成果由此进入 |
| **1** | **俯仰 θ + 角速度阻尼** | 1 | 两轮同向 | `θ*, θ̇*, θ̈*` 全前馈 | 131 ms 发散；且必须压住髋的 20 N·m 扰动（§1.5） |
| **2** | **横滚 φ** | 1 | 两髋反向 | 侧向加速度引起的倾角 | 安全关键，单支撑不可控（§1.6），仅次于俯仰 |
| **3** | 偏航 ψ | 1 | 两轮反向 | **`ψ̇_ff = 0.5cos q·q̇`**（§1.3）+ scrub 符号补偿（§1.2） | 高于高度，因为高度动作会持续激励偏航误差 |
| **4** | 机身高度 z | 1 | 两髋同向 | 重力负载前馈 `mg·0.06sin q` | 性能项，非安全项；须在俯仰零空间里动作 |
| **5** | 前向速度 `v_x` | 1 | 两轮同向 | `v_x*` | **与 L1 争同一维，实际几乎拿不到权限**（见下） |
| **6** | 关节正则 + 阻尼 + 远离死点偏置（拉向 `q₀=25°`） | 余 | 全部 | — | 填满零空间防漂移；防高度/横滚增益奇异（§1.4） |

**L1 与 L5 的真相**（这是严格优先级相对 QP 加权的一个硬性后果）：

> 俯仰与 `v_x` 都只能靠"两轮同向滚"这**一维**权限。严格层级下 L1 全取、L5 全空。
> 所以 **WBC 完全无法在俯仰和速度之间做权衡，这个权衡 100% 发生在 MPC 里**。
> L5 的实际作用仅限于俯仰任务已满足（`ẍ_1*` 达成且有余量）时吃掉剩余权限。
> 这是符合轮式倒立摆物理的正确设计，但必须清楚：**调速度跟踪要去调 MPC 权重，
> 改 WBC 的 L5 增益几乎没有效果。** 这是一个非常容易浪费时间的坑。

### 4.4 任务激活与退出的平滑过渡（**原方案漏项**）

三个会导致层级结构突变的事件，都必须平滑：

| 事件 | 问题 | 处理 |
|---|---|---|
| 高度任务过死点 | `J_z → 0`，该级失效且 `N_i` 不再收缩 | 任务权重 ∝ `sin²q`，用 `smoothstep` 在 `q ∈ [3°, 8°]` 上淡入淡出 |
| 接触集变化（单轮离地） | `N_0` 维数跳变 5 → 2，`τ` 跳变 | 对 `Jc` 的行做连续加权（权重 = 归一化法向力），而不是硬增删行 |
| 冲击（落地） | 刚性接触假设失效，`J̇c q̇` 出现脉冲 | 检测 `\|f_z\|` 突变 → 20 ms 内把 L3～L6 权重降到 0.2，只保 L1/L2 |

统一实现建议：每个任务带一个 `activation ∈ [0,1]`，乘在 `ẍ_i*` 上而**不是**乘在
`J_i` 上（乘 `J_i` 会破坏 `N_i` 的投影性质，导致低优先级泄漏到高优先级）。
这是一个容易写错且症状隐蔽的细节。

## 5. 不等式约束怎么进零空间框架（核心难点）

### 5.1 力矩限：SNS（Saturation in the Null Space）

Flacco & De Luca 的算法，迭代式，无需 QP：

1. 按当前优先级解出 `τ`；
2. 找出越限执行器，**钳到限值**并作为新的等式约束加入；
3. 在被钳方向的零空间里**重解剩余任务**；
4. 若任务已不可行，引入**任务缩放因子 `s ∈ (0,1]`**，取恰好可行的最大 `s`。
   关键是这样**保持任务方向不变、只降幅值**；直接对 `τ` 做 `np.clip` 会扭曲方向
   （现有代码正是在扭曲方向）；
5. 低优先级被饱和牵连时降幅或丢弃，**绝不允许低优先级破坏高优先级**。
   这一点纯投影本来自动成立，是饱和破坏了它，SNS 就是来修这个的。

最坏迭代次数 = 执行器数 = 4，闭式、定长、可硬实时。

**本机器人的特殊性**：四个执行器的限值不同（髋 ±10，轮 ±5），且 §1.5 建议给
高度任务的髋力矩单独设 ±4 的软限。所以 SNS 要支持**分层限值**：
L1（俯仰）可用满量程 ±10，L4（高度）只能用 ±4。实现上是每个任务带自己的限值向量。

### 5.2 摩擦锥：本构型可解析化，不需要 QP

轮子的切向力就是 `f_t = τ_wheel/R`，所以摩擦锥

```
|f_t| ≤ μ·f_z      ⟺      |τ_wheel| ≤ μ·f_z·R
```

**退化成一条随法向力实时变化的力矩上限**，直接喂给 §5.1 的 SNS 当箱约束：

```
|τ_wheel,i| ≤ min( 5.0 ,  μ · f̂_z,i · 0.16 )
```

`f̂_z,i` 三源交叉验证（§2.3），取保守值。**注意：模型里没有力/力矩传感器**
（只有 gyro / accelerometer / framequat / frameangvel），所以 `f̂_z` 只能是模型
估计。仿真里可以用 `data.cfrc_ext` 或 `contact.force` 做真值对比来标定估计器，
但真机上没有这个奢侈——**估计器的精度直接决定摩擦锥约束的可信度**，这是本方案
里最脆弱的一环，建议留 20% 保守余量（`μ_eff = 0.8`）。

其余两类不等式：

| 约束 | 转化 | 处理 |
|---|---|---|
| 法向力单边性 `f_z ≥ 0` | 转成**髋力矩上限**（法向力分配由曲柄几何决定） | 解析，进 SNS |
| 横向 scrub | 无独立执行器（§1.2） | **只能事后校验 + 降低偏航任务幅值**，是唯一必须靠任务缩放的方向 |

### 5.3 奇异鲁棒与增益排程

所有伪逆用阻尼最小二乘，阻尼按各自奇异度排程。**统一排程表**（`p = sin q`）：

| 对象 | 排程 | 依据 |
|---|---|---|
| 高度任务阻尼 | ∝ `1/(p² + ε)`，`ε = 0.01` | `dz/dq = 0.06p → 0`（§1.4） |
| 高度任务 activation | ∝ `p²`，`q ∈ [3°,8°]` 淡入 | 同上 |
| 横滚回路增益 | ∝ `p` | 髋→法向力增益 ∝ `1/p`，11.5 倍变化（§1.4） |
| 偏航权限上限 | `7.5 − 5.59p` | scrub（§1.2） |
| 偏航前馈 | `0.5·cos q·q̇` | 寄生偏航（§1.3） |
| 俯仰/横滚解耦阻尼 | 按 `u` 与横向轴夹角 `atan(0.5p)` | 中行程耦合（§1.1） |
| `Q_uᵀSᵀ` 条件数 | 监控，超阈值加阻尼 | §4.1 |

注意这张表里有 `p` 和 `1/p` 同时出现——**这不是矛盾**，是 §1.4 那个互为倒数的
双重奇异的直接体现（高度权限 ∝ `p`，法向力增益 ∝ `1/p`）。

现有代码的 `kp_mid_bump = 40`（已核过恒等于 `sin²q`）就是这张表里"高度任务
activation ∝ p²"那一行的手工版本，换成 WBC 后会被自动吸收。

### 5.4 诚实的代价清单

| 相比 QP-WBC 丢掉的 | 影响 | 缓解 |
|---|---|---|
| 全局最优（多约束同时活跃时 SNS 贪心） | 极限工况性能略差，通常 <10% | 接受 |
| 约束之间无法连续权衡 | 只能靠优先级离散表达 | 把真正需要权衡的（俯仰 vs 速度）全部上移到 MPC |
| 任务缩放改变"到达时间"，与 MPC 计划不一致 | MPC 会反复规划做不到的动作 | **必须把实际 `s` 回馈给 MPC**，见下 |
| 层级内无法表达"软优先级" | 相近重要性的任务只能强排序 | L2/L3 的排序需实验确认 |

**`s` 回馈通道的具体做法**（这是实践中最容易出问题的地方，建议第一天就留）：
把每个任务的实际缩放因子 `s_i` 与饱和标志逐拍上报给 MPC；MPC 用它
(a) 收紧对应方向的约束上界（如 `s_yaw < 1` 时把 `M_z` 上界乘 `s_yaw`），
(b) 在代价里对该方向增加正则。否则会出现典型的"MPC 规划—WBC 做不到—MPC 看到
误差加大要求—更做不到"的正反馈。

### 7.1 模块规划

```

  contact.py        # 接触点/法向/μ；曲柄几何 → r_i(q)；集中横向约束的构造
  schedule.py       # §5.3 的统一增益排程表（单一真值来源，禁止各处硬编码）
  mpc/
    srbd.py         # SRBD 线性化、yaw 对齐、时变 r_i、反射惯量、惯量插值表
    qp.py           # OSQP 封装：预分配 sparsity、update-only、warm start
    mpc.py          # 50 Hz 主循环、状态预推、失败回退
  wbc/
    projection.py   # QR 消力、动力学一致逆、递归零空间、条件数监控
    tasks.py        # 任务定义（J, ẍ*, 前馈, activation, 分层限值）
    sns.py          # SNS 饱和 + 任务缩放 + s 回馈上报
    wbc.py          # 慢环 250 Hz + 快环 1 kHz（俯仰阻尼 + 饱和）
  estimation/
    attitude.py     # 四元数 EKF
    odometry.py     # 接触运动学里程计（含 ∓0.06cos q·q̇ 修正）
    contact_est.py  # 接触状态 + f̂_z 三源交叉
  fsm.py            # §2.4 的状态机

保留：geometry.py（曲柄 L(q) 与反解）；lqr.py（作为 §3.4 的应急回退，不要删）
删除：controllers.py 的 WheelTorqueMixer / AdaptiveHipPD（被 WBC 吸收）
```

### 7.2 里程碑

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **M0** | 模型接口 + 数值核验 §1 的六条 | 六条与解析一致；`u` 偏转 26.6°；秩 5 |
| **M1** | 状态估计升级 + **工作点移到 `q₀=25°`**（§1.4） | `v_x` 稳态偏差 <0.02 m/s；现有 LQR 在新工作点仍能站稳 |
| **M2** | **WBC 单独跑，上层仍用现有 LQR 喂参考** | 平地不差于现状；实测 WBC 频率（§2.2）；零空间性质通过验证（§7.4） |
| **M3** | MPC 接入替换上层 | 速度阶跃的非最小相位过冲明显减小；对照 §6 的 LQR 基线 |
| **M4** | 升降腿联调 | **全行程升降过程中偏航漂移 <3°**（§1.3 的直接验收项）；俯仰扰动 <2°（§1.5） |
| **M5** | 偏航 + 粗糙地形 | 中行程转弯不失控（§1.2）；单轮离地能恢复（§1.6） |
| **M6** | 极限工况 | 打滑时任务缩放生效、`s` 回馈闭合、不发散 |

**M2 是最关键的一步**：WBC 与 MPC 必须解耦调试。两层同时上线，出问题无法定位。
**M1 的工作点迁移应该在动架构之前做完**，因为它会改变所有增益的标称值。

### 7.3 M0 的数值核验方法

- `mj_jac` 取两接触点雅可比 → 拼 `Jc` → 扫 `q` 查 `rank` 与零空间维数；
- 构造地面力 → 机身力扳手的映射矩阵，查零空间方向是否 `∥ (0.12sin q, 0.24, 0)`，
  并记录它与横向轴的夹角是否在 `q=π/2` 达到 26.57°；
- 扫 `q` 记录 `Q_uᵀSᵀ` 与各级 `J_i N_{i−1}` 的条件数 → 定 §5.3 的阻尼参数；
- 验证 §1.3：给定 `q̇`，固定其余任务，看自由演化的 `ψ̇` 是否为 `0.5cos q·q̇`；
- 验证 §1.5：施加纯髋力矩阶跃，测机身俯仰角加速度是否 ≈ `τ_hip/I_yy`；
- 验证 §1.6：人为抬起一侧轮，确认横滚不可控（应当发散）。

**已知陷阱**：在 `q > 0` 姿态下用新建 `MjData` 做切点落地放置时会出现 `ncon = 0`
（此前调查已确认）。核验脚本必须先让接触真正建立（推进若干步，或显式给 1e-4 级
穿透）再取雅可比，否则 `Jc` 是空的、所有秩结论都是假的。

### 7.4 验证清单（每项都能独立定位一类 bug）

| 检查 | 方法 | 通过标准 |
|---|---|---|
| `Jc` 正确 | 稳态滚动时算 `Jc q̇` | ≈ 0（<1e-6） |
| `J̇c q̇` 正确 | `mj_objectAcceleration` 结果 vs 有限差分 | 相对误差 <1% |
| QR 消力正确 | 回代的 `f` vs `data.cfrc_ext` / `contact.force` | <1e-6 |
| **零空间性质** | 开启/关闭 L6 后比较 `‖J_1 q̈ − ẍ_1*‖` | **完全不变**（这是零空间法唯一的核心承诺） |
| activation 实现正确 | 淡入淡出高度任务，同时监控 L1 残差 | L1 残差不受影响（若受影响，说明错乘在 `J_i` 上，§4.4） |
| SNS 正确 | 构造必然饱和的场景 | `τ` 方向与未饱和解同向，只幅值变小 |
| **MPC 单独正确性** | 关掉 WBC，用 `data.xfrc_applied` 直接施加 MPC 的 `f*` | 能稳定 → MPC 无误，问题在 WBC；不能 → 反之 |
| 摩擦锥优雅退化 | 逐步把 `μ` 从 1.0 降到 0.3 | 性能下降但不发散 |
| 快慢环一致性 | 慢环频率从 1000 降到 250 Hz | 俯仰 RMS 增幅 <20% |

`xfrc_applied` 那一条是整个调试链里最有价值的工具：它把 MPC 与 WBC 的正确性
彻底解耦，强烈建议在 M3 之前就把这个测试脚手架搭好。

## 8. MuJoCo 实现陷阱清单

这些都是本模型的具体情况，逐条确认过 XML。

| # | 陷阱 | 具体情况 | 处理 |
|---|---|---|---|
| 1 | **`nq ≠ nv`** | freejoint 用四元数：`nq = 11`，`nv = 10` | 所有矩阵按 `nv` 维；位置更新必须用 `mj_integratePos`，禁止 `qpos += Δt·qvel` |
| 2 | **freejoint 速度的坐标系** | MuJoCo 里 `qvel[0:3]` 为世界系线速度，`qvel[3:6]` 为**机体系**角速度（需在 M0 用一次数值实验确认） | 估计器与 MPC 的角速度必须统一到同一坐标系，这是经典 bug 来源 |
| 3 | **没有 `mj_jacDot`** | MuJoCo 不提供雅可比导数 | 用 `mj_objectAcceleration`（`qacc=0`）取偏置项（§4.2） |
| 4 | **没有力传感器** | 传感器只有 `imu_gyro` / `imu_acc` / `imu_quat` / `imu_angvel` | `f̂_z` 只能模型估计；仿真里可用 `cfrc_ext` 标定但真机没有（§5.2） |
| 5 | **机身网格会触地** | `base_link_visual_0` 是 `contype=1 conaffinity=1`；腿与轮网格 `contype=0` | 低姿态 + 大俯仰时机身可能撞地，需几何扫查出 `θ_max(z)` 约束（§3.2） |
| 6 | **四关节全部 `limited="false"`** | 曲柄可无限旋转，`geometry.py` 的 `arccos` 夹取到 `[0,π]` 会在越界后失去双射 | 软限位 `q ∈ [5°,175°]` + 零空间排斥项（§3.2 / L6） |
| 7 | **`condim=3`** | 接触无扭转摩擦、无滚阻 | 偏航只能靠差动切向力；单点接触无侧倾抗力（§1.6） |
| 8 | **圆柱-平面单点接触** | 实测 `ncon=2`（每轮 1 点），半宽仅 0.01 m | 按点接触 3 维力建模是正确的；但接触点沿轮缘移动，`Jc` 必须每拍重算 |
| 9 | **`ncon=0` 陷阱** | 新建 `MjData` 在 `q>0` 的切点放置姿态下无接触（已确认） | 核验/初始化脚本先建立接触（§7.3） |
| 10 | **接触排除不完整** | 仅排除 `base_link↔joint2_Link` 与 `↔joint4_Link` | `joint1_Link`/`joint3_Link` 的 `contype=0` 使其不参与碰撞，当前无自碰风险；改模型时需复查 |
| 11 | **`timestep=0.001` 与软接触** | 实测穿透 ~5e-14，接触足够刚 | 刚性接触假设成立；但冲击瞬间仍需 §4.4 的降权保护 |
| 12 | **纯力矩源无速度限** | `gear=1` 的 `<motor>` 无 back-EMF 模型 | 仿真里轮速可无限增长；真机有速度限，建议在 MPC 里加 `\|ω_wheel\| ≤ ω_max` 软约束，避免算法依赖仿真里不存在的速度余量 |
