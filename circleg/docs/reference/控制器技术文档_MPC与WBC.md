# 控制器（MPC + WBC）设计文档

本文件描述上层控制器的**设计思路与依据**：为什么分成 MPC 与 WBC 两层、MPC 为什么用 8 状态模型、
WBC 为什么必须把接触一致性写成硬等式、以及各处的取舍代价。

面向需要复刻或改造该控制器的工程师。具体函数实现以源码为准。

代码基线：`0e91281`。适用范围：`Algorithm/mpc/`、`Algorithm/wbc/`、`wheel_leg_mujoco/gbc_mpc_wbc/`。

---

## 一、要解决的问题

### 1.1 这台机器人的平衡手段有两个，而且互相耦合

轮腿机器人在双轮着地时，前后方向的质心位置有两个成对的手段：

| 手段 | 物理通道 | 代价 |
|---|---|---|
| 摆腿（曲柄转角） | 髋力矩撬动地面，把质心相对接地点前后移动 | 腿角行程有限，且腿角过大时小腿会碰到地面 |
| 俯仰（机体倾角） | 质心随倾角前后移动 | 倾角越大，落地/站立越不安全 |

两者共同产生同一个结果：**质心相对接地点的水平偏移**。用倒立摆关系表述就是

```
Δ = z_com * a / g          （a 为规划的前向加速度）
```

这个偏移必须按某种比例分给"摆腿"和"俯仰"。比例分错了会有两个后果：
腿摆太多，小腿离地间隙不够；倾角太大，姿态余量不够。

所以这不是一个"把误差压到零"的调节问题，而是**一个带约束的分配问题**。
这就是需要 MPC 的根本原因：只有它能把"分配比例"与"硬约束"放在同一个优化里。

### 1.2 为什么还需要第二层

MPC 用的是一个降阶模型（8 个状态、3 个输入），它**不足以算出六个执行器的力矩**：
腿是闭链机构，力与力矩的对应依赖完整浮基动力学的质量矩阵与雅可比。
同时，这一拍要同时满足的事有五六件（俯仰、腿角、速度、腿长、偏航、横滚），
每一件都想被满足，但执行器只有六个。

所以第二层（WBC）要回答的是：**在完整动力学与接触约束下，这一拍六个执行器怎么分配最合理。**
两层分工因此是：

- **MPC：未来 0.5 s 内，质心该往哪走、姿态该保持多少、摆腿与俯仰各分多少**（带约束的规划）；
- **WBC：这一拍，六个执行器出多少力，才能让所有任务同时尽量满足且物理可实现**（带约束的分配）。

## 二、总体架构

```
  指令（速度/偏航）
        │
        ▼
  规划器 planner：斜坡 + jerk 限幅 ──► 参考位置/速度/加速度
        │
        ▼
  MPC（50 Hz）：8 状态降阶模型 + 约束 QP
        │  输出：参考状态（位置/速度/俯仰/偏航/腿角）与参考加速度
        ▼
  WBC（1 kHz）：完整浮基动力学 + 接触约束 + 任务分配
        │  输出：六个执行器力矩
        ▼
  执行器
```

三条设计边界：

1. **MPC 不给力矩。** 它的输出是"参考状态"与"参考加速度"，力矩由 WBC 从任务解出来。
   理由见 1.2，也见跳跃模块文档 2.4（上游算力、下游算力矩的中间层必须有明确消费者）。
2. **WBC 的核心算法不吃仿真。** `Algorithm/wbc/` 只接受矩阵（质量矩阵、动力学偏置、
   接触雅可比及其偏置、任务行），不 import MuJoCo。取矩阵的适配在仿真侧完成。
   这样算法核心可以用解析构造的模型做单元测试，也便于换平台。
3. **增益排程只有一处来源。** 所有随构型变化的增益（高度任务阻尼、横滚增益、偏航权限、
   俯仰横滚解耦阻尼）集中在排程表里，禁止在各任务里再写一套（见 8.5）。

## 三、MPC 的模型：为什么用 8 状态而不是 6 状态

这是本控制器最重要的一条设计选择，单独一节。

### 3.1 两种降阶模型

| 模型 | 状态数 | 状态 | 输入 |
|---|---|---|---|
| `held_leg`（6 状态） | 6 | 位置、速度、俯仰、俯仰角速度、偏航、偏航角速度 | 轮力 ×2 |
| `leg_input`（8 状态） | 8 | 上述 6 个 + **共模腿角 φ_c、共模腿角速度** | 轮力 ×2 + **共模髋力矩 τ_c** |

`held_leg` 的假设是"腿角固定不动"，腿被当成一根刚性连杆。
`leg_input` 把腿角当成一个**可以被规划的变量**，并给它一个执行器（髋力矩）。

### 3.2 6 状态丢掉了什么

丢掉的正是 1.1 表里的第一行：**摆腿这个水平执行器**。

在 6 状态模型里，前后方向的唯一手段是轮力；而真实机器人上，质心前后移动主要靠摆腿撬地。
两者不是同一件事：

- 6 状态模型里，轮力对前向加速度的权限是**直接且为正**的（因为腿被钉死，轮子推着整个刚体走）；
- 8 状态模型里，腿角自由后，轮力对前向加速度的**直接权限很小、而且符号为负**——腿会自由摆动，
  把轮子的推力"泄"成了腿角运动，弱化了耦合。

这个差别不是数值问题，而是模型结构问题：**腿角固定时算出来的"轮力很有效"，在真实机器人上不成立。**
用 6 状态模型规划出来的加速度，执行时会被腿的摆动吃掉一部分，规划与实际不一致。

### 3.3 8 状态换来了什么

腿角进入状态后，MPC 可以显式回答"这次减速/加速，靠摆腿还是靠俯仰"，并且：

- 摆腿量有**硬上限**（共模腿角状态约束），保证小腿不磕地；
- 超出的部分自动落到俯仰上（俯仰也有硬上限）；
- 两者的分配在优化里自动完成，不需要人工给一个比例。

设计意图可以用一句话概括：**腿只承担一部分质心偏移（限幅封顶），剩下的交给俯仰——小摆腿 + 小俯仰共同平衡。**

实测（同一组工况，只改腿角限幅）：

| 共模腿角限幅 | 腿角峰值 | 俯仰峰值 | 位移收敛时间 |
|---|---|---|---|
| 0.15 | 150 mrad | 0.69° | 1.17 s |
| 0.25 | 250 mrad | 0.28° | 0.79 s |

这组数字说明的不是"哪个更好"，而是**限幅确实在起分配作用**：腿放开一点，俯仰就小一点、收敛快一点。
这种"可调的分工"在 6 状态模型里根本不存在——那里没有腿角这个变量。

### 3.4 8 状态的三个代价

**代价一：需要工作点配平（trim）。**
腿角保持在非零位置时，机构本身不平衡，需要一个**常值髋力矩**去顶住。
所以模型不能直接在"腿角 0、髋力矩 0"处线性化，必须先解一个配平问题：
在零轮力条件下求 (θ_trim, τ_c_trim)，使俯仰角加速度与腿角加速度同时为零。
这个配平点就是模型的线性化点，也是姿态参考的零点附近。配平解不出来（不收敛）就应当报错，
不能悄悄退回零。

**代价二：必须断言符号。**
`∂v̇/∂φ_c > 0`（正方向的腿角增量使质心前移）这条约定被上游多处依赖：ZMP 曲柄参考、
摆腿前馈、能力表插值方向。因此模型构建时必须显式断言，否则符号反了也会静默通过。
同理还要断言偏航角加速度对左右轮力的符号、共模髋力矩对腿角加速度有权限。

**代价三：摆腿的等效半径必须从模型量。**
摆腿移动质心的杠杆不是腿长。ZMP 公式里的 `r_crank` 定义为
`d(质心 x − 接地点 x) / d(δφ_c)`，必须在模型里差分量出来（标称腿长 0.28 m 时实测约 0.21 m）。
**不能用腿长代替**：用腿长会把摆腿的权限高估约三成，ZMP 参考随之偏大。

### 3.5 8 状态与 ZMP 参考是绑定的

ZMP 参考要写的是"曲柄该摆多少"，而曲柄角在 6 状态模型里根本不是一个变量。
所以"ZMP 参考"与"8 状态模型"必须同时成立，不能单独打开其中一个：
模型状态数不足 8 时，ZMP 参考会被强制关闭（而不是给一个没有意义的输出）。

ZMP 的具体推导、分配与观测方法见第六章。

## 四、MPC 的建模推导

### 4.1 起点：完整浮基动力学 + 接触约束

MPC 的模型不是"假设一个倒立摆"，而是从带接触约束的完整浮基动力学出发，再做系统性降阶：

```
M(q) q̈ + h(q, q̇) = Sᵀ τ + J_c ᵀ f          （浮基动力学，f 为两轮法向/纵向力）
J_c q̈ + b_c(q, q̇) = 0                       （接触一致性：轮子不滑、不穿透）
```

两条式子决定了后面所有的操作：**降阶必须保留"能被执行器影响、且能被观测"的方向，
并且降阶模型必须仍然满足这两条式子的投影形式。**

### 4.2 降阶的第一步：删哪些状态（权限账本）

降阶不是"凭经验挑六个量"，而是按每个自由度的**权限**逐个判断：

| 保留的状态 | 为什么保留 |
|---|---|
| 位置 `s`、速度 `v` | 任务目标本身就是它；轮力可直接驱动 |
| 俯仰 `pitch`、`pitch_rate` | 是摔车的直接指标；轮力矩与髋力矩都能影响 |
| 偏航 `yaw`、`yaw_rate` | 左右轮差动是唯一的驱动手段，必须建模 |

| 删除的状态 | 为什么删 |
|---|---|
| 横向 `p_y`、`v_y` | **横向没有执行器**。它是非完整约束下由偏航决定的从动量，不是可独立规划的状态 |
| 高度 `p_z`、`v_z` | 机身高度由**曲柄位置源**直接给定，不是靠法向力积分出来的；交给腿部规划与 WBC |
| 横滚 `roll`、`roll_rate` | 权限是**瞬时**的（左右差动法向力），单支撑时权限直接为零；用 MPC 预测它没有意义 |

最后一条尤其重要：横滚"能控但只能瞬时控"，放进 MPC 会让规划器规划出一个它无法持续维持的动作。
横滚因此下放给 WBC，用即时反馈处理；而在 WBC 里通过**两腿单独建模**获得了第二个、
可持续的执行手段（差动腿长），详见 8.4。

### 4.3 降阶的第二步：把输入压到两个

决策量取两轮的纵向地面力 `u = [f_R, f_L]`（N）。于是所有约束都退化成**逐轮箱型约束**：

```
净驱动力   = f_R + f_L
偏航力矩   = half_track * (f_R - f_L)
电机限幅   = |f_i| <= τ_max / R              （力与力矩的换算）
摩擦锥     = |f_i| <= μ * f_z,i              （同一行的箱型约束）
```

这一步是整个 MPC 设计的关键简化：如果不以"力"为决策量，电机限幅与摩擦锥都会变成
决策变量的耦合约束，QP 的规模与病态程度都会上升。以力为决策量后，QP 只有 2N 个变量。

### 4.4 扩展到 8 状态

在"6 状态 + 2 输入"的基础上加入共模腿角与髋力矩（理由见第三节），状态变为

```
x = [s, v, pitch, pitch_rate, yaw, yaw_rate, φ_c, φ̇_c]      （8）
u = [f_R, f_L, τ_c]                                          （3）
```

**建模方式与 6 状态不同**，这一点必须写清楚，因为代码里两条路径并存：

- 6 状态的纵向/俯仰子块直接**复用实测线性化**（在 MuJoCo 接触位形上，已把滚动约束、
  接触雅可比、自由髋关节都包含进去了），比手推简化模型可靠；
- 8 状态则是在**配平点对"接触约束下的完整动力学"做中心差分线性化**：

```
1) 速度映射：约束方向速度置零（纯滚动），自由方向速度由降阶状态给定
2) 给定 (x, u)，解带接触约束的动力学（KKT）得到 q̈
3) 取自由行得到降阶加速度 （ẋ 的导数分量）
4) 对 8 个状态、3 个输入逐列中心差分 -> A(8×8)、B(8×3)
5) 仿射项：配平点处的残差，作为常值漂移
```

配平点必须先解出来：在零轮力条件下求 `(θ_trim, τ_c_trim)` 使俯仰角加速度与腿角加速度同时为零。
配平不收敛就报错，不允许退回零工作点（零工作点下腿被"吊着"，模型与实际不符）。

### 4.5 离散化与缩写

```
x[k+1] = A_d x[k] + B_d u[k] + w_d
```

`A_d、B_d` 由矩阵指数离散，`w_d` 是常值漂移项的离散化。然后把中间状态**消去**，
让决策变量只剩 N 步的力（缩写 / condensed 形式）：问题规模固定，
每拍只需更新向量，OSQP 可以复用矩阵分解。

### 4.6 代价与约束

```
J = Σ_k (x_k − x_ref,k)ᵀ Q (x_k − x_ref,k) + Σ_k u_kᵀ R u_k
s.t.  A_d, B_d 动力学
      pitch、速度、共模腿角的状态带           （硬约束）
      力/髋力矩的上下界                       （硬约束）
      法向力 >= 下限                          （硬约束）
```

**俯仰为什么是硬约束而不是权重**：权重可以被更大的任务压过去，硬约束不能。
俯仰限幅是安全边界，它不应该在"追速度"时被牺牲。同理腿角限幅是间隙边界。

**权重与限值的分工**：权重决定"多想要"，约束决定"绝对不许"。把安全量写进权重，
迟早会遇到"某个工况下被别的任务压过去"的问题。

### 4.7 已知建模误差（必须写在文档里）

| 项 | 现状与影响 |
|---|---|
| 6 状态线性化时髋力矩取 0 | 相当于髋自由；真正上 WBC 后髋被握住，等效质量变大、不稳定极点会移动。需要带髋约束重测 |
| 力与力矩的换算 | 实测输入是"差动模式单轮力矩"，对应净地面力 `2u/R`；换算系数错一个因子会直接放大/缩小加速度能力 |
| 8 状态的配平点 | 只在标称腿长处成立；腿长变化后配平点与线性化点都会偏，这是"跳跃期必须隔离 MPC"的原因之一（见跳跃模块文档 5.2） |

## 五、有速度输入下的控制

这一章讲"给一个速度指令，控制器怎么把它变成可执行的参考"。与 ZMP 点规划分开写，
因为两者的驱动关系是单向的：**速度指令产生规划加速度，规划加速度才驱动 ZMP 偏移**。

### 5.1 输入只接受速度与偏航角速度

`MotionCommand` 只接受 `velocity` 与 `yaw_rate`。传入绝对位置或绝对朝向会被直接拒绝。

理由：绝对位置输入与实测位置是同一件事的两种说法。两者同时存在时，
"参考说我在 A、实测说我在 B"会变成一个人为的正反馈源（参考把机器人往 A 拉，
而机器人实际在 B，误差永远不为零）。位置只能由速度积分得到，不能由外部指定。

### 5.2 处理链

| 级 | 处理 | 为什么在这一级 |
|---|---|---|
| 1 | 死区（速度 0.005 m/s、偏航 0.01 rad/s） | 指令噪声不该产生运动 |
| 2 | 限幅（max_speed、max_yaw_rate） | 指令可以超范围，参考不能 |
| 3 | 斜坡（加速度/制动力限值） | 参考加速度必须可被机构实现 |
| 4 | jerk 限幅 | 加速度阶跃会让 MPC 把它放大成姿态需求 |
| 5 | 能力缩放 capability | 参考不能比当前执行能力更激进 |
| 6 | 保持/停机判据 | "停住"是一个状态，不是一个速度值 |

每一级都有独立存在的理由，不能合并：死区是抗噪，限幅是安全，斜坡是可行性，
jerk 是平滑性，能力缩放是让参考服从执行器现状。

### 5.3 为什么必须有 jerk 限幅

只限加速度是不够的：加速度从 0 直接变成满值，参考轨迹里会出现一个阶跃，
MPC 的预测会把"加速度突变"理解成"质心偏移要快速变化"，于是规划出一次姿态调整；
等加速度再突变回来，又要反向调整一次。表现出来就是起步/停车时机体"点一下头"。

因此起步与刹车都按 jerk 爬升：加速度在 `jerk_ramp_time` 内从 0 升到限值。
刹车可以单独给一个 jerk 上限（`brake_jerk_ramp_time`），因为刹车的姿态风险比起步高。

### 5.4 加速度限值从能力表反算，不手填

规划器的加速度上限不是人工给的数，而是从模型的**稳态能力表**反算，并对齐腿角限幅：

- 能力表给出"某个前向加速度需要多大的共模腿角（俯仰为 0 的稳态族）"；
- 规划限值取腿角限幅处对应的加速度；
- 起步取该值的 85%，刹车与零指令恢复取 95%（两者风险不同）。

手填的问题在于：手填的加速度上限与腿角限幅之间没有一致性保证，
常常出现"规划允许、模型达不到腿角"，然后由 WBC 硬顶，表现为腿角贴限位。

### 5.5 速度规划期：四个模式与逐相限值

速度参考不是"把一个目标速度交给 MPC"，而是由规划器先跑出一条**参考轨迹**。
规划器内部有四个模式，进入条件与处理方式都不同：

| 模式 | 进入条件 | 位置参考 | 速度参考 |
|---|---|---|---|
| RESET | 未使能 / 指令过期 / 无接触 | 冻结在当前参考位置 | 0（输出常值参考） |
| DRIVE | 目标速度或目标偏航率非零 | **每拍跟随实测位置** | 斜坡（S 曲线）跟踪指令 |
| BRAKE | 曾经有指令，现在指令归零 | 制动期**只重锚位置**，保留斜坡速度与加速度 | 从当前速度刹到 0 |
| HOLD | 停车判据连续满足 `hold_dwell` | 不再跟随（`reset_position=False`） | 0 |

三处设计要点：

**(a) DRIVE 期位置参考跟随实测。** 加速/减速过程中，机体必然滞后于参考位置。
如果位置目标固定不动，这个滞后会被当成位置误差，MPC 会规划出额外的前倾去"追"它——
而那个滞后本来就是加速的物理结果。因此驱动期位置目标跟随实测，**只让速度参考承担加速度意图**。

**(b) BRAKE 期只重锚位置、不动速度。** 刹车过程中位置同样会滞后，所以也要重锚；
但速度必须继续按斜坡往下走，否则刹车会被"重锚"打断，变成一路滑行。

**(c) HOLD 需要"停稳"的判据，不是一个速度值。**
停车判据同时要求：速度与偏航率接近零、俯仰接近平衡角、俯仰角速度很小、两轮都有接触且不打滑，
**并且连续满足一段时间**（`hold_dwell`）。只在速度为 0 那一刻判定"停住"会把
"速度过零的瞬间"误当成停车。

**逐相限值**：驱动用较缓的起步限值（避免起步就产生明显前倾），零指令的站定与受扰恢复用另一组
（更激进，因为此时没有"前倾换取加速度"的需求）；刹车可以单独给 jerk 上限，因为刹车阶段的
姿态风险比起步高。

**规划期在本拍内是外推的。** 规划器用同一个斜坡函数把参考向前推满整个 MPC 视界
（25 步 × 0.02 s = 0.5 s），MPC 看到的是"斜坡未来会怎么走"，而不是一个常数目标。
这也是 ZMP 偏移参考能够提前收回的前提（见 6.4）。

### 5.6 位置参考锚定

位置参考是一个**积分量**（由速度积分得到），它必须与实测保持一种可控的关系。
锚定就是"在明确的时刻把参考位置对齐到实测"，规则如下：

| 时刻 | 锚定内容 | 理由 |
|---|---|---|
| 首次使能 | 位置、偏航、速度全部取自实测 | 冷启动没有别的信息来源 |
| 暂停后恢复（接触稳定驻留后） | 同首次使能 | 暂停期间参考不积分，恢复时必须对齐 |
| 偏航误差超限 | **只重锚偏航**，位置不动 | 朝向已经错了要重来；位置误差可能只是正常前进过程 |
| 停车捕获（HOLD） | 位置不重锚（`reset_position=False`） | 纯速度保持不能把位置目标挪走 |
| 落地重锚（跳跃） | 位置、速度都重锚 | 落地是坐标系重建，必须从实测重新起算 |

三条必须遵守的规则：

**(a) 参考速度只能来自指令，不能来自实测。** 这是硬规则：实测回灌会形成正反馈
（实测往前 → 参考往前 → 更往前）。锚定时"位置取自实测、速度取自指令"是刻意的组合。

**(b) 制动期锚定位置时，必须保留斜坡的速度与加速度。** 否则刹车被打断。
但这条有一个前提条件：**必须确认"这次减速是执行指令产生的"**（`commanded_motion` 为真）。
如果那个标志丢了，制动分支会跳过重锚，位置目标就冻结在当时的实测位置，
随后机体带着速度继续走 → 位置误差建立 → 控制器回拉 → 表现为**落地/停车后向后回退**。
这是一个真实发生过的缺陷。

**(c) 冻结参考时必须同时记录"续接点"。** 跳跃期参考会被冻结（不推进），
冻结期间重锚要改用实测速度重新播种，而不能用冻结前的旧速度继续积分。
但这条与 (a) 不冲突：(a) 说的是**稳态下的速度参考来源**，(c) 说的是**重锚时刻的初值**。

### 5.7 能力缩放：参考要服从执行器现状

规划器内部维护一个 0~1 的能力因子：

| 触发 | 处理 |
|---|---|
| 轮子打滑 | 直接降到 0 |
| 部分轮脱接触 / 残余误差超限且持续 | 逐步降到 0.25 |
| 恢复正常 | 按固定速率恢复（不阶跃回 1） |

理由：参考是对"我想要什么"的描述，它必须随"我现在能做到什么"收缩。
一个不收缩的参考会让控制器长期工作在饱和边缘，误差全部堆在 WBC 里。

### 5.8 暂停期输出什么，以及恢复的门槛

暂停的三种触发见 5.5 的 RESET 行。这里只写暂停期**输出什么**：

- 位置：冻结在当前参考位置（不是实测位置）；
- 速度与加速度：全零；
- 俯仰：取平衡角。

之所以输出"冻结的参考位置"而不是"跟随实测"，是因为暂停意味着控制权已经不在参考手里
（离地、未使能），此时让参考跟着实测走会把飞行的位移写进参考，恢复时被当成"我已经在这了"。

恢复的门槛是**稳定接触驻留一段时间**（`touchdown_dwell`）之后才锚定，
锚定规则见 5.6。与跳跃模块的落地重锚是同一套思路：
**恢复控制之前先把参考与实测对齐，不能带着一个过期参考重新启动。**

### 5.9 跟踪误差保护

偏航参考与实测的偏差超过 `yaw_error_limit` 时，重锚偏航（位置不重锚）。
理由：偏航的误差是"朝向已经错了"，再追下去会绕圈；位置误差则可能是正常的前进过程。

### 5.10 与 ZMP 的关系

速度指令只产生一件事：**规划加速度**。ZMP 偏移由这个加速度驱动（见第六章）。

这条关系解释了两个常见困惑：

1. 站着不动时 ZMP 曲柄输出为 0 —— 因为没有规划加速度，不是"ZMP 没生效"；
2. 停住时偏移要"提前收回"（`zmp_lead`）—— 否则速度归零后偏移还在，会表现为停住后机体回弹一下。

## 六、ZMP 点规划

### 6.1 它是什么、不是什么

ZMP 点规划**不是一个控制回路**，而是参考生成的一部分：把"质心相对接地点的水平偏移"
作为中间量算出来，再分配到俯仰与曲柄两个具体通道上。

它不改任何增益、不引入反馈，输出只是"参考状态里的俯仰角与腿角"。

### 6.2 推导：从质心动力学到偏移参考

把质心相对接地点的偏移记作 `Δ`，高度记作 `z`。对绕接地点的力矩平衡做近似：

```
m ẍ · z = m g · Δ        ⇒        Δ = z · ẍ / g
```

也就是：**想要一个前向加速度 `a`，质心就必须先相对接地点偏出去 `Δ = z·a/g`。**
这就是"零矩点"的直觉：支撑点要落在"质心 + 惯性力"的合力作用线上。

这里 `a` 取的是**规划加速度**（规划器的输出），不是实测加速度，也不是位置误差。

### 6.3 把 Δ 分配给两个通道

偏移有两个来源，几何关系不同：

```
俯仰：  Δ_tilt  = z · sinθ                      （机体倾斜，质心随倾角移动）
曲柄：  Δ_crank = r_crank · sin q_c             （摆腿，质心随机体相对接地点移动）
```

于是给定分配比例 `split`：

```
Δ_tilt  = (1 − split) · Δ
Δ_crank = split · Δ
θ_ref   = asin(Δ_tilt  / z)          = asin((1 − split)·a/g)      限幅到 15°
q_c_ref = asin(Δ_crank / r_crank)     = asin(split·a/(g·r_crank))  限幅到 0.9×腿角限幅
```

两个通道的限幅来自不同约束：俯仰限幅是姿态安全（15°），
曲柄限幅是小腿离地间隙（0.9 倍共模腿角限幅，留 10% 余量）。

`split = 1` 表示全部交给曲柄（俯仰参考严格为 0），`split = 0` 表示全交给俯仰。

**`r_crank` 必须从模型量出来，不能用腿长代替。** 它是
`d(质心 x − 接地点 x)/d(δφ_c)`，标称腿长 0.28 m 时实测约 0.21 m。
用腿长代替会把摆腿权限高估约三成，偏移参考随之偏大。

### 6.4 三个实现细节，缺一不可

**(a) 提前量 `zmp_lead`。** 把加速度序列向前挪若干步再算偏移。
目的是让偏移参考在速度归零之前就开始收回，否则停住瞬间偏移还在，机体要回弹一下。

**(b) 逐节点速率限制。** 偏移参考不是一次写入，而是沿视界逐节点限速推进，
并且**跨拍连续**（上一拍推进到的位置作为这一拍的起点）。
没有这一条，每拍都会从 0 重新起步，等于每拍给一次阶跃。

**(c) 写两个通道、四行参考。** 俯仰角参考与俯仰角速度参考（差分）、
腿角参考与腿角速度参考（差分）都要写。只写角度不写角速度，PD 的速度项会一直在对抗一个不存在的速度。

### 6.5 限幅与饱和

| 量 | 限幅 | 依据 |
|---|---|---|
| 俯仰偏移参考 | 15° | 姿态安全余量 |
| 曲柄偏移参考 | 0.9 × 共模腿角限幅 | 小腿离地间隙，留 10% |
| 俯仰参考变化率 | 1 rad/s | 避免参考阶跃 |
| 曲柄参考变化率 | 3 rad/s | 同上 |

一旦算出的偏移超过限幅，就进入饱和：**参考停在限幅上，而不是继续增长**。
这意味着"加速度再大也不会让参考更大"，超出部分是规划器应当自己限制住的。

### 6.6 观测口径：不要看参考状态的第 7 列

参考状态数组里腿角那一列（第 7 列，索引 6）在 6 状态模型下是**补零的占位列**，
它**永远为 0**，与曲柄参考无关。

真正的输出在控制器内部：`last_theta_ff` 与 `last_crank_ff`（本拍写进参考的实际值）。
判断"ZMP 有没有在动"必须看这两个量。这一条曾经导致一整轮实验得出"ZMP 没工作"的错误结论。

### 6.7 什么时候它是 0，以及为什么

偏移由规划加速度驱动，所以：

| 工况 | 规划加速度 | ZMP 输出 |
|---|---|---|
| 站立不动 | 0 | 0 |
| 位置参考完全跟随实测（落地恢复段） | ≈0 | ≈0 |
| 加速/减速行驶 | 非 0 | 跟随（曲柄可能饱和） |
| 落地后往后滚 | 刹车需求（正加速度） | **恒为正**（刹车副产品） |

最后一行是一条实测结论：落地后机体速度为负，规划器的第一优先级是刹车，
刹车必然产生正向加速度，于是曲柄恒为正、方向不受输入控制。
所以"用 ZMP 主动前探/后探"在落地窗口内不成立——那里的 ZMP 输出是刹车的副产品，
不是可以被指令选择的动作。

### 6.8 与 8 状态模型的绑定

曲柄角只在 8 状态模型里是状态变量，所以 ZMP 参考只在 8 状态模型下才有意义。
模型状态数不足 8 时应当关闭 ZMP 参考，而不是写入一个没有对应状态的列。

## 七、MPC 的约束与限值

| 约束 | 值 | 类型 | 来源与理由 |
|---|---|---|---|
| 俯仰角 | 0.785 rad（45°） | 硬约束（状态带） | 用户指定：放开可用俯仰幅度以换取制动能力。注意这是硬约束，调权重无法突破 |
| 共模腿角 | 0.55 rad | 硬约束（状态带） | 模型可信范围上限；同时是小腿离地间隙的间接保证 |
| 髋力矩 | 10 N·m | 输入上下界 | 对应执行器实际能力 |
| 轮力矩 | 5 N·m | 输入上下界 | 同上 |
| 法向力 | ≥ 2 N | 单边约束 | 不能拉地面；下限不是 0，是为了留出数值余量 |
| 偏航力矩 | `7.5 − 5.59·p` | 随构型变化的权限上限 | scrub 库仑力矩会吃掉偏航权限，p = sin(髋角) |
| 速度状态带 | 3.0 m/s | 硬约束（状态带） | 与最大指令速度配套 |

求解：OSQP。三种失败处理：

1. **条件数报警**（Hessian 条件数超过 1e6）——只报警，不改变解；
2. **连续失败计数**（默认 3 拍）——先走兜底通路，超过阈值置位降级标志，由上层切回纯 LQR；
3. **状态预推**——用上一拍的解把状态向前推"估计延迟 + 求解耗时"，再作为本拍的初值。
   补偿量默认为 0（关闭），开启后必须与实测延迟一致，否则补偿本身就是新的偏差源。

## 八、WBC 的设计

### 8.1 定位

WBC 是"这一拍的分配器"，输入是完整浮基动力学的各个块与一张任务表，输出是六个执行器力矩。
它的三条不变量：

1. **动力学等式必须成立**：`M q̈ + h = Sᵀ τ + J_cᵀ f`。不能先解最小二乘力矩再回代——
   那样得到的 τ 在接触方向上与 f 不自洽。
2. **接触力不是自由变量**：必须有接触一致性等式 `J_c q̈ + bias = 0`。
   没有这条约束，求解器可以把 τ 和 f 任意组合来"满足"任务，解在真实物理中不可实现。
3. **法向力非负**：不能拉地面。

### 8.2 建模推导

#### (1) 起点与两条不变量

与 MPC 同一组方程，但**不降阶**：这里的 `q` 是完整浮基位形（本项目 nv = 20，执行器 6 个）。

```
M q̈ + h = Sᵀ τ + J_c ᵀ f          （M: nv×nv，S: nv×6，J_c: nc×nv，f: nc）
J_c q̈ + b_c = 0
```

两条不变量：动力学等式必须成立；接触力不是自由变量，必须满足接触一致性。

#### (2) 接触消力：对 J_cᵀ 做正交分解

把 `J_cᵀ` 的列空间与它的正交补分开：

```
J_cᵀ = Q_c Λ        （Q_c 为列空间的一组正交基）
Q_cᵀ Q_c = I ，    Q_cᵀ Q_⊥ = 0   （Q_⊥ 与接触力列空间正交，即 J_cᵀ 的左零空间）
```

用 `Q_⊥ᵀ` 左乘动力学等式，`f` 被彻底消掉：

```
q_uᵀ (M q̈ + h) = q_uᵀ Sᵀ τ                    （q_u 即上式的 Q_⊥）
```

这时候左边只剩 `q̈` 与已知的 `h`，右边只剩 `τ`。但**执行器不够**：
`q_uᵀ Sᵀ` 是一个行数大于列数的矩阵（消力后剩下的方向比执行器多），
所以 τ 无法从这条式子唯一反解，只能取最小二乘（这就是"欠驱动"的来源，
代码里对应"M 加权伪逆投影"的力矩恢复）。

再做一次投影，把"执行器影响不到"的方向单独拿出来：对 `q_uᵀ Sᵀ` 取左零空间得到 `W`，
于是

```
W M q̈ = −W h
```

物理含义是：**在既没有接触力、也没有执行器能作用的方向上，动力学必须自己成立。**
这是一条**不含 f、不含 τ 的纯等式**，也就是硬约束里的"欠驱动动力学等式"。

缺了它，求解器可以把 τ 和 f 任意组合去满足任务，得到的解在真实物理中不可实现——
任务满足了，但这台机器人做不到。

#### (3) 动力学一致的伪逆与零空间投影

```
J̄ = M⁻¹ Jᵀ (J M⁻¹ Jᵀ + λ² I)⁻¹          （M 加权、阻尼伪逆）
N = I − J̄ J
```

为什么用 **M 加权**而不是普通伪逆：普通伪逆在质量矩阵度量下不是正交投影，
会把加速度"投"到执行器无法产生的方向上；力矩恢复时就会出现残差。
M 加权后 `J̄ J` 是 M 自伴投影算子，`N` 是精确的零空间投影算子——
但 `λ > 0` 时这个性质会退化，这是阻尼换条件数的固有代价，必须知道。

#### (4) 严格优先级：递归零空间

第 i 级任务 `J_i q̈ + b_i = a_i`，在上一级剩下的零空间里求解：

```
q̈_i  = q̈_{i−1} + (J_i N_{i−1})⁺ (a_i − b_i − J_i q̈_{i−1})
N_i  = N_{i−1} − (J_i N_{i−1})⁺ (J_i N_{i−1})
```

每级只动"上一级没用掉"的方向，所以高优先级任务永远不会被低优先级任务破坏。
总加速度是各级增量之和（线性叠加），这也是"分层限值"能按级分配力矩预算的前提。

**它的代价**：任务维数超过执行器数时，低优先级任务拿到的零空间会被耗尽，`scaling` 恒为 0，
表现为末级任务（偏航、横滚）完全不起作用。

#### (5) 加权最小二乘（当前默认）

把任务的"严格优先级"换成"大权重"，先构造硬约束系统（接触等式 + 欠驱动动力学等式）：

```
        [ J_c ]        [ −b_c ]
A q̈ = b,   A = [     ] ,  b = [      ]
        [ W M ]        [ −W h ]
```

两条都**不含 τ**：它们只约束 `q̈`。τ 事后再由 `q̈` 恢复（见 (6)）。

```
特解：q̈_p = A⁺ b       零空间：N = I − A⁺ A
通解：q̈ = q̈_p + N z
```

任务变成对 `z` 的加权最小二乘：

```
min_z  Σ_i w_i ‖J_i N z − r_i‖²  +  λ‖z‖²
       r_i = a_i − b_i − J_i q̈_p
法方程：(Σ_i w_i NᵀJ_iᵀ J_i N + λI) z = Σ_i w_i Nᵀ J_iᵀ r_i
```

`w_i` 是本级权重乘 activation。与严格优先级的区别：**没有任何任务会被清零**，
但"必须满足"的语义消失，高优先级任务也会被牺牲一部分。

#### (6) 力矩与接触力的恢复，以及一致性残差

```
τ = recover_torque(q̈, h)                  由欠驱动方向等式唯一确定执行器该出多少
f = recover_contact_force(q̈, h, τ)        回代接触方向，得到与 τ 一致的接触力
ρ = ‖M q̈ + h − Sᵀ τ − J_cᵀ f‖             一致性残差
```

`τ` 与 `f` 的恢复互为逆过程（给定同一个 `q̈`，先算 τ 再回代出 f 应与直接求解一致）。
`ρ` 是**判据**：超过阈值（1e-7 量级）说明这一拍的解不满足动力学，应当视为不可行，
而不是照常下发。

#### (7) 为什么"越限后直接 clamp"不行

早期实现的做法是解出 τ 之后越限就 `clamp`。后果有两个：

1. clamp 之后的 τ 与求解得到的 q̈、f **不再满足动力学等式**，`ρ` 直接变大——解已经不是物理解；
2. 丢失了每个任务的结果信息（谁被限幅、谁被饿死），反馈回路拿不到判断依据。

所以现在的做法是**限幅自洽**：把限幅折进求解（修改限值区间与动力学偏置，让求解器
对"已经用掉的那部分力矩"记账），再在求解后叠加。这条经验对任何"先解再截断"的结构都适用。

#### (8) 单级 QP 形式（可选后端）

决策变量直接取 `[q̈; f; τ]`，四类硬约束：

1. 动力学等式；
2. 接触一致性等式；
3. 执行器力矩上下限；
4. 法向力非负。

任务全部进代价项（软目标）。与零空间法的本质区别：

- 零空间法：任务是硬等式，执行器数少于任务维数时低优先级任务被**清零**；
- 单级 QP：任务是软目标，按权重竞争，**不会被清零**，但也不再"必须满足"。

这条对比说明一件事：**"优先级"与"可满足性"不能同时都要**。选哪种取决于业务要求
（安全量的绝对保证 vs 所有任务都分到份额）。

### 8.3 任务与优先级

任务分两组：

- **balance**（平衡组）：俯仰；
- **motion**（运动组）：左右腿角、前向速度、左右腿长、偏航、横滚，跳跃时追加质心竖直加速度。

顺序即优先级（用户指定）：**俯仰 > 腿角 > 速度/位移 > 腿长 > 偏航 > 横滚**。

为什么俯仰排在第一位：俯仰是唯一"错了就会摔"的量；腿角是它的主要配平手段，排第二；
速度/位移是任务目标；腿长与偏航、横滚属于保持性任务，允许被牺牲。

每条任务带一个 `activation`（0~1）缩放，作用是"本级相对已有解的纠正增量"。
这提供了一种"部分放权"的手段：行程到极限时把某一级的权限降到 0，而不是让它硬顶着出力。

### 8.4 两腿单独建模：让横滚成为可以直接规划的量

#### (1) 原来的做法与它的问题

腿的两个自由度（腿长 L、摆角 φ）在左右两条腿上各有一份，最自然的建模方式是拆成
**共模 + 差模**：

```
共模 = (R + L) / 2      差模 = (R − L) / 2
```

共模决定质心高度、参与俯仰；差模决定左右高度差，也就是**横滚**。
把任务写在共模/差模上，看起来更"物理"。

问题在于：**这是一种预先规定好的分配比例**。写成共模/差模，
等于事先宣布"两条腿必须对称地动，只有差的那一部分才用来管横滚"，
而这个比例本应由优化决定。人工规定比例的后果是：任何需要非对称动作的工况
（侧向不平、单侧负载、横滚修正）都会被这个建模方式限制住。

#### (2) 现在的做法：四条腿任务，各自独立

现在把 `L_R、φ_R、L_L、φ_L` 各自建成一个任务，目标分别是"各自回到标称值"：

```
length_R → L0      angle_R → φ_ref
length_L → L0      angle_L → φ_ref
```

**对称性由任务自己保证**，不由建模方式保证。两条腿都想回 L0，所以自然对称；
一旦横滚任务需要，加权最小二乘会自动让两条腿偏离一点——偏离量由权重竞争决定，不由人规定。

这一步换来的是：**差动腿长成了一个可被规划的执行通道**，而不只是一个被建模方式压掉的自由度。

#### (3) 为什么这件事对横滚特别重要

横滚有两个可能的执行手段，性质完全不同：

| 手段 | 类型 | 持续性 |
|---|---|---|
| 左右差动法向力 | 力矩级（瞬时） | 只能瞬时；单支撑时权限为零 |
| 左右差动腿长 | 位置级（几何） | 可持续维持 |

这也正是 MPC 不建横滚状态的原因（见 4.2）：力矩级的权限没有预测价值。
但位置级的权限有——**差动腿长可以把横滚"摆"到一个新的平衡位置并保持住**，
这在倾斜地面、单侧轮压到凸起这类工况里是唯一可持续的手段。

两腿单独建模之后，这条通道才真正对优化器开放：

- 横滚任务（motion 组最后一级）给出横滚角/角速度目标；
- 求解器在"横滚任务"与"两条腿各自回 L0"之间按权重分配；
- 结果是两条腿的高度差自动产生，不需要任何人给一个"差模指令"。

#### (3b) 逐腿建模的第二个理由：越界与差异

除了给横滚留出通道，逐腿建模还有一个纯粹的安全性理由：**两条腿的实际行程必然有差异**。

如果按共模量做判断（例如"平均腿长到终点就算压缩完成"），会出现一种很难查的故障：
一侧已经压到机械下限，另一侧还没到，但平均值看起来正常，越界保护不触发。
逐腿建模后，每条腿都有自己的任务、自己的测量、自己的越界判据，
"某一侧先到极限"这件事在数值上就能被看见。

这也是"对称性由任务保证、不由建模保证"的第二层含义：
对称是结果，不是前提。

#### (4) 代价与约束

| 项 | 说明 |
|---|---|
| 权重决定比例 | 腿长任务权重 25、横滚任务权重 10：横滚会让位于腿长，属于"必要时才动" |
| 优先级最低 | 横滚排在 motion 组最末，机动时会先被牺牲；这是有意的，横滚错了不会立刻摔，速度错了会 |
| 牵连高度与俯仰 | 差动腿长会同时改变质心高度与两侧法向力分配，横滚动作会带走一点高度/俯仰任务 |
| 增益随髋角排程 | 髋到法向力的增益 `∝ 1/p`（p = sin 髋角），横滚权限在行程上变化可达一个数量级，增益必须随 p 缩放 |
| 需要 activation 下限 | 权限被缩到 0 时横滚完全失控，因此保留一个非零的下限，保证"最后一点权限还在" |

#### (5) 这条设计的边界

差动腿长能做的是"缓慢的横滚姿态调整"，不是"横滚的快速稳定"。
快速扰动仍然要靠差动法向力（瞬时权限）。
两者叠加在同一个求解器里：力矩级的修正走法向力，位置级的修正走差动腿长。
**这也是把横滚留在 WBC 而不是交给 MPC 的真正理由**：
MPC 的降阶模型里既没有差动腿长这个变量，也不需要预测一个只靠几何维持的量。

### 8.5 增益排程：为什么几乎所有权限都挂在髋角上

这台机器人的髋角 `q` 有两个互相矛盾的奇异方向，用 `p = sin q` 统一描述：

| 现象 | 表达式 | 后果 |
|---|---|---|
| 高度权限在行程端点消失 | `dz/dq = 0.06 p → 0` | 高度任务在端点"要求不动"却要求不出力，需要加大阻尼 |
| 髋到法向力的增益在死点发散 | `∝ 1/p` | 横滚回路在死点失控，增益必须乘 `p` |
| 中行程俯仰与横滚不再独立 | 耦合强度 ∝ `β = atan(0.5p)` | 解耦阻尼随 `β` 变化 |

同一个表里 `p` 与 `1/p` 同时出现，这不是矛盾，而是同一个几何的双重奇异。
排程全部写在**一处**（单一真值来源），各任务里禁止再写一套——否则两处各算一半，
调一处不生效，排查时找不到原因。

偏航还有一条与髋角线性相关的权限上限（`7.5 − 5.59 p`）和一条前馈（`0.5·cos q·q̇`）：
升降腿会产生寄生偏航，必须前馈掉，否则偏航任务一直在对抗一个已知扰动。

### 8.6 三种求解后端与取舍

| 后端 | 做法 | 代价 |
|---|---|---|
| 零空间法（严格优先级） | 逐级投影，每级只用上一级剩下的零空间 | 零空间会被前几级任务吃光，**末级任务彻底失效**（scaling 恒为 0） |
| 加权最小二乘 | 所有任务在一个加权 LS 里按权重竞争 | 优先级变软，低优先级任务也能分到份额，但"必须满足"的语义消失 |
| 单级 QP | 决策变量是 `[q̈, f, τ]`，任务全进代价项 | 需要 QP 求解器；好处是任务不会被清零，且力的可行域可以显式约束 |

**当前默认是加权最小二乘**（用户指定）。原因是实测出来的：这台机器人只有六个执行器，
而任务有七个（俯仰、腿角左右、速度、腿长左右、偏航、横滚），零空间**解到第三级任务就耗尽了**，
排在后面的偏航、横滚、腿长任务拿到的投影恒为零——不是"权重小"，而是物理上没有剩余的可行方向。

这个现象有一个直接的实测特征：**`scaling` 恒为 0**。它把问题暴露得很清楚——
零空间法在任务维数超过执行器数时，不是"低优先级任务少分一点"，而是"完全分不到"。
所以任何以"降级满足"为期望的场合都不能用严格优先级。

另外，原来的加权版本本身也有一个缺陷：越限后直接 clamp 力矩，导致返回的 τ 与 q̈、接触力不再动力学一致，
而且丢掉了反馈回路需要的信息。因此现在用的是**限幅自洽的加权版本**：
把限幅折进求解过程，保证输出的力矩与解一致。

这条取舍写在这里是为了提醒复刻者：**"加权"不是"更简单"，它换掉的是优先级语义。**
如果某天发现低优先级任务必须被严格保证，就该换回严格优先级或单级 QP，而不是继续调权重。

### 8.7 摩擦锥：为什么现在不加

摩擦锥约束会在每个轮子上增加一组不等式，显著提高问题规模与数值风险。
当前决定是先去掉以降低复杂度，等出现"解在物理上打滑"的证据再加回。
在加回之前，防滑依赖两件事：偏航权限随髋角的限幅、以及轮力矩的上下界。

### 8.8 不可行兜底

两级，且不允许静默失败：

1. 完整约束不可行 → 去掉接触一致性等式再解（接触力回到自由变量）；
2. 仍不可行 → 输出零力矩与无控制加速度，并置位兜底标志。

每一次兜底都必须记日志。兜底不是"容错"，它意味着这一拍的控制已经不成立，
必须能在事后查出来是哪一拍、因为什么。

### 8.9 无接触时直接返回零力矩

平衡被禁用（`balance_enabled=False`）时直接返回零力矩，不做任何求解。
理由：没有接触就没有反力，任何"平衡解"都是假的。
这一点与跳跃模块的飞行段设计一致：空中不追求平衡，只做腿长与摆角。

## 九、两层的接口

### 9.1 MPC 给 WBC 的东西

| 量 | 用途 |
|---|---|
| 参考状态（位置、速度、俯仰、俯仰角速度、偏航、偏航角速度、腿角、腿角速度） | 任务目标 |
| 参考加速度 | 前馈项（俯仰角加速度、前向加速度、偏航角加速度） |

WBC 把参考状态与实测状态之差乘以增益，得到任务目标加速度；参考加速度作为前馈直接加上。
这就是"参考 + PD + 前馈"的结构：MPC 负责"去哪儿"，WBC 负责"这一拍怎么去"。

### 9.2 MPC 的力输出没有消费者

MPC 每拍都算出一组轮子接触力，但**它不进入 WBC**。WBC 用自己的接触力作为决策/中间变量，
由任务与动力学等式决定。这不是遗漏，而是分工：力矩与接触力必须由同一个求解器同时决定，
否则两者不自洽（这正是 8.1 第 1 条不变量）。

需要"计划力前馈"时，做法是把计划力折进 WBC 的限幅与偏置，让求解器**对已施加的力矩记账**，
求解后再叠加回去——这是补丁式的做法，只在明确需要时启用。

### 9.3 相位相关的接口

WBC 的任务集与权重会随相位变化：跳跃期替换腿长任务参考、追加质心竖直加速度任务、
按相位重载权重；无 MPC 解时（飞行、平衡禁用）退化为阻尼。

关键约定：**任务参考替换必须"替换"而不是"叠加"**。历史上出现过
"腿长任务参考仍是标称值，同时跳跃要求压缩"的冲突，表现为腿被拉回去、与蹬伸力对撞。
