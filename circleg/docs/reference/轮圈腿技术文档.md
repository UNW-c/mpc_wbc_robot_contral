# 轮圈腿机器人 设计文档

本文件描述轮圈腿（偏心曲柄式轮腿，代码里称 circleg）这台机器人的**控制设计思路与依据**：
构型带来了哪些硬约束、控制栈为什么这样分层、每一层的物理依据、以及跳跃为什么这样做。

面向需要复刻或改造该机器人的工程师。拓扑尺寸与实测数据见
`docs/构型与控制逻辑.md`（该文档是构型与参数的分析基准，本文不重复罗列，
只写"为什么这样设计"）。

代码基线：`0e91281`。

---

## 一、构型带来的三个硬约束

### 1.1 传动本质：偏心曲柄，不是并联连杆

每条腿只有一个主动髋关节，轮心通过一根长 0.06 m 的曲柄挂在髋轴上：

```
髋角 q  →  轮心相对髋轴的位置 = 0.06 · (±sin q, 0, cos q)
```

竖直分量决定机身高度，水平分量决定轮子前后位置。没有第二条连杆，
所以**腿长与摆角不是两个独立自由度，而是同一个 q 的两种读法**：

```
L(q) = 0.080 − 0.060·cos q        （代码里的腿长定义，标称常量偏置）
```

这一点决定了后面所有的设计：**这台机器人只有一个"腿"自由度，它同时承担高度与前后位置。**

四个电机被组织成三个控制通道：

| 通道 | 由谁产生 | 负责 |
|---|---|---|
| 高度（腿长） | 两髋同向（共模） | 机身高度、跳跃 |
| 横滚/制导 | 两髋反向（差模） | 单侧抬升、斜坡适应 |
| 纵向力与偏航 | 两轮（差动与共模） | 前进、转向 |

### 1.2 约束一：死点

曲柄承受重力所需的髋力矩正比于力臂 `0.06·sin q`：

| q | 0（上死点） | π/2（中点） | π（下死点） |
|---|---|---|---|
| 所需髋力矩 | 0（自锁卸载） | 最大 | 0 |
| 机身高度 | 最低 0.193 m | 0.253 m | 最高 0.313 m |
| `dL/dq = 0.06 sin q` | 0 | 最大 | 0 |

设计上的三个直接后果：

1. **默认姿态放在上死点**：机身最低、髋电机零负载、等效摆长最短（质心高于轮轴 17 mm）。
   站得稳、又不费电。
2. **腿长指令在死点附近是高增益的**。`dq/dL = 1/(0.06 sin q)` 在两端趋于无穷：
   从 q=0 起以 0.12 m/s 伸腿，第一个 1 ms 步长里参考角就要跳 3.6°（等效 63 rad/s）。
   因此高度/腿长指令必须限速、髋角必须进 MPC 的状态约束、髋角任务必须有阻尼，
并且实测髋角要有独立保护（`hip_guard`）——否则指令一到就会被当成阶跃，或者被规划到一个模型不可信的区间。
3. **横滚与高度在同一对执行器上**，只是共模与差模之分。死点附近共模权限消失，
   差模权限反而最大（力臂最大），这也是横滚任务需要按行程排程的原因。

### 1.3 约束二：轮轴反装，符号必须先统一

两条腿是把同一个零件**绕竖直轴旋转 180°** 安装的（不是镜像）。
后果是两个轮电机的物理正方向相反：正力矩在一个轮上让机身抬头，在另一个轮上让机身低头。

所以控制栈里必须先做一次混合，把"物理四路"换成"语义三通道"：

```
共模髋 = (τ_右髋 + τ_左髋) / 2        差模髋 = (τ_右髋 − τ_左髋) / 2
轮共模 = (τ_右轮 − τ_左轮) / 2        轮差模 = (τ_右轮 + τ_左轮) / 2   （符号由反装决定）
```

**这一步的符号如果错，表现是"控制器一启动就往一边倒"，而且看单路力矩完全正常。**
因此符号约定必须只在一处定义，并且有测试覆盖。

### 1.4 约束三：两轮纵向错位

`p_R` 与 `p_L` 的水平分量符号相反，所以同一个 q 下右轮向后、左轮向前：
行程中点 q=π/2 时两轮纵向错开 **120 mm**，在两端归零。

这条特性有三个设计后果：

1. **接地点连线的方向随 q 变化**：升降腿的过程中，支撑多边形的轴线会先斜过去再摆回来。
   偏航控制不能假设"左右轮纵向对齐"。
2. **速度估计不能用 `轮速 × 半径`**：机身速度必须用曲柄-轮运动学合成
   （轮速项 + 曲柄角速度引起的附加项），否则升降腿时会把"腿在动"读成"机身在前冲"。
3. **它会引入寄生偏航**：升降腿时两侧接地点的纵向位置不同，地面切向力产生一个偏航力矩。
   这部分必须前馈掉，否则偏航环一直在对抗一个已知扰动。

## 二、控制栈：MPC + WBC

### 2.1 两台机器人共用同一套控制器结构

轮圈腿与串联腿用的是**同一套控制器**：

```
指令 ──► 规划器（斜坡）──► MPC（8 状态降阶模型 + 约束 QP）──► WBC（完整浮基动力学 + 任务分配）──► 力矩
```

两者共用的部分：`WheelMPC`、`ControlSupervisor`、`Algorithm/wbc` 的任务与求解器、规划器、
接触估计器。**差别只在两处**：降阶模型（`hip_input` vs `leg_input`）与任务集（髋跟踪 vs 腿长任务）。

这一条是复刻时最先要搞清的：不要以为轮圈腿是另一套控制器。它的特殊性来自构型，
不是来自控制架构。

### 2.2 为什么需要 MPC

整台机器人只有一个"腿"自由度（共模髋角 q），它同时决定：

- 机身高度（`h = 0.16 − 0.06 cos q`）；
- 质心相对接地点的前后位置（曲柄水平分量 `0.06 sin q`）。

于是"想往前加速"与"想改变高度"抢同一个执行器，而俯仰是第二个手段、且有安全限幅。
这三者的分配是一个带约束的问题，不是单回路能解决的：

- 髋角有硬限幅（小腿/机构约束），不能无限摆；
- 俯仰有安全包线；
- 轮力矩、法向力有上下界。

MPC 是唯一能同时看到这三条约束并给出分配的地方。

### 2.3 为什么需要 WBC

MPC 用的是降阶模型（8 状态、3 输入），它无法算出六个执行器的力矩：
曲柄是闭链机构，力与力矩的对应依赖完整浮基动力学的质量矩阵与雅可比；
而且这一拍要同时满足俯仰、横滚、偏航、高度、髋跟踪、速度六件事，执行器只有六个。

所以 WBC 负责"这一拍怎么分"，并且必须同时满足：
动力学等式、接触一致性（轮子不滑不穿透）、力矩上下界、法向力非负。

### 2.4 多速率与整数步调度

频率分离按**整数物理步**计数，不按浮点时间累计。理由：`dt` 累加会漂，
跑久了相位差出一步，表现为偶发采样抖动，并让"偶发翻车"无法复现。

### 2.5 LQR 在这套栈里的位置

仓库里仍然保留一套 LQR（`Algorithm/lqr.py`、`APP/chassis_controller.py`），但它**不在主控制栈上**：

| 用途 | 说明 |
|---|---|
| MPC 兜底 | MPC 连续失败达到阈值后，退到 LQR 维持平衡（`fallback_gain`） |
| 独立观察任务 | `APP/observe_task.py` 用的单机平衡路径，与 MPC+WBC 主程序并列 |

主程序（`APP/mujoco_mpc_wbc.py`）的地面平衡是 **MPC + WBC**，不是 LQR。
复刻时不要从 `docs/构型与控制逻辑.md` 的 LQR 章节反推主控制栈——那部分描述的是这条兜底/观察路径。

## 三、MPC 的模型：8 状态 + 髋输入

### 3.1 状态与输入

```
x = [s, v, pitch, pitch_rate, yaw, yaw_rate, q_c, q̇_c]      （8）
u = [f_R, f_L, τ_c]                                          （3）
```

`q_c` 是**共模髋角**（两髋同向那部分），`τ_c` 是共模髋力矩。
这与串联腿的 8 状态模型结构相同、含义不同：那边第 7/8 个状态是"腿长与摆角"，
这边是"曲柄角"，两者都是"腿这个自由度"的状态，但物理量与几何完全不同，**不可互换**。

### 3.2 为什么必须把髋角放进模型

因为曲柄是**机身高度与质心前后位置的唯一来源**。如果模型里没有髋角：

- MPC 无法表达"用摆曲柄来移动质心"这条通道，只能靠轮力，而轮力在这台机器人上
  对前向加速度的直接权限是弱的（腿会自由摆动把推力泄掉）；
- 也无法表达"高度变化"这件事，而高度在跳跃与越障时是主任务。

把髋角放进状态、把髋力矩放进输入之后，MPC 才能在线回答"这次加速，曲柄摆多少、俯仰留多少"，
并且这个分配受髋角限幅与俯仰限幅双重约束。

### 3.3 代价一：髋力矩成了决策量

髋力矩既然是 MPC 的输入，就不能再被当作"已知扰动力矩"喂进俯仰方程。
两者只能选一个，否则同一个量被算两遍。所以这套配置下"把髋力矩当已知输入"必须关闭。

### 3.4 代价二：死点附近线性化敏感

模型是在某个工作点（某个 `q`）上线性化的。死点附近几何增益极高（`dL/dq → 0`、`dq/dL → ∞`），
工作点稍微偏一点，线性化模型的增益就差很多。因此：

- 髋角必须进约束（`hip_angle_limit`），不让 MPC 规划到模型不可信的区间；
- 共模髋角还有一层独立的硬保护（`hip_guard`），非跳跃段超过即触发保护动作。

### 3.5 权重与限值（这台机器人的取值）

| 项 | 值 | 说明 |
|---|---|---|
| 位置权重 | 20000 | 位置是主任务 |
| 速度权重 | 1333 | 与位置配套 |
| 俯仰权重 | 150000 | 远高于位置：姿态优先 |
| 俯仰角速度权重 | 100 ~ 300 | 视预设（激进档更高） |
| 髋角权重 | 50 | 髋角是手段，不是目标 |
| 髋角速度权重 | 2.4 ~ 4.5 | 同上 |
| 髋角状态限幅 | 0.70 ~ 0.80 rad | 模型可信范围（视预设） |
| 终端代价缩放 | 5.0 | 加强视界末端的收敛 |

"俯仰权重远大于位置"这条是设计取舍的直接体现：**宁可慢一点到位，也不能低头**。

## 四、WBC 的任务与层级

### 4.1 两组的划分

| 组 | 层级顺序 | 内容 |
|---|---|---|
| balance | 1 | 俯仰 |
| balance | 2 | **差模髋**（左右髋反向部分） |
| balance | 3 | 横滚 |
| motion | 4 | 偏航 |
| motion | 5 | 高度（机身 z） |
| motion | 6 | 前向速度 |
| motion | 7 | **共模髋跟踪**（跟踪 MPC 轨迹） |

### 4.2 为什么俯仰排第一

俯仰是唯一"错了立刻摔"的量，而且它的执行手段（轮力矩、髋力矩）与其他任务共享。
把它放在最高优先级，其他任务只能在剩下的零空间/权重里分配。

### 4.3 为什么差模髋排在 balance 里、而且这么靠前

差模髋（左右髋反向）产生的是**单侧抬升**，也就是横滚与侧向的制导手段。
它比横滚本身还靠前，原因是：横滚的权限本身依赖髋角（力臂 `∝ sin q`），
如果不先把差模髋的姿态定住，横滚任务连"用哪个执行器"都不稳定。

这条也解释了为什么横滚任务的激活要随髋角排程：死点附近差模髋的力臂最大、权限最好，
行程中点则相反。

### 4.4 为什么共模髋跟踪排在 motion 最后

共模髋是"位置级"的慢量：它决定高度与质心前后位置，响应慢、惯性大。
如果把它放到高优先级，它会在每一个扰动瞬间去抢执行器，把速度与偏航任务全部饿死。

但它也不能被"顺便优化掉"：**曲柄漂了，MPC 的降阶模型本身就失效了**
（模型是在特定 q 上线性化的）。所以它必须有一个明确的跟踪任务，只是排在最后。

### 4.5 高度任务用机身 z，不用"腿长"

串联腿的高度任务写在腿长方向上；轮圈腿写在**机身 z 位置**这一行上。
理由：这台机器人的"高度"就是机体的竖直位置，曲柄角只是它的实现手段；
而腿长在这台机器人上是一个标称定义量（`L = 0.08 − 0.06 cos q`，含 13 mm 的标称偏置），
拿它当高度目标会把标称偏置换算成真实高度误差。

### 4.6 共模髋跟踪带加速度前馈

共模髋的任务目标是"MPC 轨迹里的髋角 + PD + 髋角加速度前馈"。前馈项的存在意味着
MPC 规划出的髋运动被直接执行，而不是等误差积累后再由 PD 追。

差模髋则相反：目标是保持名义（0），只做阻尼——因为它没有"规划"这回事，
它的作用是局部调平，不是被规划的量。

### 4.7 hip_guard：一层独立于 MPC 的硬保护

非跳跃段如果共模髋角超过 `hip_guard`（1.7 rad），直接触发保护动作（减速/停机），
不经过 MPC。

为什么需要独立的一层：MPC 的髋角限幅是**规划层**的约束，它约束的是"我打算去的地方"；
而 hip_guard 约束的是"实测已经到的地方"。规划器可以规划得没问题，但执行跟不上、
或者参考被冻结，此时只有实测保护能兜住。

### 4.8 偏航

偏航由两轮差动提供，是 motion 组的第 4 级（低于俯仰/差模髋/横滚，高于高度与速度）。

三条注意点：

1. **权限随构型下降**：轮子压在斜向支撑上时，可用的偏航力矩会被轮子的侧向刮擦吃掉，
   所以偏航力矩上限要随髋角下调，而不是用一个常数；
2. **寄生偏航必须前馈**：升降腿时两轮接地点纵向位置不同，会产生一个与髋角速度成正比的偏航力矩，
   让反馈去追一个已知量等于故意制造稳态误差；
3. **偏航参考要限速**：偏航参考阶跃会让差动轮力矩瞬间打满，进而扰动纵向力，
   把俯仰拉进一次不必要的瞬态。

## 五、指令与参考生成

### 5.1 MPC 是纵向的唯一规划者

前向速度任务的目标由三部分组成：

```
v_target = MPC 规划的加速度（前馈）
         + 速度增益 × (MPC 参考速度 − 实测速度)
         + 位置增益 × (MPC 参考位置 − 实测位置)
```

误差项只用来修正"MPC 两次刷新之间"的偏差，主意图来自 MPC。

**这里有一条关键约定：WBC 的速度任务不引用键盘指令，也不引用规划器的参考位置。**
早期实现是"键盘指令直接进 WBC + 另一套参考做 PD"，结果是两套参考互相抵消：
MPC 想减速、键盘指令想加速，执行器只能听权重高的那个，表现为"指令下去了但速度不动"。
现在的做法是把纵向决策权**只留给 MPC**，其余通道只负责修正。

### 5.2 legacy 模式保留作对照

配置里保留一个 `legacy` 的纵向模式：直接按键盘速度指令做绝对 PD，不使用 MPC 参考。
它的作用是"对照组"——任何新的纵向结构都必须能证明自己优于它。

但要注意：**不能拿 legacy 模式下的历史结论去评价 MPC 模式**。
历史上有一条"相对 MPC 参考的 PD 失效（代价从 9.03 恶化到 29.01）"的结论，
后来查明它是在"preview_lead 把 PD 变成了前馈"且"存在两套控制器"的条件下得到的，
不能说明跟踪结构本身有问题。

### 5.3 参考速度只来自指令

与串联腿一致的硬规则：参考速度由指令积分得到，不由实测反推。
实测回灌会形成正反馈（实测往前 → 参考往前 → 更往前）。

### 5.4 高度与"腿长"的关系

- **高度是任务目标**：WBC 有一条机身 z 位置任务，目标来自设定高度；
- **腿长只是标称换算量**：`L = 0.08 − 0.06 cos q` 里含 13 mm 的标称偏置，
  它与真实几何不对应。把腿长指令再翻译成髋角参考去叠加，等于引入一个系统性高度偏差。

实测也支持这个结论：尝试过给 MPC 加"髋角参考前馈"（按能力表把规划加速度换算成髋角），
**没有收益，因此保持关闭**。

## 六、状态估计与构型的耦合

### 6.1 曲柄-轮运动学：机身速度不是轮速

轮圈腿的轮子挂在曲柄末端，所以"轮子转多快"与"机身走多快"之间差一个曲柄项：

```
机身水平速度 = f(轮速, 曲柄角速度, 曲柄角)
```

忽略曲柄项会在两种工况下明显出错：升降腿时（腿在动，机身没动）与死点附近（几何增益大）。
因此速度估计模块的核心就是这条运动学，而不是简单的 `v = ωR`。

另外一条口径约定：**参考点取机体坐标系原点，不是轮心、也不是质心**。
因为不同 q 下轮心与质心的位置都在变，只有机体原点是一个固定定义的点。

### 6.2 接触门控

打滑或离地的轮子**不提供速度观测**。理由：滚动模型假设"无切向滑移"，
一旦打滑，由轮速反推机身速度会给出一个系统性错误的观测，比没有观测更糟。

### 6.3 位姿推算

偏航角来自陀螺积分 + 偏航参考的约束，位置来自速度积分。
两者都必须能被"重锚事件"重置（使能、恢复、跳跃落地、手动复位）。

## 七、接触状态估计的设计

接触判定在这台机器人上是**最容易出错、后果最直接**的一环：判错离地就直接把平衡环断掉。

### 7.1 双阈值滞回，不用单阈值

法向力有噪声，单阈值会在门限附近来回翻转。所以用两个门限：

```
低于 off_force 且持续 off_duration   → 判离地
高于 on_force  且持续 on_duration    → 判接地
```

两个门限之间是"保持原状态"的死区。这同时也避免了"一帧支撑力掉零就切相位"。

### 7.2 相位门控：跳跃期不能只看力

跳跃过程中"法向力掉零"与"真的离地"是两件事：蹬伸期力的分配转移会让法向力降到零，
而轮子还压在地面上。所以跳跃相位下必须叠加**动作相位**的门控：

- 推力段：只有共模髋角超过某个角度才允许判离地（说明蹬伸动作确实做了）；
- 飞行段：在预计飞行时间的一定比例之前不判着地（否则会在上升段被噪声打断）；
- 着地段：接地门限放宽（更快确认着地，因为需要立刻开始缓冲）。

### 7.3 IMU 旁证与"法向力瞬时卸载"

竖直比力接近失重可以作为离地的独立旁证。但反过来，**法向力低不等于离地**：
急反转、髋力矩反作用都会把轮子瞬间卸空。

因此非跳跃相位下，判离地需要运动学旁证：机身上升量不足、且竖直比力没有接近真失重时，
判为"法向力瞬时卸载"，不判离地。

这一条防的是一个具体故障循环：卸空 → 判离地、控制置零 → 重锚参考 → 又一次过指令。

## 八、跳跃设计（轮圈腿版）

### 8.1 与串联腿的根本差别：这里轮子能做姿态

串联腿上"轮子控姿态"不成立（轮子惯量占机体俯仰惯量的比例约 1:127，落地必打滑）。
轮圈腿不一样：轮子与机体通过电机座直接相连、轴线平行于俯仰轴，
**轮电机的反作用力矩直接作用在机体上**，可以当反作用轮用。

这条差别决定了两个平台的跳跃设计完全不同，不能互相照搬：

| | 串联腿 | 轮圈腿 |
|---|---|---|
| 空中姿态手段 | 只有髋（与 pitch 是 2:1 交换） | 髋 + 轮反作用 |
| 姿态控制目标 | 接受姿态，只做落地准备 | 主动把俯仰拉平 |

### 8.2 PREPARE：为什么要先预倾

蹬伸时髋力矩会产生一个让机身**前翻**的冲量。如果不做处理，这个冲量会全部变成离地时的俯仰角动量。

所以设计上让机身**先向后仰到一个预倾角**，让蹬伸的前翻冲量把它"转正"。
预倾角由开环搜索确定（当前值 −0.524 rad / −30°），不是随手给的数。
实测离地角动量因为这个预倾显著降低。

预倾阶段本模块只做两件事：给上层平衡控制一个俯仰参考、以及判断"到位了没有"。
它自己不出力矩——姿态是上层平衡环的事，跳跃模块只负责改参考。

**为什么预倾要通过上层做**：如果跳跃模块自己给髋力矩去压姿态，就会与平衡环抢执行器，
两个环互相打架，到位判据也会被自己的力矩打乱。

### 8.3 THRUST：满力矩蹬伸，不做角动量反馈

蹬伸段只用满髋力矩，不对俯仰角动量做任何反馈调节。

理由是实测结论：**任何角动量反馈都会分流推力**，高度直接掉到目标以下。
推动作本身就会改变姿态，此时用姿态反馈去修，等于用本该用来起跳的力矩去做姿态。

同时保留两个保护：

- 髋角超过某个角度仍未离地 → 中止（说明机构卡住或接触异常）；
- 髋角再大一些 → 反向满力矩制动（保护曲柄不要撞结构限位）。

### 8.4 FLIGHT：髋收回到站姿，轮子把俯仰拉平

飞行段做两件事：

1. **髋 PD 把腿收回到站姿（下死点）**。为什么不收在中点：中点时机身质心偏前、等效摆长也长，
   落地无法平衡；收到下死点则落地时构型与站姿一致，交还控制时没有二次瞬态。
2. **轮反作用做俯仰 PD**：`τ = kp·θ + kd·θ̇`，按符号约定让正力矩使机身后仰。
   临近着地时（预计飞行时间的 70% 之后）把阻尼放大，把俯仰角速度压到接近 0——
   落地瞬间带着角速度撞地，任何缓冲都救不回来。

### 8.5 LANDING：髋阻抗 + 轮速匹配 + 俯仰平衡

触地后三件事同时做：

| 动作 | 目的 |
|---|---|
| 髋阻抗（PD 保持在着地角） | 吸收冲击，不让腿在冲击下弹跳 |
| 轮速匹配 | 把空中积累的轮子自转卸掉（否则轮子带着速度落地会打滑） |
| 俯仰平衡（轮力矩 PD） | 触地后立即接管倒立摆，不等交还 |

第三条是关键：**触地瞬间平衡就已经开始**，不能等"落地阶段结束"再交给上层。
延迟交接期间机体会自由倒下，最后变成"交还时的一次大瞬态"。

### 8.6 RECOVER：快速交还，不要慢慢放

落地稳定后只需要很短的时间（一个控制周期量级）确认髋已回到站姿就交还上层。

早期的做法是在落地后保留一段较长的髋 PD 锁定期再交还，实测结果是：
**锁定期结束时会产生一次二次瞬态**——因为锁定期内轮子在做平衡、髋被 PD 钉住，
交还瞬间髋的参考与上层的要求不一致。

结论：交还越干脆越好，前提是落地姿态已经与站姿一致（这正是 9.4 收腿到站姿的原因）。

### 8.7 ABORT 与失败出口

| 触发 | 处理 |
|---|---|
| 任意相位俯仰超过 1.2 rad | 中止 |
| 准备段失去接触或超时 | 中止 |
| 蹬伸超时或髋角过大 | 中止 |
| 飞行超时（预计飞行时间的 1.5 倍） | 中止 |

中止后的动作是"髋阻尼 + 轮速匹配"，并把控制权交回上层。中止不是一个终点，
而是一个"让系统回到可以重新被控制的状态"的动作。

## 九、与串联腿实现的对照

仓库里有两套完全独立的实现，**不共用参数、不共用判据、不共用状态机**：

| | 轮圈腿（本文） | 串联腿 |
|---|---|---|
| 腿的自由度 | 1（曲柄角，同时决定高度与前后位置） | 2（腿长、摆角独立） |
| 地面平衡 | **MPC（8 状态，hip_input）+ WBC** | **MPC（8 状态，leg_input）+ WBC** |
| MPC 第 7/8 状态 | 共模髋角、髋角速度 | 共模腿角、腿角速度 |
| 高度怎么表达 | WBC 的机身 z 任务 | WBC 的腿长任务 |
| 空中姿态 | 髋 + 轮反作用 | 只有髋 |
| 跳跃相位 | PREPARE / THRUST / FLIGHT / LANDING / RECOVER | COMPRESS / COMPRESS_BRAKE / THRUST / FLIGHT / LANDING / RECOVER |
| 死点 | 有（曲柄两端），必须排程与限幅 | 无（串联腿没有曲柄死点） |

**改动其中一套时不得假设另一套同步。** 两边的"腿长上限""离地判据""摆角参考"名称相同但含义不同，
混用会得到看起来生效、实际没有对应的结果。

## 十一、已知限制

| 项 | 现状 |
|---|---|
| MPC 在单一工作点线性化 | 构型随 q 变化，线性化点偏离后模型增益会变差；靠髋角限幅与 hip_guard 把工况限制在模型可信区间 |
| 死点高增益 | 只能靠限幅与阻尼压制，不能消除（几何决定） |
| 两轮纵向错位 | 120 mm 的错位无法机械消除（零件旋转安装的代价） |
| 横滚通道 | 构型提供了差动腿长的能力，但当前控制栈没有作为独立通道开放 |
| 空中姿态 | 依赖轮反作用；轮力矩上限与轮子惯量决定了姿态修正带宽 |
| 跳跃参数 | 预倾角为开环搜索结果，不是在线自适应 |
| 摩擦锥 | 平衡环不显式建模轮子侧向摩擦极限，靠权限上限保守处理 |
